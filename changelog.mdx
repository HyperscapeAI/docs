### 🤖 LLM Autonomy Refactor

Major improvements to AI agent decision-making with genuine LLM reasoning:

- **THINKING+ACTION Format**: Agents now respond with structured reasoning before taking action
  - `<THINKING>` section explains the agent's reasoning
  - `<ACTION>` section specifies the chosen action
  - Enables debuggable agent behavior (see why it chose an action)
  - Foundation for multi-step reasoning
- **Agent Thoughts Dashboard**: Real-time visualization of agent decision-making
  - RuneScape-themed parchment/scroll visual style
  - Live sync of agent thoughts via `/api/agents/:agentId/thoughts` API
  - Expandable history of recent thoughts
  - Flash animation when new thoughts arrive
  - Spectator overlay for watching agents
- **Target Locking**: 30-second lock on combat targets prevents target switching
  - `lockedTargetId` persists across ticks
  - Lock clears when target dies, despawns, or timeout expires
  - Dramatically improves combat effectiveness
- **Force Flee Mechanism**: Pre-emptive survival check runs before LLM selection
  - If health < 25% AND threats nearby, agent automatically flees
  - Survival instinct overrides LLM decisions
  - Prevents agents from dying due to poor LLM choices
- **Combat Readiness Scoring**: `getCombatReadiness()` evaluates combat preparedness
  - Factors: health level, weapon equipped, food available
  - Combat goals scaled down when readiness is low
  - "NOT RECOMMENDED" warnings added to risky combat options
- **New Providers**: 3 additional context providers for better decision-making
  - `possibilitiesProvider`: What actions are currently possible (crafting, gathering, combat)
  - `goalTemplatesProvider`: Structured goal templates for OSRS beginner flows
  - `guardrailsProvider`: Safety constraints and warnings
- **New Actions**: Additional actions for agent autonomy
  - `lootStarterChestAction`: Loot starter chest for basic tools
  - `mineRockAction`: Mine rocks for ore (with level validation)
- **Item Detection Utilities**: Centralized `item-detection.ts` module
  - Consistent item checking across the entire plugin
  - Handles multiple item formats (name, itemId, nested item.name)
  - Functions: `hasAxe()`, `hasPickaxe()`, `hasFood()`, `hasWeapon()`, etc.
- **Dev Script Cleanup**: Replaced 223-line `dev-with-ai.mjs` with one-liner using `concurrently`
  - New `dev:ai` command: `bun run dev:ai`
  - Runs game and ElizaOS together with colored output

<Update label="Collision System & UI Improvements" description="January 2026" date="2026-01-16">

### 🎯 Static Tile Collision System

Production-quality OSRS-accurate collision system for static world objects and entities:

- **CollisionMatrix**: Zone-based collision storage with bitmask flags
  - World divided into 8×8 tile zones (Int32Array[64] = 256 bytes per zone)
  - Lazy allocation: zones created on first write
  - Memory efficient: 1000×1000 tile world = ~4MB
  - O(1) tile lookups with zero allocations in hot paths
- **Collision Flags**: OSRS-accurate bitmask flags
  - Static objects: `BLOCKED`, `WATER`, `STEEP_SLOPE`
  - Entity occupancy: `OCCUPIED_PLAYER`, `OCCUPIED_NPC`
  - Directional walls: 8 directions for future dungeons/buildings
  - Combined masks: `BLOCKS_WALK`, `BLOCKS_MOVEMENT`, `BLOCKS_RANGED`
- **Automatic Footprint Detection**: Build-time model bounds extraction
  - New `extract-model-bounds.ts` script parses GLB files
  - Extracts bounding boxes from glTF position accessors
  - Generates `model-bounds.json` manifest automatically
  - Footprints calculated from model dimensions × scale
  - Turbo caching avoids rebuilding when models unchanged
- **Multi-Tile Entities**: Stations and large resources occupy multiple tiles
  - Furnaces, anvils, banks support 2×2 footprints
  - Center-based registration (footprint centered on entity position)
  - OSRS-style interaction from any adjacent tile
  - `tilesWithinRangeOfFootprint()` for multi-tile range checks
- **Pathfinding Integration**: Mobs and players respect collision
  - BFSPathfinder checks `CollisionMatrix` for static objects
  - Safespotting: players can hide behind trees/rocks
  - Depleted resources remain solid (stumps block movement)
- **Network Synchronization**: Zone-based collision sync
  - Base64 serialization for efficient network transport
  - Only allocated zones sent to clients
  - `getZonesInRadius()` for area-based sync
- **Testing**: 1,118 lines of comprehensive unit tests
  - CollisionMatrix: zone allocation, flag operations, negative coordinates
  - CollisionFlags: bitmask uniqueness, directional walls
  - TileSystem: multi-tile footprint calculations

Raycast proxy optimization for fast entity click detection:

- **Raycast Proxy**: Invisible capsule meshes for instant click detection on NPCs and mobs

OSRS-accurate food consumption with 3-tick eat delay and combat integration:

- **Eat Delay**: 3-tick (1.8s) cooldown between eating foods
