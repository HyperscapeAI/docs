### 🤖 Quest-Driven Agent Progression (commit 593cd56b)

**Major Change:** Agents now acquire tools through quests instead of starter chests, matching natural MMORPG progression.

**Removed:**
- `LOOT_STARTER_CHEST` action
- Starter chest entities from world
- Direct starter item grants

**Added:**
- `ACCEPT_QUEST` and `COMPLETE_QUEST` actions
- Questing goal (priority 100 when agent lacks tools)
- Banking goal (priority 90 when inventory >= 25/28 slots)
- `BANK_DEPOSIT_ALL` action for bulk banking
- Enhanced questProvider with tool-to-quest mapping

**Quest-to-Tool Mapping:**

| Quest | NPC | Tools Granted |
|-------|-----|---------------|
| Lumberjack's First Lesson | Forester Wilma | Bronze Hatchet + Tinderbox |
| Fresh Catch | Fisherman Pete | Small Fishing Net |
| Torvin's Tools | Torvin | Bronze Pickaxe + Hammer |

**Autonomous Banking:**

Agents automatically bank items when inventory reaches 25/28 slots:
- Walks to nearest bank
- Opens bank session
- Deposits ALL items
- Withdraws back essential tools (axe, pickaxe, tinderbox, net)
- Closes bank session
- Restores previous goal after banking complete

**Bank Protocol Fix:**

Replaced broken `bankAction` packet with proper sequence:
```typescript
// ❌ Old (broken)
sendPacket('bankAction', { action: 'deposit', itemId, quantity });

// ✅ New (correct)
await service.openBank(bankId);
await service.bankDeposit(itemId, quantity);
// or
await service.bankDepositAll();
await service.closeBank();
```

**Resource Detection Fix:**

Increased resource approach range from 20m to 40m for CHOP_TREE, MINE_ROCK, and CATCH_FISH to fix "no resources nearby" errors despite visible resources.

### 🎵 Audio Streaming via PulseAudio (commits 3b6f1ee, aab66b0, b9d2e41)

**Feature:** Capture game music and sound effects in RTMP streams using PulseAudio virtual sink.

**Setup:**
1. Install PulseAudio and create virtual sink (`chrome_audio`)
2. Configure Chrome to use PulseAudio output
3. FFmpeg captures from PulseAudio monitor instead of silent audio

**Audio Stability Improvements:**
- `thread_queue_size=1024` for audio input (prevents buffer underruns)
- `use_wallclock_as_timestamps=1` for real-time timing
- `aresample=async=1000:first_pts=0` filter to recover from audio drift
- Video `thread_queue_size` increased from 512 to 1024 for better a/v sync
- Removed `-shortest` flag that caused audio dropouts

**Configuration:**
```bash
STREAM_AUDIO_ENABLED=true
PULSE_AUDIO_DEVICE=chrome_audio.monitor
PULSE_SERVER=unix:/tmp/pulse-runtime/pulse/native
XDG_RUNTIME_DIR=/tmp/pulse-runtime
```

**Graceful Fallback:** Falls back to silent audio if PulseAudio unavailable.

- **Issue**: `CombatStateService` syncs abbreviated keys (`data.c`/`data.ct`) but `getGameState()` only read full keys (`data.inCombat`/`data.combatTarget`)
- **Impact**: DuelCombatAI always saw `inCombat=false` and flooded `executeAttack` every tick instead of letting auto-attacks drive combat
- **Fix**: `EmbeddedHyperscapeService.getGameState()` now reads both abbreviated and full keys:
  ```typescript
  inCombat: !!(data.inCombat || data.combatTarget || data.c || data.ct),
  currentTarget: (data.combatTarget as string) || (data.ct as string) || null,
  ```
- **File**: `packages/server/src/eliza/EmbeddedHyperscapeService.ts`
- **Root Cause**: CombatStateService uses abbreviated keys for network efficiency, but embedded service wasn't aware of this optimization

**Magic Attack TOCTOU Race Condition:**
- **Issue**: Cooldown was checked early but claimed after async `consumeRunesForSpell` call. With the combat state bug flooding attacks, two concurrent invocations could both pass the cooldown check before either claimed it
- **Impact**: Duplicate magic projectiles, double rune consumption, visual glitches
- **Fix**: Moved cooldown claim and `enterCombat` before async rune consumption to close the race window:
  ```typescript
  // Claim cooldown BEFORE async rune consumption
  this.ctx.combatSystem.setNextAttackTick(attackerId, nextAttackTick);
  this.ctx.combatSystem.enterCombat(attackerId, targetId, weaponType);
  
  // THEN consume runes (async operation)
  await this.ctx.runeService.consumeRunesForSpell(attackerId, spell);
  ```
- **File**: `packages/shared/src/systems/shared/combat/handlers/MagicAttackHandler.ts`
- **Pattern**: Time-of-check to time-of-use (TOCTOU) race condition
- **Prevention**: Claim resources synchronously before async operations
