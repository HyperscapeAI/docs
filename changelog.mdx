<Update label="Prayer System & Death Overhaul" description="January 2026" date="2026-01-18">

### 🙏 Prayer System

Complete OSRS-accurate prayer system with drain mechanics and combat bonuses:

- **Prayer Skill**: New combat skill trained by burying bones
  - Bone types: Regular (4.5 XP), Big (15 XP), Dragon (72 XP)
  - 2-tick (1.2s) bury delay (OSRS-accurate)
  - Prayer level = maximum prayer points
- **Prayer Activation**: Toggle prayers for temporary combat bonuses
  - 5 initial prayers: Thick Skin, Rock Skin, Burst of Strength, Clarity of Thought, Superhuman Strength
  - Defensive prayers: +5% to +10% Defense
  - Offensive prayers: +5% to +10% Attack/Strength
  - Maximum 6 active prayers simultaneously
- **Prayer Drain**: OSRS-accurate drain formula
  - `drainResistance = 2 × prayerBonus + 60`
  - `pointsPerMinute = drainEffect × 60 / drainResistance`
  - Drains every game tick (600ms)
  - All prayers deactivate when points reach 0
- **Prayer Altars**: Recharge prayer points to maximum
  - Interactive altar entities placed in world
  - 2-tile interaction range
  - Instant recharge on use
- **Combat Integration**: Prayer bonuses applied as multipliers to effective levels
  - `effectiveLevel = floor((baseLevel + styleBonus) × prayerMultiplier)`
  - Multiple prayers stack multiplicatively
  - Conflicting prayers auto-deactivate (e.g., can't have two Strength prayers)
- **Database Schema**: New columns in `characters` table
  - `prayerLevel`, `prayerXp`, `prayerPoints`, `prayerMaxPoints`, `activePrayers`
  - Active prayers stored as JSON array: `'["thick_skin", "burst_of_strength"]'`
- **Security Features**:
  - Rate limiting: 5 toggles/second
  - Input validation with type guards
  - Timestamp validation prevents replay attacks
  - Prayer ID format validation (regex pattern)
  - Bounds checking for all numeric inputs
- **UI Components**:
  - Prayer tab in Skills Panel with prayer points bar
  - Prayer cards with lock states for level requirements
  - Active state highlighting (green border)
  - Tooltips showing effects and drain rates
  - Color-coded points bar (green >25%, red ≤25%)
- **Manifest-Driven**: Prayer definitions in `manifests/prayers.json`
  - Data-driven architecture allows easy content updates
  - Supports prayer conflicts, categories, and bonuses
- **Testing**: 62 comprehensive unit tests covering all validation and mechanics

### ⚰️ Death System Overhaul

Major refactor with crash recovery, atomic operations, and combat state cleanup:

- **Crash Recovery System**: Enterprise-grade recovery prevents item loss on server restart
  - Death locks now store full item data in `items` JSONB column
  - `recovered` boolean tracks if death was processed during crash recovery
  - `killedBy` field identifies what killed the player
  - Server startup queries `WHERE recovered = false` and recreates gravestones/ground items
  - Atomic `INSERT ... ON CONFLICT DO NOTHING` prevents duplicate death locks
- **Transaction Safety**: Death processing uses serializable transactions
  - Death lock created FIRST with full item list (crash-safe)
  - Inventory/equipment cleared atomically
  - If crash occurs, items recoverable from death lock
  - `isolationLevel: "serializable"` prevents all race conditions
- **Shadow State Loot UI**: Transaction-based loot with automatic rollback
  - Client optimistically removes items from UI
  - Transaction IDs track pending loot requests
  - 3-second timeout triggers automatic rollback if no server response
  - `LOOT_RESULT` events confirm/reject loot operations
  - Prevents client/server desync on loot failures
- **Combat State Cleanup**: Three-layer cleanup on death/respawn
  - Event-based: `PLAYER_SET_DEAD` and `PLAYER_RESPAWNED` events
  - Runtime guards: Health checks in aggro/combat loops
  - Timeout cleanup: Stale states cleaned after timeout
  - Mobs stop chasing dead players
  - Combat states cleared when target dies
- **Input Sanitization**: Comprehensive security for `killedBy` field
  - Unicode NFKC normalization prevents homograph attacks
  - Zero-width character removal (U+200B-U+200D, U+FEFF)
  - BiDi override filtering (U+202A-U+202E)
  - Control character removal (0x00-0x1F, 0x7F)
  - HTML character filtering (<, >, ', ", &)
  - 64 character length limit
- **Position Validation**: NaN/Infinity checks with world bounds clamping
  - X/Z: -10000 to 10000
  - Y: -50 to 500
  - Prevents Three.js renderer crashes
- **Integer Overflow Protection**: 32-bit safe tick calculations
  - `MAX_TICK = 2147483647` (2^31-1)
  - Prevents MessagePack serialization overflow
- **Loot Rate Limiting**: 100ms cooldown between loot requests
- **Death Screen Improvements**:
  - Countdown timer showing time until items despawn
  - Respawn button spam prevention
  - 10-second timeout with retry on failure
  - Input blocking during death animation
- **Movement Blocking**: Players cannot move while dying or dead
  - `DeathState.DYING` and `DeathState.DEAD` block movement requests
- **Respawn Validation**: Server validates player is actually dead before allowing respawn
- **OSRS-Accurate Timings**:
  - Ground item despawn: 6000 ticks (60 minutes, was 300)
  - Death animation: 7 ticks (was 8)
  - Stale lock cleanup: 3000 ticks (30 minutes, was 6000)
- **Database Migration**: `0017_add_death_recovery_columns.sql`
  - New columns: `items` (JSONB), `killedBy` (TEXT), `recovered` (BOOLEAN)
  - Indexes: `idx_player_deaths_recovered`, `idx_player_deaths_recovery_lookup`
  - CHECK constraint for valid `zoneType` values
- **Code Quality**: Removed internal tracking codes (DS-XXX, Phase X) from comments

### 🐛 Bug Fixes

  - `isDeadMob()` helper checks `MobAIState.DEAD` or `currentHealth <= 0`
  - Raycast loop skips dead mobs to check next intersection

- **Firemaking Type Fix**: Aligned `FiremakingMoveRequestPayload` with actual usage (position instead of fromPosition/toPosition)

<Update label="Collision System & UI Improvements" description="January 2026" date="2026-01-16">

### 🎯 Static Tile Collision System

Production-quality OSRS-accurate collision system for static world objects and entities:

- **CollisionMatrix**: Zone-based collision storage with bitmask flags
  - World divided into 8×8 tile zones (Int32Array[64] = 256 bytes per zone)
  - Lazy allocation: zones created on first write
  - Memory efficient: 1000×1000 tile world = ~4MB
  - O(1) tile lookups with zero allocations in hot paths
- **Collision Flags**: OSRS-accurate bitmask flags
  - Static objects: `BLOCKED`, `WATER`, `STEEP_SLOPE`
  - Entity occupancy: `OCCUPIED_PLAYER`, `OCCUPIED_NPC`
  - Directional walls: 8 directions for future dungeons/buildings
  - Combined masks: `BLOCKS_WALK`, `BLOCKS_MOVEMENT`, `BLOCKS_RANGED`
- **Automatic Footprint Detection**: Build-time model bounds extraction
  - New `extract-model-bounds.ts` script parses GLB files
  - Extracts bounding boxes from glTF position accessors
  - Generates `model-bounds.json` manifest automatically
  - Footprints calculated from model dimensions × scale
  - Turbo caching avoids rebuilding when models unchanged
- **Multi-Tile Entities**: Stations and large resources occupy multiple tiles
  - Furnaces, anvils, banks support 2×2 footprints
  - Center-based registration (footprint centered on entity position)
  - OSRS-style interaction from any adjacent tile
  - `tilesWithinRangeOfFootprint()` for multi-tile range checks
- **Pathfinding Integration**: Mobs and players respect collision
  - BFSPathfinder checks `CollisionMatrix` for static objects
  - Safespotting: players can hide behind trees/rocks
  - Depleted resources remain solid (stumps block movement)
- **Network Synchronization**: Zone-based collision sync
  - Base64 serialization for efficient network transport
  - Only allocated zones sent to clients
  - `getZonesInRadius()` for area-based sync
- **Testing**: 1,118 lines of comprehensive unit tests
  - CollisionMatrix: zone allocation, flag operations, negative coordinates
  - CollisionFlags: bitmask uniqueness, directional walls
  - TileSystem: multi-tile footprint calculations

- **Money Pouch**: Protected coin storage (characters.coins column)

- **UI Components**:

- **Error Handling**: Graceful inventory sync with fallback

- **Testing**: 32 comprehensive unit tests
  - Input validation (NaN, Infinity, negative, overflow)
  - Insufficient coins, inventory full, stack overflow
  - New stack creation, existing stack updates
  - Atomicity simulation

### ⚡ Performance Optimizations

Raycast proxy optimization for fast entity click detection:

- **Raycast Proxy**: Invisible capsule meshes for instant click detection on NPCs and mobs
- **Performance Gain**: Avoids expensive VRM SkinnedMesh raycast (~700-1800ms per click)
- **Implementation**: Proxy added directly to THREE.Scene, bypasses Node system

OSRS-accurate food consumption with 3-tick eat delay and combat integration:
