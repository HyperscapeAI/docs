### 🤝 Player-to-Player Trading System

Complete OSRS-style trading system with two-screen confirmation flow and anti-scam features:

- **Trade Request Flow**: Click-based trade initiation with proximity checks
  - Players must be adjacent (1 tile) to trade
  - Auto-walk to target if out of range (OSRS-style)
  - Pink clickable chat messages for trade requests
  - Interface blocking: can't trade while banking/shopping
- **Two-Screen Confirmation**: OSRS-accurate anti-scam flow
  - **Offer Screen**: Add/remove items, see partner's offer
  - **Confirmation Screen**: Final review with wealth transfer indicator
  - Both players must accept on each screen
  - Acceptance resets if either offer changes
- **Anti-Scam Features**:
  - Red flashing exclamation when items removed from trade
  - Wealth transfer indicator shows value difference (green = gaining, red = losing)
  - Partner's free inventory slots displayed
  - Warning if wealth difference >50% of offer value
- **Click-Based UI**: OSRS-style item management
  - Left-click inventory item: add 1 to trade
  - Right-click inventory item: context menu (Offer-1, Offer-5, Offer-10, Offer-X, Offer-All, Value, Examine)
  - Click trade slot to remove item
  - Quantity prompt with K/M notation support (e.g., "10k", "1.5m")
- **Security & Validation**:
  - Server-authoritative state management
  - Atomic database transactions prevent item duplication
  - Inventory locks during swap operations
  - Tradeable flag enforcement
  - Rate limiting on trade requests
  - Proximity validation on every action
- **Modular Architecture**: Refactored from 1,105-line monolith into focused modules
  - `request.ts`: Trade initiation and response
  - `items.ts`: Add, remove, set quantity
  - `acceptance.ts`: Accept, cancel, two-screen flow
  - `swap.ts`: Atomic item swap execution
  - `helpers.ts`: Shared utilities
- **PendingTradeManager**: Server-authoritative walk-to-trade system
  - Zero-allocation hot path with pre-allocated buffers
  - Intelligent re-pathing when target moves
  - Proper cleanup on disconnect
- **Testing**: 291 lines of integration tests with real TradingSystem instances

### 🗺️ Terrain Flattening System

Automatic terrain flattening under stations for professional world building:

- **Flat Zones**: Rectangular areas with level ground
  - Defined per-station in `stations.json` manifest
  - `flattenGround: true` enables flattening
  - `flattenPadding`: extra meters around footprint (default: 0.3m)
  - `flattenBlendRadius`: smooth transition distance (default: 0.5m)
- **Spatial Indexing**: Efficient O(1) flat zone lookup
  - Terrain tiles (100m) used for spatial index
  - Multiple zones can overlap same terrain tile
  - Pre-calculated affected tiles on registration
- **Smooth Blending**: Natural transitions to procedural terrain
  - Smoothstep interpolation: t² × (3 - 2t)
  - Rectangular blend zones (not circular)
  - Blends from flat height to procedural height
- **Manifest-Driven**: Configured in station manifests
  - Banks, furnaces, anvils, altars, ranges support flattening
  - Auto-calculated from station footprint + padding
  - Height sampled from procedural terrain at station center
- **TerrainSystem API**: Public methods for dynamic flat zones
  - `registerFlatZone(zone)`: Add flat zone
  - `unregisterFlatZone(id)`: Remove flat zone
  - `getFlatZoneAt(x, z)`: Check if position is in flat zone
- **Increased Terrain Bumpiness**: Made terrain more varied to showcase flat zones
  - MAX_HEIGHT: 30m → 50m
  - Hill noise increased for more pronounced hills
  - Flat zones now visibly contrast with bumpy surroundings

### 🎮 Anchor-Based UI Positioning

Unity/Unreal-style anchor system for responsive UI scaling:

- **WindowAnchor System**: Windows maintain position relative to viewport anchors
  - 9 anchor points: corners, edges, center
  - Windows store offset from anchor, not absolute position
  - Responsive scaling preserves anchor relationships
- **Anchor Points**:
  - `top-left`, `top-center`, `top-right`
  - `center-left`, `center`, `center-right`
  - `bottom-left`, `bottom-center`, `bottom-right`
- **Default Anchors**: Sensible defaults for each window
  - Chat, Skills/Prayer: `bottom-left`
  - Minimap: `top-right`
  - Inventory, Menubar: `bottom-right`
  - Action bar: `bottom-center`
- **Viewport Resize**: Windows reposition based on anchor
  - Mobile → Desktop transitions use default layout
  - Desktop resizes preserve anchor offsets
  - Prevents windows clustering in corners
- **Migration**: v13 migration sets anchors on existing windows
- **Anchor Utilities**: Helper functions in `anchorUtils.ts`
  - `getAnchorPosition()`: Get viewport coordinates for anchor
  - `calculateOffsetFromAnchor()`: Window offset from anchor
  - `calculatePositionFromAnchor()`: Position from anchor + offset
  - `detectNearestAnchor()`: Auto-detect anchor from position
  - `repositionWindowForViewport()`: Main resize handler

### 🐛 Equipment System Fixes

Critical bug fixes preventing item duplication:

- **Transaction Locks**: Prevent race conditions during equip/unequip
  - Added locks to EquipmentSystem operations
  - Prevents concurrent equip/unequip on same player
- **Order of Operations**: Atomic equip/unequip flow
  - **equipItem**: Remove from inventory FIRST, then equip
    - If removal fails, abort equip (prevents duplication)
    - Verify item exists at specified inventory slot
  - **unequipItem**: Clear equipment slot FIRST, then add to inventory
    - Check inventory has space before unequipping
    - If add fails, restore equipment slot (prevents item loss)
- **New InventorySystem Methods**: Synchronous operations with return values
  - `hasSpace(playerId, slotsNeeded)`: Check if inventory has room
  - `hasItemAtSlot(playerId, itemId, slot)`: Verify item at specific slot
  - `removeItemDirect(playerId, params)`: Synchronous removal with return value
  - `addItemDirect(playerId, params)`: Synchronous add with return value

<Update label="Collision System & UI Improvements" description="January 2026" date="2026-01-16">

### 🎯 Static Tile Collision System

Production-quality OSRS-accurate collision system for static world objects and entities:

- **CollisionMatrix**: Zone-based collision storage with bitmask flags
  - World divided into 8×8 tile zones (Int32Array[64] = 256 bytes per zone)
  - Lazy allocation: zones created on first write
  - Memory efficient: 1000×1000 tile world = ~4MB
  - O(1) tile lookups with zero allocations in hot paths
- **Collision Flags**: OSRS-accurate bitmask flags
  - Static objects: `BLOCKED`, `WATER`, `STEEP_SLOPE`
  - Entity occupancy: `OCCUPIED_PLAYER`, `OCCUPIED_NPC`
  - Directional walls: 8 directions for future dungeons/buildings
  - Combined masks: `BLOCKS_WALK`, `BLOCKS_MOVEMENT`, `BLOCKS_RANGED`
- **Automatic Footprint Detection**: Build-time model bounds extraction
  - New `extract-model-bounds.ts` script parses GLB files
  - Extracts bounding boxes from glTF position accessors
  - Generates `model-bounds.json` manifest automatically
  - Footprints calculated from model dimensions × scale
  - Turbo caching avoids rebuilding when models unchanged
- **Multi-Tile Entities**: Stations and large resources occupy multiple tiles
  - Furnaces, anvils, banks support 2×2 footprints
  - Center-based registration (footprint centered on entity position)
  - OSRS-style interaction from any adjacent tile
  - `tilesWithinRangeOfFootprint()` for multi-tile range checks
- **Pathfinding Integration**: Mobs and players respect collision
  - BFSPathfinder checks `CollisionMatrix` for static objects
  - Safespotting: players can hide behind trees/rocks
  - Depleted resources remain solid (stumps block movement)
- **Network Synchronization**: Zone-based collision sync
  - Base64 serialization for efficient network transport
  - Only allocated zones sent to clients
  - `getZonesInRadius()` for area-based sync
- **Testing**: 1,118 lines of comprehensive unit tests
  - CollisionMatrix: zone allocation, flag operations, negative coordinates
  - CollisionFlags: bitmask uniqueness, directional walls
  - TileSystem: multi-tile footprint calculations
