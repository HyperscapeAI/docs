### ⚡ GPU-Instanced Particle System (PR #877)

Major performance optimization reducing fishing spot draw calls from ~150 to 4 via centralized GPU-instanced particle rendering:

- **ParticleManager Architecture**: Centralized particle routing system
  - Single entry point for all particle effects (water, glow, fire, magic)
  - Routes particle events to specialized sub-managers based on type
  - Ownership tracking eliminates need for type hints on unregister/move
  - Extensible design for future particle types (dust, smoke, blood)
- **WaterParticleManager**: GPU-instanced fishing spot effects
  - 4 InstancedMeshes (splash, bubble, shimmer, ripple) replace ~150 individual meshes
  - TSL NodeMaterials with InstancedBufferAttributes for per-particle data
  - GPU-computed animations (parabolic arcs, wobble, twinkle, ring expansion)
  - Per-instance data: spotPos (vec3), ageLifetime (vec2), angleRadius (vec2), dynamics (vec4)
  - Vertex buffer budget: 7 of 8 max attributes per particle layer
- **GlowParticleManager**: Instanced glow billboards for altars, fires, torches
  - Preset system: altar, fire, torch with configurable particle counts and spread
  - Mesh-aware spark placement (samples geometry vertices for altar preset)
  - Color override support (single hex or three-tone palette)
  - Billboard orientation via camera right/up vectors
- **Performance Impact**: 
  - FPS improvement: 65-70 → 120 on reference hardware
  - Draw calls: ~150 → 4 per fishing spot
  - CPU savings: ~450 lines of per-entity animation code eliminated
  - GPU-driven particle updates (trig, quaternion, opacity all on GPU)
- **ResourceEntity Refactor**: Delegates to ParticleManager hub API
  - Retains only lightweight glow mesh for interaction detection
  - Lazy registration pattern (retries if manager not ready during entity init)
  - Proper cleanup via unregister on destroy
- **ResourceSystem Integration**: Creates ParticleManager on client, forwards events
  - Retroactive registration for entities created before system start
  - Listens to RESOURCE_SPAWNED events for particle routing
  - Per-frame update drives all particle managers
- **Discriminated Union API**: Type-safe particle configuration
  - `WaterParticleConfig` for fishing spots (resourceId-based variants)
  - `GlowParticleConfig` for altars/fires/torches (preset-based)
  - `ParticleConfig = WaterParticleConfig | GlowParticleConfig`
- **Fishing Spot Variants**: Net (calm), Bait (medium), Fly (active)
  - Variant-specific colors, ripple speeds, particle counts
  - Burst system for fish activity (2-4 splash particles every 3-7 seconds)
  - Configurable burst intervals and splash counts per variant

  - "Let's go!", "Fight me!", "Too slow", "Bring it"

  - Pulls personality from Eliza agent runtime character definition

  - 3-second LLM timeout with scripted fallback
  - Temperature 0.9 for creative, varied responses

  - 6 own-low taunts, 6 opponent-low taunts, 8 ambient taunts
  - Ensures trash talk works even without LLM access

  - Never blocks combat tick loop
  - 8-second cooldown between messages
  - In-flight flag prevents overlapping LLM calls
- **DuelCombatAI Integration**: Trash talk wired into combat AI tick loop
  - `sendChatMessage` callback provided by DuelOrchestrator
  - Sends chat as overhead bubble via agent's EmbeddedHyperscapeService
  - Health milestone detection compares previous vs current HP

  - Previously blocked in combat state

### ⚡ Terrain Worker Performance Optimization (commit ef54a70)

Moved height and normal computation to web workers for 63x reduction in main-thread noise evaluations:

- **Worker Height Computation**: Full height calculation in worker threads
  - Synced noise weights to match TerrainSystem (hillScale 0.012→0.02, persistence 0.5→0.6)
  - Added shoreline adjustment to worker (calculateBaseSlopeAt, adjustHeightForShoreline)
  - Worker heights now fully correct for tiles without flat zones
- **Worker Normal Computation**: Normals computed in worker via overflow grid
  - (resolution+2)² overflow grid with centered finite differences
  - Eliminates ~16,384 noise calls per tile on main thread
  - 63x reduction in noise evaluations for normal calculation
- **Conditional Fallback**: Main-thread recomputation only for tiles with flat zones
  - Tiles without flat zones use worker data directly (zero noise calls)
  - Tiles overlapping buildings/stations recompute on main thread
  - Ensures flat zone heights are respected in final geometry
- **Performance Impact**: Terrain generation now runs in parallel across CPU cores
  - Main thread free for rendering and input handling
  - Smooth frame rates during terrain streaming
