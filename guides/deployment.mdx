## Deployment Overview

Hyperscape uses a split deployment model optimized for modern cloud platforms:

- **Server**: Railway (recommended), Fly.io, or Docker host
- **Client**: Cloudflare Pages (recommended), Vercel, or Netlify
- **Database**: PostgreSQL (Neon recommended)
- **Assets**: Cloudflare R2 CDN (recommended) or S3-compatible storage

### Production Architecture

The official production deployment uses:
- **Frontend**: Cloudflare Pages (`hyperscape.pages.dev`)
- **API/Server**: Railway (`hyperscape-production.up.railway.app`)
- **Assets/CDN**: Cloudflare R2
- **Database**: Neon PostgreSQL

This architecture provides:
- Global CDN distribution for assets and frontend
- Auto-scaling server infrastructure
- Serverless database with branching
- Automatic SSL/TLS certificates

## Environment Variables

### Server Production

```bash
# Required
DATABASE_URL=postgresql://...
JWT_SECRET=your-secret-key
PRIVY_APP_ID=your-app-id
PRIVY_APP_SECRET=your-app-secret

# Optional
PORT=5555
PUBLIC_CDN_URL=https://cdn.example.com
LIVEKIT_API_KEY=...
LIVEKIT_API_SECRET=...
```

### Client Production

```bash
PUBLIC_PRIVY_APP_ID=your-app-id
PUBLIC_API_URL=https://api.hyperscape.lol
PUBLIC_WS_URL=wss://api.hyperscape.lol
PUBLIC_CDN_URL=https://cdn.hyperscape.lol
```

<Warning>
  `PUBLIC_PRIVY_APP_ID` must match between client and server.
</Warning>

## Railway Deployment

Railway deployment is automated via GitHub Actions and uses Nixpacks for building.

<Steps>
  <Step title="Create Railway project">
    1. Connect your GitHub repository to Railway
    2. Create a new service from the repository
    3. Railway will auto-detect the `railway.server.json` configuration
  </Step>
  
  <Step title="Configure build">
    Railway uses `nixpacks.toml` for build configuration:
    - Builds only `shared` and `server` packages (frontend is on Cloudflare Pages)
    - Fetches manifests from CDN instead of cloning assets repo
    - Start command: `cd packages/server && bun dist/index.js`
  </Step>
  
  <Step title="Add PostgreSQL">
    Add PostgreSQL service from Railway marketplace and link to your service.
  </Step>
  
  <Step title="Set environment variables">
    Required variables:
    ```bash
    DATABASE_URL=${{Postgres.DATABASE_URL}}  # Auto-linked
    JWT_SECRET=your-random-secret
    PRIVY_APP_ID=your-privy-app-id
    PRIVY_APP_SECRET=your-privy-app-secret
    PUBLIC_CDN_URL=https://your-cdn-url
    NODE_ENV=production
    ```
  </Step>
  
  <Step title="Configure GitHub Actions (optional)">
    The repository includes `.github/workflows/deploy-railway.yml` for automated deployments.
    
    Add these secrets to your GitHub repository:
    - `RAILWAY_TOKEN` - Railway API token
    
    Set these environment IDs in the workflow file:
    - `RAILWAY_PROJECT_ID`
    - `RAILWAY_SERVICE_ID`
    - `RAILWAY_ENVIRONMENT_ID`
  </Step>
</Steps>

<Info>
Railway deployment automatically triggers on pushes to `main` that affect server-related files. The workflow uses Railway's GraphQL API to trigger redeployments.
</Info>

## Cloudflare Pages Deployment (Recommended)

Cloudflare Pages provides global CDN distribution and automatic preview deployments.

<Steps>
  <Step title="Connect repository">
    1. Go to Cloudflare Pages dashboard
    2. Create a new project from your GitHub repository
    3. Select the `packages/client` directory as the root
  </Step>
  
  <Step title="Configure build">
    ```
    Build command: bun run build
    Build output directory: dist
    Root directory: packages/client
    ```
  </Step>
  
  <Step title="Set environment variables">
    Add these in Cloudflare Pages → Settings → Environment variables:
    ```bash
    PUBLIC_PRIVY_APP_ID=your-privy-app-id
    PUBLIC_API_URL=https://hyperscape-production.up.railway.app
    PUBLIC_WS_URL=wss://hyperscape-production.up.railway.app/ws
    PUBLIC_CDN_URL=https://your-r2-cdn-url
    ```
  </Step>
  
  <Step title="Configure CORS on server">
    Add your Cloudflare Pages domain to the server's CORS allowlist:
    ```typescript
    // In packages/server/src/startup/http-server.ts
    const allowedOrigins = [
      'https://hyperscape.pages.dev',
      'https://*.hyperscape.pages.dev',  // Preview deployments
      // ... your custom domain
    ];
    ```
  </Step>
</Steps>

<Info>
Cloudflare Pages automatically creates preview deployments for pull requests at `*.hyperscape.pages.dev` subdomains. The CORS configuration supports wildcard subdomains for preview deployments.
</Info>

## Database Setup

### Neon PostgreSQL

1. Create database at [neon.tech](https://neon.tech)
2. Copy connection string
3. Set as `DATABASE_URL` in server environment

### Migrations

```bash
cd packages/server
bunx drizzle-kit push      # Apply schema
bunx drizzle-kit migrate   # Run migrations
```

## CDN Setup

### Option 1: Cloudflare R2 (Recommended)

Cloudflare R2 provides S3-compatible object storage with zero egress fees:

<Steps>
  <Step title="Create R2 bucket">
    1. Go to Cloudflare dashboard → R2
    2. Create a new bucket (e.g., `hyperscape-assets`)
    3. Enable public access
  </Step>
  
  <Step title="Upload assets">
    Upload the contents of `packages/server/world/assets/` to your R2 bucket.
  </Step>
  
  <Step title="Configure custom domain">
    1. Add a custom domain to your R2 bucket (e.g., `assets.hyperscape.club`)
    2. Set `PUBLIC_CDN_URL=https://assets.hyperscape.club` in both client and server environments
  </Step>
</Steps>

<Info>
In production, the server fetches manifests from the CDN at startup instead of bundling them in the deployment. This reduces deployment size and allows manifest updates without redeploying the server.
</Info>

### Option 2: Self-Hosted

Use the included Docker CDN for development or self-hosted deployments:

```bash
bun run cdn:up
```

Configure `PUBLIC_CDN_URL` to point to your CDN host.

### Option 3: AWS S3 or Compatible

Upload assets to S3, DigitalOcean Spaces, or similar:

1. Build assets: `bun run assets:optimize`
2. Upload `packages/server/world/assets/`
3. Set `PUBLIC_CDN_URL` to bucket URL
