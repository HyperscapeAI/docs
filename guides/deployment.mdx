## Deployment Overview

Hyperscape uses a split deployment model:

- **Server**: Railway, Fly.io, or Docker host
- **Client**: Vercel, Netlify, or static hosting
- **Database**: PostgreSQL (Neon recommended)
- **Assets**: CDN or object storage

## Environment Variables

### Server Production

```bash
# Required
DATABASE_URL=postgresql://...
JWT_SECRET=your-secret-key
PRIVY_APP_ID=your-app-id
PRIVY_APP_SECRET=your-app-secret

# Optional
PORT=5555
PUBLIC_CDN_URL=https://cdn.example.com
LIVEKIT_API_KEY=...
LIVEKIT_API_SECRET=...
```

### Client Production

```bash
PUBLIC_PRIVY_APP_ID=your-app-id
PUBLIC_API_URL=https://api.hyperscape.lol
PUBLIC_WS_URL=wss://api.hyperscape.lol
PUBLIC_CDN_URL=https://cdn.hyperscape.lol
```

<Warning>
  `PUBLIC_PRIVY_APP_ID` must match between client and server.
</Warning>

## Railway Deployment

Railway deployment is fully automated via GitHub Actions. The workflow uses Railway's GraphQL API for deployments and supports both Nixpacks and Docker build methods.

### Automated Deployment

The repository includes a GitHub Actions workflow that automatically deploys to Railway on every push to `main`:

```yaml
# .github/workflows/deploy-railway.yml
name: Deploy to Railway
on:
  push:
    branches: [main]
    paths:
      - 'packages/shared/**'
      - 'packages/server/**'
      - 'packages/plugin-hyperscape/**'
      - 'package.json'
      - 'bun.lock'
      - 'nixpacks.toml'
      - 'railway.server.json'
      - 'Dockerfile.server'
```

The workflow triggers deployments using Railway's GraphQL API and monitors deployment status.

### Setup Steps

<Steps>
  <Step title="Create Railway project">
    1. Create a new project at [railway.app](https://railway.app)
    2. Connect your GitHub repository
    3. Note your Project ID, Service ID, and Environment ID
  </Step>
  
  <Step title="Configure GitHub secrets">
    Add to your repository secrets:
    - `RAILWAY_TOKEN`: Your Railway API token
    
    Update workflow environment variables:
    ```yaml
    env:
      RAILWAY_PROJECT_ID: your-project-id
      RAILWAY_SERVICE_ID: your-service-id
      RAILWAY_ENVIRONMENT_ID: your-environment-id
    ```
  </Step>
  
  <Step title="Choose build method">
    Railway supports two build methods:
    
    **Option 1: Nixpacks (Recommended)**
    - Uses `nixpacks.toml` configuration
    - Faster builds with caching
    - Automatic dependency detection
    
    **Option 2: Docker**
    - Uses `Dockerfile.server`
    - Multi-stage builds for smaller images
    - More control over build process
  </Step>
  
  <Step title="Add PostgreSQL">
    Add PostgreSQL service from Railway marketplace.
    Railway will automatically set `DATABASE_URL`.
  </Step>
  
  <Step title="Set environment variables">
    Configure in Railway dashboard:
    ```bash
    # Required
    PRIVY_APP_ID=your-privy-app-id
    PRIVY_APP_SECRET=your-privy-app-secret
    JWT_SECRET=your-random-secret
    
    # Build configuration
    CI=true
    SKIP_ASSETS=true
    NODE_ENV=production
    
    # Optional
    PUBLIC_CDN_URL=https://cdn.hyperscape.lol
    ```
  </Step>
</Steps>

### Nixpacks Configuration

The `nixpacks.toml` file configures Railway's Nixpacks builder:

```toml
# nixpacks.toml
[phases.setup]
aptPkgs = [
  "python3", "make", "g++", "git",
  "pkg-config", "libcairo2-dev", "libpango1.0-dev",
  "libjpeg-dev", "libgif-dev", "librsvg2-dev"
]

[phases.install]
cmds = ["bun install --frozen-lockfile"]

[phases.assets]
dependsOn = ["install"]
cmds = ["git clone --depth 1 https://github.com/HyperscapeAI/assets.git packages/server/world/assets"]

[phases.build]
dependsOn = ["assets"]
cmds = [
  "bun run build:shared",
  "bun run build:server"
]

[start]
cmd = "bun dist/index.js"

[variables]
CI = "true"
SKIP_ASSETS = "true"
NODE_ENV = "production"
```

### Docker Configuration

The `Dockerfile.server` provides a multi-stage build:

**Stage 1: Builder**
- Installs build dependencies (Python, Make, G++, Cairo)
- Clones game assets from GitHub
- Builds packages in correct order (PhysX → Shared → Server)

**Stage 2: Runtime**
- Minimal production image with only runtime dependencies
- Copies built artifacts from builder stage
- Includes game manifests for DataManager
- Exposes port 5555 with health check

```dockerfile
# Multi-stage build
FROM oven/bun:1.1.38-debian AS builder
# ... build steps ...

FROM oven/bun:1.1.38-debian AS runtime
# ... runtime setup ...
CMD ["bun", "run", "start"]
```

### Asset Handling in Production

In production/CI environments, assets are served from CDN instead of being bundled:

```javascript
// scripts/ensure-assets.mjs
function isCI() {
  return !!(
    process.env.CI ||
    process.env.RAILWAY_ENVIRONMENT ||
    process.env.RAILWAY_SERVICE_ID ||
    process.env.VERCEL ||
    process.env.NETLIFY ||
    process.env.GITHUB_ACTIONS
  );
}

if (isCI()) {
  console.log("⏭️  Skipping asset download (CI/production environment detected)");
  console.log("   Assets are served from CDN in production");
  return;
}
```

Set `PUBLIC_CDN_URL` to your asset hosting URL in Railway environment variables.

### Deployment Workflow

The GitHub Actions workflow:

1. **Triggers** on push to main (when server-related files change)
2. **Deploys** via Railway GraphQL API mutation
3. **Monitors** deployment status with polling
4. **Reports** success/failure in GitHub Actions logs

<Info>
The workflow uses Railway's GraphQL API instead of the CLI for more reliable deployments and better status monitoring.
</Info>

## Database Setup

### Neon PostgreSQL

1. Create database at [neon.tech](https://neon.tech)
2. Copy connection string
3. Set as `DATABASE_URL` in server environment

### Migrations

```bash
cd packages/server
bunx drizzle-kit push      # Apply schema
bunx drizzle-kit migrate   # Run migrations
```

## CDN Setup

### Option 1: Self-Hosted

Use the included Docker CDN:

```bash
bun run cdn:up
```

Configure `PUBLIC_CDN_URL` to point to your CDN host.

### Option 2: Cloud Storage

Upload assets to S3, R2, or similar:

1. Build assets: `bun run assets:optimize`
2. Upload `packages/server/world/assets/`
3. Set `PUBLIC_CDN_URL` to bucket URL
