## Deployment Overview

Hyperscape uses a split deployment model:

- **Server**: Railway, Fly.io, or Docker host
- **Client**: Vercel, Netlify, or static hosting
- **Database**: PostgreSQL (Neon recommended)
- **Assets**: CDN or object storage

## Environment Variables

### Server Production

```bash
# Required
DATABASE_URL=postgresql://...
JWT_SECRET=your-secret-key
PRIVY_APP_ID=your-app-id
PRIVY_APP_SECRET=your-app-secret

# Optional
PORT=5555
PUBLIC_CDN_URL=https://cdn.example.com
LIVEKIT_API_KEY=...
LIVEKIT_API_SECRET=...
```

### Client Production

```bash
PUBLIC_PRIVY_APP_ID=your-app-id
PUBLIC_API_URL=https://api.hyperscape.lol
PUBLIC_WS_URL=wss://api.hyperscape.lol
PUBLIC_CDN_URL=https://cdn.hyperscape.lol
```

<Warning>
  `PUBLIC_PRIVY_APP_ID` must match between client and server.
</Warning>

## Railway Deployment

Railway deployment is automated via GitHub Actions (`.github/workflows/deploy-railway.yml`). The workflow triggers on pushes to `main` that affect server or client files.

### Automated Deployment

The deployment workflow:
1. Builds the client frontend (`bun run build:client`)
2. Copies client dist to server's `public/` directory
3. Deploys to Railway using the GraphQL API
4. Server fetches game manifests from CDN at startup

<Info>
  Manifests are fetched from `https://d20g7vd4m53hpb.cloudfront.net` at server startup. No need to clone the assets repository in production.
</Info>

### Manual Railway Setup

<Steps>
  <Step title="Create Railway project">
    Connect your GitHub repository to Railway.
  </Step>
  
  <Step title="Configure build">
    Railway uses `nixpacks.toml` for build configuration:
    - Build command: `bun run build`
    - Start command: `cd packages/server && bun run start:railway`
    - Frontend is built and copied to `public/` during build
  </Step>
  
  <Step title="Add PostgreSQL">
    Add PostgreSQL service from Railway marketplace. Railway will automatically set `DATABASE_URL`.
  </Step>
  
  <Step title="Set environment variables">
    Required variables:
    ```bash
    PUBLIC_PRIVY_APP_ID=your-app-id
    PRIVY_APP_SECRET=your-app-secret
    JWT_SECRET=your-jwt-secret
    PUBLIC_CDN_URL=https://d20g7vd4m53hpb.cloudfront.net
    ```
  </Step>
  
  <Step title="Configure GitHub Actions">
    Add `RAILWAY_TOKEN` secret to your GitHub repository:
    1. Generate token at [Railway Dashboard](https://railway.app/account/tokens)
    2. Add as repository secret: Settings → Secrets → Actions → New secret
    3. Name: `RAILWAY_TOKEN`
  </Step>
</Steps>

### Railway Configuration Files

- **`nixpacks.toml`**: Nixpacks builder configuration with Bun provider
- **`railway.server.json`**: Railway service configuration
- **`.railwayignore`**: Files to exclude from deployment
- **`Dockerfile.server`**: Multi-stage Docker build (alternative to Nixpacks)

## Database Setup

### Neon PostgreSQL

1. Create database at [neon.tech](https://neon.tech)
2. Copy connection string
3. Set as `DATABASE_URL` in server environment

### Migrations

```bash
cd packages/server
bunx drizzle-kit push      # Apply schema
bunx drizzle-kit migrate   # Run migrations
```

## CDN Setup

### Production CDN

In production, the server automatically fetches manifests from the CDN at startup:

```typescript
// Server fetches manifests from CDN on boot
const CDN_URL = "https://d20g7vd4m53hpb.cloudfront.net";
await fetchManifestsFromCDN(CDN_URL, manifestsDir);
```

<Info>
  The server only needs manifest JSON files in production. 3D models, textures, and audio are served directly from the CDN to clients.
</Info>

### Local Development CDN

Use the included Docker CDN for local development:

```bash
bun run cdn:up
```

This serves assets from the local `assets/` directory cloned via Git LFS.

### Custom CDN Setup

To use your own CDN:

1. Upload assets to S3, R2, or similar
2. Set `PUBLIC_CDN_URL` environment variable
3. Ensure manifests are accessible at `${CDN_URL}/manifests/`
