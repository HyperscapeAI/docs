## Deployment Overview

Hyperscape uses a split deployment model:

- **Server**: Railway, Fly.io, or Docker host
- **Client**: Vercel, Netlify, or static hosting
- **Database**: PostgreSQL (Neon recommended)
- **Assets**: CDN or object storage

## Environment Variables

### Server Production

```bash
# Required
DATABASE_URL=postgresql://...
JWT_SECRET=your-secret-key
PRIVY_APP_ID=your-app-id
PRIVY_APP_SECRET=your-app-secret

# Optional
PORT=5555
PUBLIC_CDN_URL=https://cdn.example.com
LIVEKIT_API_KEY=...
LIVEKIT_API_SECRET=...
```

### Client Production

```bash
PUBLIC_PRIVY_APP_ID=your-app-id
PUBLIC_API_URL=https://api.hyperscape.lol
PUBLIC_WS_URL=wss://api.hyperscape.lol
PUBLIC_CDN_URL=https://cdn.hyperscape.lol
```

<Warning>
  `PUBLIC_PRIVY_APP_ID` must match between client and server.
</Warning>

## Railway Deployment

Railway deployment uses Nixpacks for automatic builds and serves both the game server and client from a single service.

<Steps>
  <Step title="Create Railway project">
    Connect your GitHub repository to Railway.
  </Step>
  
  <Step title="Configure build">
    Railway automatically detects the Nixpacks configuration from `nixpacks.toml`:
    - Build command: Multi-phase build (shared → client → server)
    - Start command: `bun run start:railway`
    - Frontend assets are built and copied to `public/` directory
  </Step>
  
  <Step title="Add PostgreSQL">
    Add PostgreSQL service from Railway marketplace.
    Railway will automatically set `DATABASE_URL` environment variable.
  </Step>
  
  <Step title="Set environment variables">
    Add all required server environment variables:
    ```bash
    PUBLIC_PRIVY_APP_ID=your-app-id
    PRIVY_APP_SECRET=your-app-secret
    JWT_SECRET=your-secret-key
    PUBLIC_CDN_URL=https://d20g7vd4m53hpb.cloudfront.net
    ```
  </Step>
  
  <Step title="Configure asset serving">
    The server automatically:
    - Fetches game manifests from CDN at startup
    - Serves frontend from `/public` directory
    - Registers asset routes conditionally based on manifest availability
  </Step>
</Steps>

### Railway Build Process

The Railway deployment uses a multi-phase build process defined in `nixpacks.toml`:

1. **Install Phase**: Install dependencies with Bun
2. **Build Phase**: 
   - Build shared package
   - Build client (Vite)
   - Build server
   - Copy client dist to server public directory
3. **Start Phase**: Run server with `bun run start:railway`

### Asset Handling in Production

In production (Railway/CI environments), assets are served from CDN:

- **Manifests**: Fetched from CDN at server startup via `fetchManifestsFromCDN()`
- **3D Models/Textures**: Served directly from CloudFront CDN
- **No Git LFS**: The `ensure-assets.mjs` script skips asset download in CI environments

<Info>
The server detects CI/Railway environments and automatically skips local asset downloads, relying entirely on the CDN for asset delivery.
</Info>

### Debugging Railway Deployments

Recent improvements to Railway deployment include:

- Build timestamp file (`/public/build-timestamp.txt`) to verify builds are running
- Debug endpoint (`/debug/public`) to inspect public directory contents
- Verbose logging during build phases
- Explicit verification that `index.html` exists before starting server

<Warning>
If the frontend fails to load, check the Railway build logs for client build errors. The server will not start if `public/index.html` is missing.
</Warning>

## Vercel Client Deployment

<Steps>
  <Step title="Import project">
    Import `packages/client` directory to Vercel.
  </Step>
  
  <Step title="Configure build">
    Root directory: `packages/client`
    Build command: `bun run build`
    Output directory: `dist`
  </Step>
  
  <Step title="Set environment variables">
    Add `PUBLIC_*` environment variables.
  </Step>
</Steps>

## Database Setup

### Neon PostgreSQL

1. Create database at [neon.tech](https://neon.tech)
2. Copy connection string
3. Set as `DATABASE_URL` in server environment

### Migrations

```bash
cd packages/server
bunx drizzle-kit push      # Apply schema
bunx drizzle-kit migrate   # Run migrations
```

## CDN Setup

### Option 1: Self-Hosted

Use the included Docker CDN:

```bash
bun run cdn:up
```

Configure `PUBLIC_CDN_URL` to point to your CDN host.

### Option 2: Cloud Storage

Upload assets to S3, R2, or similar:

1. Build assets: `bun run assets:optimize`
2. Upload `packages/server/world/assets/`
3. Set `PUBLIC_CDN_URL` to bucket URL
