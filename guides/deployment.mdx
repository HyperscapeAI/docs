## Deployment Overview

Hyperscape uses a split deployment model:

- **Server**: Railway, Fly.io, or Docker host
- **Client**: Vercel, Netlify, or static hosting
- **Database**: PostgreSQL (Neon recommended)
- **Assets**: CDN or object storage

## Environment Variables

### Server Production

```bash
# Required
DATABASE_URL=postgresql://...
JWT_SECRET=your-secret-key
PRIVY_APP_ID=your-app-id
PRIVY_APP_SECRET=your-app-secret

# Optional
PORT=5555
PUBLIC_CDN_URL=https://cdn.example.com
LIVEKIT_API_KEY=...
LIVEKIT_API_SECRET=...
```

### Client Production

```bash
PUBLIC_PRIVY_APP_ID=your-app-id
PUBLIC_API_URL=https://api.hyperscape.lol
PUBLIC_WS_URL=wss://api.hyperscape.lol
PUBLIC_CDN_URL=https://cdn.hyperscape.lol
```

<Warning>
  `PUBLIC_PRIVY_APP_ID` must match between client and server.
</Warning>

## Railway Deployment

Railway deployment is automated via GitHub Actions (`.github/workflows/deploy-railway.yml`).

<Steps>
  <Step title="Create Railway project">
    Connect your GitHub repository to Railway.
  </Step>
  
  <Step title="Configure build">
    Railway uses `nixpacks.toml` for build configuration:
    
    ```toml
    [phases.setup]
    nixPkgs = ["bun"]
    
    [phases.build]
    cmds = [
      "bun install --frozen-lockfile",
      "bun run build:shared",
      "bun run build:client",
      "bun run build:server"
    ]
    
    [start]
    cmd = "cd packages/server && bun run start:railway"
    ```
  </Step>
  
  <Step title="Add PostgreSQL">
    Add PostgreSQL service from Railway marketplace.
    Railway automatically sets `DATABASE_URL`.
  </Step>
  
  <Step title="Set environment variables">
    Required variables:
    ```bash
    PRIVY_APP_ID=your-app-id
    PRIVY_APP_SECRET=your-app-secret
    JWT_SECRET=your-secret-key
    PUBLIC_CDN_URL=https://cdn.hyperscape.lol
    ```
  </Step>
  
  <Step title="Configure manifest loading">
    Railway deployment fetches manifests from CDN at startup:
    
    ```typescript
    // From http-server.ts
    if (process.env.NODE_ENV === "production") {
      await fetchManifestsFromCDN(config.manifestsDir);
    }
    ```
    
    Manifests are downloaded from `PUBLIC_CDN_URL/manifests/` to avoid bundling large asset files.
  </Step>
</Steps>

### Railway GitHub Actions

The repository includes automated Railway deployment:

```yaml
# .github/workflows/deploy-railway.yml
name: Deploy to Railway
on:
  push:
    branches: [main]
    paths:
      - 'packages/server/**'
      - 'packages/shared/**'
      - 'packages/client/**'
```

**Features**:
- Automatic deployment on push to main
- Builds client and server
- Fetches manifests from CDN (not from assets repo)
- Uses Railway GraphQL API for deployment

### CORS Configuration

Railway deployment requires CORS configuration for Cloudflare Pages frontend:

```typescript
// From http-server.ts
const allowedOrigins = [
  "https://hyperscape.club",
  "https://www.hyperscape.club",
  "https://hyperscape.pages.dev",
  "http://hyperscape.pages.dev",
  /^https:\/\/[a-z0-9-]+\.hyperscape\.pages\.dev$/,  // Preview deployments
  /^http:\/\/[a-z0-9-]+\.hyperscape\.pages\.dev$/,   // HTTP fallback
  /^http:\/\/localhost:\d+$/,                         // Local development
];
```

## Vercel Client Deployment

<Steps>
  <Step title="Import project">
    Import `packages/client` directory to Vercel.
  </Step>
  
  <Step title="Configure build">

  </Step>

## Database Setup

### Neon PostgreSQL

1. Create database at [neon.tech](https://neon.tech)
2. Copy connection string
3. Set as `DATABASE_URL` in server environment

### Migrations

```bash
cd packages/server
bunx drizzle-kit push      # Apply schema
bunx drizzle-kit migrate   # Run migrations
```

## CDN Setup

### Option 1: Self-Hosted

Use the included Docker CDN:

```bash
bun run cdn:up
```

Configure `PUBLIC_CDN_URL` to point to your CDN host.

### Option 2: Cloud Storage

Upload assets to S3, R2, or similar:

1. Build assets: `bun run assets:optimize`
2. Upload `packages/server/world/assets/`
3. Set `PUBLIC_CDN_URL` to bucket URL
