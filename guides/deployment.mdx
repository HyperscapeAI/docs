## Deployment Overview

Hyperscape uses a split deployment model:

- **Server**: Railway, Fly.io, or Docker host
- **Client**: Vercel, Netlify, or static hosting
- **Database**: PostgreSQL (Neon recommended)
- **Assets**: CDN or object storage

## Environment Variables

### Server Production

```bash
# Required
DATABASE_URL=postgresql://...
JWT_SECRET=your-secret-key
PRIVY_APP_ID=your-app-id
PRIVY_APP_SECRET=your-app-secret

# Optional
PORT=5555
PUBLIC_CDN_URL=https://cdn.example.com
LIVEKIT_API_KEY=...
LIVEKIT_API_SECRET=...
```

### Client Production

```bash
PUBLIC_PRIVY_APP_ID=your-app-id
PUBLIC_API_URL=https://api.hyperscape.lol
PUBLIC_WS_URL=wss://api.hyperscape.lol
PUBLIC_CDN_URL=https://cdn.hyperscape.lol
```

<Warning>
  `PUBLIC_PRIVY_APP_ID` must match between client and server.
</Warning>

## Railway Deployment

Railway deployment uses Nixpacks for automatic builds. The configuration is in `nixpacks.toml` at the repository root.

<Steps>
  <Step title="Create Railway project">
    Connect your GitHub repository to Railway.
  </Step>
  
  <Step title="Configure build">
    Railway automatically detects `nixpacks.toml` and uses it for builds.
    
    Build phases:
    - **Setup**: Installs system dependencies (Python, Cairo, etc.)
    - **Install**: Runs `bun install`
    - **Build**: Builds shared and server packages only (client is on Cloudflare Pages)
    - **Start**: Runs `cd packages/server && bun dist/index.js`
  </Step>
  
  <Step title="Add PostgreSQL">
    Add PostgreSQL service from Railway marketplace.
    Railway automatically sets `DATABASE_URL` environment variable.
  </Step>
  
  <Step title="Set environment variables">
    Required variables:
    ```bash
    DATABASE_URL=postgresql://...  # Auto-set by Railway
    JWT_SECRET=your-secret-key
    PRIVY_APP_ID=your-app-id
    PRIVY_APP_SECRET=your-app-secret
    PUBLIC_CDN_URL=https://your-cdn.com
    NODE_ENV=production
    ```
  </Step>
  
  <Step title="Configure CDN">
    Assets are served from CDN (Cloudflare R2 recommended).
    
    The server fetches manifests from `PUBLIC_CDN_URL` at startup:
    - Manifests are downloaded to `packages/server/world/assets/manifests/`
    - Skipped in development if local manifests exist
    - Required in production (CI=true environment)
  </Step>
</Steps>

### Railway GitHub Actions

Automatic deployment is configured in `.github/workflows/deploy-railway.yml`:

- Triggers on push to `main` for server-related paths
- Uses Railway GraphQL API for deployments
- Requires `RAILWAY_TOKEN` secret in GitHub repository settings

<Info>
The Railway deployment workflow was updated to use the GraphQL API instead of the deprecated CLI method.
</Info>

    Import `packages/client` directory to Vercel.
  </Step>
  
  <Step title="Configure build">

## Database Setup

### Neon PostgreSQL

1. Create database at [neon.tech](https://neon.tech)
2. Copy connection string
3. Set as `DATABASE_URL` in server environment

### Migrations

```bash
cd packages/server
bunx drizzle-kit push      # Apply schema
bunx drizzle-kit migrate   # Run migrations
```

## CDN Setup

### Option 1: Cloudflare R2 (Recommended for Production)

Cloudflare R2 provides S3-compatible object storage with zero egress fees.

1. Create R2 bucket at [Cloudflare Dashboard](https://dash.cloudflare.com)
2. Upload assets to bucket (models, textures, manifests)
3. Configure public access or custom domain
4. Set `PUBLIC_CDN_URL` to your R2 bucket URL

**Manifest Fetching**:
- Server automatically fetches manifests from `PUBLIC_CDN_URL` at startup
- Manifests are cached in `packages/server/world/assets/manifests/`
- In development, local manifests are used if they exist (skips CDN fetch)

### Option 2: Self-Hosted (Development)

In production, the server automatically fetches manifests from the CDN at startup:

```typescript
// Server fetches manifests from CDN on boot
const CDN_URL = "https://d20g7vd4m53hpb.cloudfront.net";
await fetchManifestsFromCDN(CDN_URL, manifestsDir);
```

<Info>
  The server only needs manifest JSON files in production. 3D models, textures, and audio are served directly from the CDN to clients.
</Info>

### Local Development CDN

Use the included Docker CDN for local development:

```bash
bun run cdn:up
```

Configure `PUBLIC_CDN_URL=http://localhost:8080`

### Option 3: Other Cloud Storage

Upload assets to S3, Google Cloud Storage, or similar:

1. Upload assets to S3, R2, or similar
2. Set `PUBLIC_CDN_URL` environment variable
3. Ensure manifests are accessible at `${CDN_URL}/manifests/`

<Info>
**Production Requirement**: In production (CI=true), the server expects manifests to be available at `PUBLIC_CDN_URL`. The `ensure-assets.mjs` script skips local asset downloads in CI environments.
</Info>
