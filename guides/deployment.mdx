## Deployment Overview

Hyperscape uses a split deployment architecture optimized for performance and scalability:

- **Frontend**: Cloudflare Pages (hyperscape.club)
- **Backend/API**: Railway (hyperscape-production.up.railway.app)
- **Database**: PostgreSQL via Railway or Neon
- **Assets/CDN**: Cloudflare R2 (assets.hyperscape.club)

This architecture separates static frontend delivery from dynamic game server operations, enabling global edge caching for the client while maintaining low-latency WebSocket connections to the game server.

## Environment Variables

### Server Production (Railway)

```bash
# Required
DATABASE_URL=postgresql://...              # Auto-set by Railway PostgreSQL
JWT_SECRET=your-secret-key                 # Generate with: openssl rand -base64 32
PUBLIC_PRIVY_APP_ID=your-app-id           # From Privy dashboard
PRIVY_APP_SECRET=your-app-secret          # From Privy dashboard

# Production URLs
PUBLIC_CDN_URL=https://assets.hyperscape.club
PUBLIC_API_URL=https://hyperscape-production.up.railway.app
PUBLIC_WS_URL=wss://hyperscape-production.up.railway.app/ws

# Optional
PORT=5555                                  # Railway auto-assigns if not set
ADMIN_CODE=your-admin-code                # For /admin command
LIVEKIT_API_KEY=...                       # Voice chat (optional)
LIVEKIT_API_SECRET=...
LIVEKIT_URL=wss://...
```

### Client Production (Cloudflare Pages)

```bash
PUBLIC_PRIVY_APP_ID=your-app-id
PUBLIC_API_URL=https://hyperscape-production.up.railway.app
PUBLIC_WS_URL=wss://hyperscape-production.up.railway.app
PUBLIC_CDN_URL=https://cdn.hyperscape.club
```

<Warning>
  `PUBLIC_PRIVY_APP_ID` must match between client and server for authentication to work.
</Warning>

## Railway Deployment (Backend/API)

Railway hosts the game server with automatic deployments via GitHub Actions.

### Automated Deployment

The repository includes a GitHub Actions workflow that automatically deploys to Railway on every push to `main`:

```yaml
# .github/workflows/deploy-railway.yml
name: Deploy to Railway
on:
  push:
    branches: [main]
    paths:
      - 'packages/shared/**'
      - 'packages/server/**'
      - 'packages/client/**'
      - 'packages/plugin-hyperscape/**'
```

**Deployment Process:**
1. Push to `main` branch triggers workflow
2. GitHub Actions calls Railway GraphQL API
3. Railway rebuilds using Nixpacks configuration
4. Server restarts with new code
5. Manifests fetched from CDN at startup

### Manual Setup

<Steps>
  <Step title="Create Railway project">
    1. Connect your GitHub repository to Railway
    2. Select the `hyperscape` repository
    3. Railway will auto-detect the Nixpacks configuration
  </Step>
  
  <Step title="Configure build (automatic)">
    Railway uses `nixpacks.toml` for build configuration:
    - Builder: Nixpacks with Bun provider
    - Build: `bun run build:shared && bun run build:server`
    - Start: `cd packages/server && bun dist/index.js`
    
    No manual configuration needed - Railway reads `nixpacks.toml` automatically.
  </Step>
  
  <Step title="Add PostgreSQL">
    Add PostgreSQL service from Railway marketplace or use external database (Neon).
    
    Railway will automatically set `DATABASE_URL` environment variable.
  </Step>
  
  <Step title="Set environment variables">
    Required variables:
    ```bash
    NODE_ENV=production
    JWT_SECRET=<generate-with-openssl-rand-base64-32>
    PRIVY_APP_ID=<from-privy-dashboard>
    PRIVY_APP_SECRET=<from-privy-dashboard>
    PUBLIC_CDN_URL=https://assets.hyperscape.club
    ```
    
    Optional variables:
    ```bash
    ADMIN_CODE=<your-admin-code>
    SAVE_INTERVAL=60
    ```
  </Step>
  
  <Step title="Configure GitHub Actions">
    Add Railway secrets to GitHub repository:
    
    1. Go to Settings → Secrets and variables → Actions
    2. Add `RAILWAY_TOKEN` (from Railway dashboard → Account → Tokens)
    3. Update workflow with your project/service/environment IDs
    
    Find IDs in Railway dashboard URL or via Railway CLI.
  </Step>
</Steps>

### Railway Configuration Files

**nixpacks.toml** - Build configuration:
```toml
[phases.setup]
aptPkgs = ["python3", "make", "g++", "pkg-config", "libcairo2-dev"]

[phases.install]
cmds = ["bun install"]

[phases.build]
cmds = [
  "bun run build:shared",
  "bun run build:server",
  "mkdir -p packages/server/world/assets/manifests"
]

[start]
cmd = "cd packages/server && bun dist/index.js"

[variables]
CI = "true"
SKIP_ASSETS = "true"
NODE_ENV = "production"
```

**railway.server.json** - Service configuration:
```json
{
  "build": {
    "builder": "NIXPACKS",
    "nixpacksConfigPath": "nixpacks.toml"
  },
  "deploy": {
    "startCommand": "cd packages/server && bun dist/index.js",
    "healthcheckPath": "/status",
    "healthcheckTimeout": 300,
    "restartPolicyType": "ON_FAILURE",
    "numReplicas": 1
  }
}
```

### Manifest Fetching

In production, the server fetches manifests from the CDN at startup instead of bundling them:

```typescript
// packages/server/src/startup/config.ts
await fetchManifestsFromCDN(CDN_URL, manifestsDir, NODE_ENV);
```

**Manifest Files Fetched:**
- Root manifests: `npcs.json`, `stores.json`, `world-areas.json`, etc.
- Items directory: `items/weapons.json`, `items/tools.json`, etc.
- Gathering: `gathering/woodcutting.json`, `gathering/mining.json`, etc.
- Recipes: `recipes/cooking.json`, `recipes/smithing.json`, etc.

Manifests are cached locally in `packages/server/world/assets/manifests/` and only re-fetched if content changes (ETag validation).

<Info>
In development, if local manifests exist, CDN fetching is skipped to allow working with local asset modifications.
</Info>

## Cloudflare Pages Deployment (Frontend)

Cloudflare Pages hosts the game client with automatic deployments via GitHub integration.

### Automated Deployment

Cloudflare Pages automatically deploys on every push to `main`:

1. **GitHub Integration**: Cloudflare Pages watches the repository
2. **Build Trigger**: Detects changes to `packages/client/**`
3. **Build Process**: Runs `bun run build` in `packages/client`
4. **Deploy**: Publishes to `hyperscape.pages.dev` and `hyperscape.club`

### Manual Setup

<Steps>
  <Step title="Connect repository">
    1. Go to Cloudflare Dashboard → Pages
    2. Create a new project
    3. Connect to GitHub repository: `HyperscapeAI/hyperscape`
    4. Select production branch: `main`
  </Step>
  
  <Step title="Configure build">
    - **Build command**: `cd packages/client && bun install && bun run build`
    - **Build output directory**: `packages/client/dist`
    - **Root directory**: `/` (monorepo root)
    - **Node version**: 22
  </Step>
  
  <Step title="Set environment variables">
    Add in Pages dashboard → Settings → Environment variables:
    
    ```bash
    PUBLIC_PRIVY_APP_ID=<from-privy-dashboard>
    PUBLIC_API_URL=https://hyperscape-production.up.railway.app
    PUBLIC_WS_URL=wss://hyperscape-production.up.railway.app/ws
    PUBLIC_CDN_URL=https://assets.hyperscape.club
    PUBLIC_APP_URL=https://hyperscape.club
    ```
  </Step>
  
  <Step title="Configure custom domain">
    1. Add custom domain: `hyperscape.club`
    2. Add DNS records as instructed by Cloudflare
    3. Enable automatic HTTPS
  </Step>
</Steps>

### Preview Deployments

Cloudflare Pages creates preview deployments for every pull request:

- **URL Pattern**: `https://<branch>-<hash>.hyperscape.pages.dev`
- **CORS**: Server automatically allows `*.hyperscape.pages.dev` origins
- **Environment**: Uses production environment variables

### Build Configuration

The client uses Vite with environment variable injection:

```typescript
// packages/client/vite.config.ts
export default defineConfig({
  envPrefix: 'PUBLIC_',  // Expose PUBLIC_* vars to client
  build: {
    outDir: 'dist',
    sourcemap: true,
    rollupOptions: {
      output: {
        manualChunks: {
          'three': ['three'],
          'react': ['react', 'react-dom']
        }
      }
    }
  }
});
```

<Warning>
After changing environment variables in Cloudflare Pages, trigger a new deployment for changes to take effect.
</Warning>

## Database Setup

Railway PostgreSQL is automatically configured when you add the database service.

### Railway PostgreSQL (Recommended)

<Steps>
  <Step title="Add database service">
    In your Railway project:
    1. Click "New" → "Database" → "PostgreSQL"
    2. Railway automatically sets `DATABASE_URL` environment variable
    3. Database is ready immediately
  </Step>

  <Step title="Run migrations">
    Migrations run automatically on server startup. To run manually:
    
    ```bash
    cd packages/server
    bunx drizzle-kit push      # Apply schema changes
    bunx drizzle-kit migrate   # Run pending migrations
    ```
  </Step>
</Steps>

### Alternative: Neon PostgreSQL

For serverless PostgreSQL with better free tier:

1. Create database at [neon.tech](https://neon.tech)
2. Copy connection string
3. Set as `DATABASE_URL` in Railway environment variables

## CDN & Assets Setup

### Cloudflare R2 (Production)

Hyperscape uses Cloudflare R2 for asset storage with global CDN distribution.

<Steps>
  <Step title="Create R2 bucket">
    1. Go to Cloudflare dashboard → R2
    2. Create bucket named `hyperscape-assets`
    3. Enable public access
  </Step>

  <Step title="Upload assets">
    Use the sync script to upload assets:
    
    ```bash
    # Set Cloudflare credentials
    export CLOUDFLARE_ACCOUNT_ID=your-account-id
    export CLOUDFLARE_API_TOKEN=your-api-token
    
    # Upload assets to R2
    bun run sync:r2
    ```
  </Step>

  <Step title="Configure custom domain">
    1. In R2 bucket settings, add custom domain: `assets.hyperscape.club`
    2. Cloudflare auto-configures DNS and SSL
    3. Set `PUBLIC_CDN_URL=https://assets.hyperscape.club` in both server and client
  </Step>
</Steps>

### Local CDN (Development)

For local development, use the Docker CDN:

```bash
bun run cdn:up    # Start nginx CDN container
bun run cdn:down  # Stop CDN container
```

## Cloudflare R2 Asset CDN

Cloudflare R2 hosts all game assets (3D models, textures, audio, manifests) with global edge caching.

### Automated Asset Deployment

Assets are automatically uploaded to R2 via GitHub Actions:

```yaml
# .github/workflows/deploy-cloudflare.yml
name: Deploy Assets to Cloudflare R2
on:
  push:
    branches: [main]
    paths:
      - 'packages/server/world/assets/manifests/**'
      - 'assets/**'
```

**Upload Process:**
1. Detects changes to manifests or assets
2. Uploads manifests to `manifests/` prefix
3. Uploads 3D models, audio, textures to root
4. Sets proper MIME types and cache headers

### Manual R2 Setup

<Steps>
  <Step title="Create R2 bucket">
    1. Go to Cloudflare Dashboard → R2
    2. Create bucket: `hyperscape-assets`
    3. Enable public access
  </Step>
  
  <Step title="Configure custom domain">
    1. Add custom domain: `assets.hyperscape.club`
    2. Point to R2 bucket
    3. Enable caching rules
  </Step>
  
  <Step title="Upload assets">
    Use Wrangler CLI to upload assets:
    
    ```bash
    # Install Wrangler
    npm install -g wrangler
    
    # Upload manifests
    wrangler r2 object put hyperscape-assets/manifests/npcs.json \
      --file=packages/server/world/assets/manifests/npcs.json \
      --content-type=application/json
    
    # Upload models (if using local assets)
    wrangler r2 object put hyperscape-assets/models/goblin/goblin.vrm \
      --file=assets/models/goblin/goblin.vrm \
      --content-type=model/gltf-binary
    ```
  </Step>
  
  <Step title="Configure GitHub Actions">
    Add Cloudflare secrets to GitHub repository:
    
    1. Go to Settings → Secrets and variables → Actions
    2. Add `CLOUDFLARE_API_TOKEN` (from Cloudflare → API Tokens)
    3. Workflow will automatically upload on manifest changes
  </Step>
</Steps>

### Cache Configuration

R2 assets use aggressive caching for performance:

| Asset Type | Cache-Control | Max Age |
|------------|---------------|---------|
| Models (.glb, .vrm) | `public, max-age=31536000, immutable` | 1 year |
| Audio (.mp3, .ogg) | `public, max-age=31536000, immutable` | 1 year |
| Textures (.png, .jpg) | `public, max-age=31536000, immutable` | 1 year |
| Manifests (.json) | `public, max-age=300, must-revalidate` | 5 minutes |
| WASM (.wasm) | `public, max-age=3600` | 1 hour |

Manifests use shorter cache times to allow content updates without cache invalidation.

### Local CDN (Development)

For local development, use the included Docker CDN:

```bash
bun run cdn:up          # Start CDN container
bun run cdn:down        # Stop CDN container
bun run cdn:restart     # Force restart
```

This starts an nginx container serving assets from `packages/server/world/assets/` at `http://localhost:8080`.

## CORS Configuration

The server automatically allows requests from production and development origins:

**Production Domains:**
- `https://hyperscape.club` (main site)
- `https://www.hyperscape.club` (www subdomain)
- `https://hyperscape.pages.dev` (Cloudflare Pages)
- `https://hyperscape-production.up.railway.app` (Railway backend)

**Development Patterns:**
- `http://localhost:<any-port>` (local development)
- `https://*.hyperscape.pages.dev` (preview deployments)
- `https://*.up.railway.app` (Railway preview environments)

**Configuration** (`packages/server/src/startup/http-server.ts`):
```typescript
const allowedOrigins = [
  "https://hyperscape.club",
  "https://www.hyperscape.club",
  "https://hyperscape.pages.dev",
  "http://hyperscape.pages.dev",  // HTTP fallback
  /^https?:\/\/localhost:\d+$/,
  /^https?:\/\/.+\.hyperscape\.pages\.dev$/,
  /^https:\/\/.+\.up\.railway\.app$/,
];
```

<Info>
The server automatically adds `PUBLIC_APP_URL` from environment variables to the CORS allowlist if set.
</Info>

## Production Checklist

### Infrastructure
- [ ] Railway project created and connected to GitHub
- [ ] Cloudflare Pages project created and connected to GitHub
- [ ] Cloudflare R2 bucket created for assets
- [ ] PostgreSQL database provisioned (Railway or Neon)
- [ ] Custom domains configured (hyperscape.club, assets.hyperscape.club)
- [ ] SSL/TLS enabled (automatic with Cloudflare)

### Environment Variables
- [ ] Server: `DATABASE_URL`, `JWT_SECRET`, `PRIVY_APP_ID`, `PRIVY_APP_SECRET`
- [ ] Server: `PUBLIC_CDN_URL` pointing to R2 bucket
- [ ] Client: `PUBLIC_PRIVY_APP_ID` matching server
- [ ] Client: `PUBLIC_API_URL` and `PUBLIC_WS_URL` pointing to Railway
- [ ] Client: `PUBLIC_CDN_URL` pointing to R2 bucket

### GitHub Actions
- [ ] `RAILWAY_TOKEN` secret configured
- [ ] `CLOUDFLARE_API_TOKEN` secret configured
- [ ] Railway project/service/environment IDs updated in workflow
- [ ] Cloudflare account ID updated in workflow

### Security
- [ ] `ADMIN_CODE` set to prevent unauthorized admin access
- [ ] JWT secret generated with `openssl rand -base64 32`
- [ ] Privy app configured with production domains
- [ ] Rate limiting enabled (`DISABLE_RATE_LIMIT` not set)

### Verification
- [ ] Server health check responds at `/status`
- [ ] WebSocket connection succeeds
- [ ] Assets load from CDN
- [ ] Manifests fetch successfully at startup
- [ ] Database migrations applied
- [ ] Authentication works with Privy
