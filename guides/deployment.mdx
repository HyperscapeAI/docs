## Deployment Overview

Hyperscape uses a split deployment architecture optimized for scalability and performance:

- **Frontend**: Cloudflare Pages (hyperscape.club)
- **Game Server**: Railway (hyperscape-production.up.railway.app)
- **Database**: PostgreSQL via Railway or Neon
- **Assets/CDN**: Cloudflare R2 (assets.hyperscape.club)

This architecture separates static content (frontend) from dynamic game logic (server) and leverages CDN edge caching for assets.

### Production URLs

| Component | URL | Purpose |
|-----------|-----|---------|
| Frontend | https://hyperscape.club | Client application (Cloudflare Pages) |
| Game Server | https://hyperscape-production.up.railway.app | WebSocket + HTTP API (Railway) |
| Assets CDN | https://assets.hyperscape.club | Game assets (Cloudflare R2) |

### Architecture Benefits

- **Global CDN**: Assets served from edge locations worldwide
- **Auto-scaling**: Railway handles server scaling automatically
- **Zero-downtime deploys**: Cloudflare Pages atomic deployments
- **Cost-effective**: R2 has no egress fees

</Warning>

## Railway Deployment (Game Server)

Railway hosts the game server with automatic deployments from GitHub.

### Automated Deployment

The repository includes a GitHub Actions workflow that automatically deploys to Railway on every push to `main`:

```yaml
# .github/workflows/deploy-railway.yml
# Triggers on changes to server, shared, or client packages
```

**What happens on push:**
1. GitHub Actions triggers Railway deployment via GraphQL API
2. Railway builds using Nixpacks configuration
3. Builds shared package → server package → client package
4. Copies client build to server's `public/` directory
5. Fetches manifests from CDN at startup
6. Deploys to production with health checks

### Manual Railway Setup

<Steps>
  <Step title="Create Railway project">
    1. Go to [railway.app](https://railway.app)
    2. Create new project from GitHub repo
    3. Select `HyperscapeAI/hyperscape`
  </Step>
  
  <Step title="Configure build settings">
    Railway uses `nixpacks.toml` and `railway.server.json` for configuration:
    
    - **Builder**: Nixpacks (auto-detected)
    - **Start command**: `cd packages/server && bun dist/index.js`
    - **Health check**: `/status` endpoint
    - **Watch patterns**: `packages/shared/**`, `packages/server/**`, `packages/client/**`
  </Step>
  
  <Step title="Add PostgreSQL database">
    1. In Railway dashboard, click "New" → "Database" → "PostgreSQL"
    2. Railway automatically sets `DATABASE_URL` environment variable
    3. No manual configuration needed
  </Step>
  
  <Step title="Set environment variables">
    Required variables:
    ```bash
    PRIVY_APP_ID=your-app-id
    PRIVY_APP_SECRET=your-app-secret
    PUBLIC_CDN_URL=https://assets.hyperscape.club
    JWT_SECRET=your-random-secret-32-chars
    NODE_ENV=production
    ```
    
    Optional variables:
    ```bash
    ADMIN_CODE=your-admin-code
    LIVEKIT_API_KEY=your-livekit-key
    LIVEKIT_API_SECRET=your-livekit-secret
    ```
  </Step>
  
  <Step title="Deploy">
    Push to `main` branch or click "Deploy" in Railway dashboard.
    
    Monitor deployment:
    - Build logs show package compilation
    - Health check validates `/status` endpoint
    - WebSocket connections tested automatically
  </Step>
</Steps>

### Railway Configuration Files

**nixpacks.toml** - Build configuration:
```toml
[phases.setup]
aptPkgs = ["python3", "make", "g++", "pkg-config", "libcairo2-dev"]

[phases.build]
cmds = [
  "bun run build:shared",
  "bun run build:server",
  "mkdir -p packages/server/world/assets/manifests"
]

[start]
cmd = "cd packages/server && bun dist/index.js"

[variables]
CI = "true"
SKIP_ASSETS = "true"
NODE_ENV = "production"
```

**railway.server.json** - Service configuration:
```json
{
  "build": {
    "builder": "NIXPACKS",
    "nixpacksConfigPath": "nixpacks.toml"
  },
  "deploy": {
    "startCommand": "cd packages/server && bun dist/index.js",
    "healthcheckPath": "/status",
    "restartPolicyType": "ON_FAILURE"
  }
}
```

### Troubleshooting Railway Deployments

**Build fails with "lockfile frozen" error:**
```bash
# Regenerate lockfile locally
bun install
git add bun.lock
git commit -m "chore: update bun.lock"
git push
```

**Frontend not loading (404 on index.html):**
- Check build logs for client build step
- Verify `cp -r dist/* public/` command succeeded
- Check `/debug/public` endpoint to see directory contents

**WebSocket connection fails:**
- Verify `PUBLIC_WS_URL` in client points to Railway domain
- Check CORS allowlist includes your frontend domain
- Ensure Railway exposes WebSocket port (default: 5555)

## Database Setup

### Neon PostgreSQL

1. Create database at [neon.tech](https://neon.tech)
2. Copy connection string
3. Set as `DATABASE_URL` in server environment

### Migrations

```bash
cd packages/server
bunx drizzle-kit push      # Apply schema
bunx drizzle-kit migrate   # Run migrations
```

## CDN Setup

### Option 1: Self-Hosted

Use the included Docker CDN:

```bash
bun run cdn:up
```

Configure `PUBLIC_CDN_URL` to point to your CDN host.

### Option 2: Cloud Storage

Upload assets to S3, R2, or similar:

1. Build assets: `bun run assets:optimize`
2. Upload `packages/server/world/assets/`
3. Set `PUBLIC_CDN_URL` to bucket URL
