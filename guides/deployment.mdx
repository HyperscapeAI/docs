## Deployment Overview

Hyperscape uses a split deployment model:

- **Server**: Railway, Fly.io, or Docker host
- **Client**: Vercel, Netlify, or static hosting
- **Database**: PostgreSQL (Neon recommended)
- **Assets**: CDN or object storage

## Environment Variables

### Server Production

```bash
# Required
DATABASE_URL=postgresql://...
JWT_SECRET=your-secret-key
PRIVY_APP_ID=your-app-id
PRIVY_APP_SECRET=your-app-secret

# Optional
PORT=5555
PUBLIC_CDN_URL=https://cdn.example.com
LIVEKIT_API_KEY=...
LIVEKIT_API_SECRET=...
```

### Client Production

```bash
PUBLIC_PRIVY_APP_ID=your-app-id
PUBLIC_API_URL=https://api.hyperscape.lol
PUBLIC_WS_URL=wss://api.hyperscape.lol
PUBLIC_CDN_URL=https://cdn.hyperscape.lol
```

<Warning>
  `PUBLIC_PRIVY_APP_ID` must match between client and server.
</Warning>

## Railway Deployment

Railway deployment is automated via GitHub Actions and uses Nixpacks for building.

<Steps>
  <Step title="Create Railway project">
    Connect your GitHub repository to Railway.
  </Step>
  
  <Step title="Configure build">
    Railway automatically detects the build configuration from `nixpacks.toml`:
    
    ```toml
    [phases.setup]
    nixPkgs = ['bun']
    
    [phases.build]
    cmds = [
      'bun install --frozen-lockfile',
      'bun run build:shared',
      'bun run build:client',
      'bun run build:server'
    ]
    
    [start]
    cmd = 'cd packages/server && bun run start:railway'
    ```
  </Step>
  
  <Step title="Add PostgreSQL">
    Add PostgreSQL service from Railway marketplace. Railway will automatically set `DATABASE_URL`.
  </Step>
  
  <Step title="Set environment variables">
    Add all required server environment variables:
    
    ```bash
    DATABASE_URL=postgresql://...  # Auto-set by Railway PostgreSQL
    JWT_SECRET=your-secret-key
    PRIVY_APP_ID=your-app-id
    PRIVY_APP_SECRET=your-app-secret
    PUBLIC_CDN_URL=https://d20g7vd4m53hpb.cloudfront.net
    NODE_ENV=production
    ```
  </Step>
</Steps>

### Railway-Specific Features

**CDN Manifest Fetching:**

In production, the server fetches game manifests from the CDN at startup instead of bundling them:

```typescript
// From packages/server/src/startup/http-server.ts
async function fetchManifestsFromCDN(manifestsDir: string): Promise<void> {
  // Downloads manifests from PUBLIC_CDN_URL at server startup
  // Skipped in development if local manifests exist
}
```

**Benefits:**
- Smaller deployment size (no bundled assets)
- Faster deployments
- Assets served from CDN with proper caching
- Manifests can be updated without redeploying server

**Frontend Serving:**

The Railway deployment serves both the game server and the built client from a single service:

```typescript
// Static file serving for built client
fastify.register(fastifyStatic, {
  root: path.join(process.cwd(), 'public'),
  prefix: '/',
});

// Fallback to index.html for SPA routing
fastify.setNotFoundHandler((req, reply) => {
  reply.sendFile('index.html');
});
```

### GitHub Actions Workflow

Deployment is triggered automatically on push to main:

```yaml
# .github/workflows/deploy-railway.yml
name: Deploy to Railway
on:
  push:
    branches: [main]
    paths:
      - 'packages/server/**'
      - 'packages/shared/**'
      - 'packages/client/**'
```

The workflow:
1. Checks out code
2. Triggers Railway deployment via GraphQL API
3. Railway builds using Nixpacks
4. Client is built and copied to `packages/server/public/`
5. Server fetches manifests from CDN at startup
6. Service starts and serves both API and static files

<Info>
The Railway deployment serves both the game server (WebSocket + API) and the built client (static files) from a single service on port 5555.
</Info>

1. Create database at [neon.tech](https://neon.tech)
2. Copy connection string
3. Set as `DATABASE_URL` in server environment

```bash
cd packages/server
bunx drizzle-kit push      # Apply schema

```

## CDN Setup

### Production CDN

In production, the server automatically fetches manifests from the CDN at startup:

```typescript
// Server fetches manifests from CDN on boot
const CDN_URL = "https://d20g7vd4m53hpb.cloudfront.net";
await fetchManifestsFromCDN(CDN_URL, manifestsDir);
```

<Info>
  The server only needs manifest JSON files in production. 3D models, textures, and audio are served directly from the CDN to clients.
</Info>

### Local Development CDN

Use the included Docker CDN for local development:

```bash
bun run cdn:up
```

This serves assets from the local `assets/` directory cloned via Git LFS.

### Custom CDN Setup

To use your own CDN:

1. Upload assets to S3, R2, or similar
2. Set `PUBLIC_CDN_URL` environment variable
3. Ensure manifests are accessible at `${CDN_URL}/manifests/`
