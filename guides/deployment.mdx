## Deployment Overview

Hyperscape uses a **split deployment model** optimized for modern cloud platforms:

- **Frontend**: Cloudflare Pages (`hyperscape.club`)
- **Server/API**: Railway (`hyperscape-production.up.railway.app`)
- **Database**: PostgreSQL (Neon recommended)
- **Assets/CDN**: Cloudflare R2 (`assets.hyperscape.club`)

### Why Split Deployment?

- **Frontend on Cloudflare Pages**: Global CDN, instant deploys, free SSL
- **Server on Railway**: WebSocket support, persistent connections, easy scaling
- **Assets on R2**: Low-cost object storage, global distribution
- **Database on Neon**: Serverless PostgreSQL, automatic scaling, generous free tier

## Environment Variables

### Server Production (Railway)

```bash
# Required
DATABASE_URL=postgresql://...              # Auto-set by Railway PostgreSQL
JWT_SECRET=your-secret-key                 # Generate with: openssl rand -base64 32
PUBLIC_PRIVY_APP_ID=your-app-id           # From Privy dashboard
PRIVY_APP_SECRET=your-app-secret          # From Privy dashboard

# Production URLs
PUBLIC_CDN_URL=https://assets.hyperscape.club
PUBLIC_API_URL=https://hyperscape-production.up.railway.app
PUBLIC_WS_URL=wss://hyperscape-production.up.railway.app/ws

# Optional
PORT=5555                                  # Railway auto-assigns if not set
ADMIN_CODE=your-admin-code                # For /admin command
LIVEKIT_API_KEY=...                       # Voice chat (optional)
LIVEKIT_API_SECRET=...
LIVEKIT_URL=wss://...
```

### Client Production (Cloudflare Pages)

```bash
PUBLIC_PRIVY_APP_ID=your-app-id
PUBLIC_API_URL=https://hyperscape-production.up.railway.app
PUBLIC_WS_URL=wss://hyperscape-production.up.railway.app
PUBLIC_CDN_URL=https://cdn.hyperscape.club
```

<Warning>
  `PUBLIC_PRIVY_APP_ID` must match between client and server for authentication to work.
</Warning>

### CORS Configuration

The server is configured to accept requests from multiple origins:

**Production Domains**:
- `https://hyperscape.club` (main site)
- `https://www.hyperscape.club` (www subdomain)
- `https://hyperscape.pages.dev` (Cloudflare Pages)
- `https://hyperscape-production.up.railway.app` (Railway backend)

**Dynamic Patterns**:
- `https://*.hyperscape.pages.dev` (Cloudflare preview deployments)
- `http://localhost:*` (any localhost port for development)

CORS is configured in `packages/server/src/startup/http-server.ts` with credentials support enabled.

## Railway Deployment

Hyperscape uses **automated Railway deployment** via GitHub Actions. The server is deployed to Railway while the client is deployed to Cloudflare Pages.

### Architecture

- **Frontend**: Cloudflare Pages (`hyperscape.club`, `hyperscape.pages.dev`)
- **Backend/API**: Railway (`hyperscape-production.up.railway.app`)
- **Assets/CDN**: Cloudflare R2 (manifests fetched at server startup)
- **Database**: Railway PostgreSQL

### Automated Deployment

Deployments trigger automatically on push to `main` when these paths change:

```yaml
# .github/workflows/deploy-railway.yml
paths:
  - 'packages/shared/**'
  - 'packages/client/**'
  - 'packages/server/**'
  - 'packages/plugin-hyperscape/**'
  - 'package.json'
  - 'bun.lock'
  - 'nixpacks.toml'
  - 'railway.server.json'
  - 'Dockerfile.server'
```

The workflow uses Railway's GraphQL API to trigger redeployments and monitor status.

### Build Configuration

Railway uses **Nixpacks** for builds (configured in `nixpacks.toml`):

```toml
[phases.setup]
aptPkgs = ["python3", "make", "g++", "pkg-config", "libcairo2-dev", ...]

[phases.install]
cmds = ["bun install"]

[phases.build]
cmds = [
  "bun run build:shared",
  "bun run build:server",
  "bun run build:client",
  "cp -r packages/client/dist/* packages/server/public/"
]

[start]
cmd = "cd packages/server && bun dist/index.js"
```

**Key Features**:
- Builds shared, server, AND client packages
- Copies client build to `packages/server/public/` for unified deployment
- Skips asset download in CI (manifests fetched from CDN at runtime)
- Uses Bun for fast builds and runtime

### Manual Railway Setup

<Steps>
  <Step title="Create Railway project">
    1. Go to [railway.app](https://railway.app)
    2. Click "New Project" → "Deploy from GitHub repo"
    3. Select your Hyperscape fork
    4. Railway will auto-detect the Nixpacks configuration
  </Step>
  
  <Step title="Configure service">
    - Builder: Nixpacks (auto-detected from `nixpacks.toml`)
    - Root directory: `/` (monorepo root)
    - Start command: `cd packages/server && bun dist/index.js`
  </Step>
  
  <Step title="Add PostgreSQL">
    Add PostgreSQL service from Railway marketplace. Connection string is automatically set as `DATABASE_URL`.
  </Step>
  
  <Step title="Set environment variables">
    Required variables:
    ```bash
    JWT_SECRET=your-random-secret
    PRIVY_APP_ID=your-privy-app-id
    PRIVY_APP_SECRET=your-privy-app-secret
    PUBLIC_CDN_URL=https://cdn.hyperscape.club
    NODE_ENV=production
    ```
  </Step>

  <Step title="Configure GitHub Actions">
    Add Railway secrets to GitHub repository:
    - `RAILWAY_TOKEN` - API token from Railway dashboard
    
    Project IDs are in `.github/workflows/deploy-railway.yml`.
  </Step>
</Steps>

### Manifest Fetching

The server **fetches manifests from CDN at startup** instead of bundling them:

```typescript
// From packages/server/src/startup/config.ts
await fetchManifestsFromCDN(CDN_URL, manifestsDir, NODE_ENV);
```

**Behavior**:
- **Production**: Always fetches from CDN
- **Development**: Skips if local manifests exist (allows local asset development)
- **Fallback**: Uses existing local manifests if CDN fetch fails

This reduces deployment size and ensures manifests stay in sync with CDN assets.

## Vercel Client Deployment

<Steps>
  <Step title="Connect repository">
    Connect your GitHub repository to Cloudflare Pages.
  </Step>
  
  <Step title="Configure build">
    ```bash
    Build command: cd packages/client && bun install && bun run build
    Build output directory: packages/client/dist
    Root directory: (leave empty - monorepo)
    ```
  </Step>
  
  <Step title="Set environment variables">
    Add these in Cloudflare Pages dashboard → Settings → Environment variables:
    
    ```bash
    PUBLIC_PRIVY_APP_ID=<your-privy-app-id>
    PUBLIC_API_URL=https://hyperscape-production.up.railway.app
    PUBLIC_WS_URL=wss://hyperscape-production.up.railway.app/ws
    PUBLIC_CDN_URL=https://assets.hyperscape.club
    PUBLIC_APP_URL=https://hyperscape.club
    ```
  </Step>
  
  <Step title="Configure custom domain">
    Add custom domain in Cloudflare Pages → Custom domains.
    
    **Production**: `hyperscape.club`
    **Preview**: `*.hyperscape.pages.dev` (automatic)
  </Step>
</Steps>

## Database Setup

Railway PostgreSQL is automatically configured when you add the database service.

### Railway PostgreSQL (Recommended)

<Steps>
  <Step title="Add database service">
    In your Railway project:
    1. Click "New" → "Database" → "PostgreSQL"
    2. Railway automatically sets `DATABASE_URL` environment variable
    3. Database is ready immediately
  </Step>

  <Step title="Run migrations">
    Migrations run automatically on server startup. To run manually:
    
    ```bash
    cd packages/server
    bunx drizzle-kit push      # Apply schema changes
    bunx drizzle-kit migrate   # Run pending migrations
    ```
  </Step>
</Steps>

### Alternative: Neon PostgreSQL

For serverless PostgreSQL with better free tier:

1. Create database at [neon.tech](https://neon.tech)
2. Copy connection string
3. Set as `DATABASE_URL` in Railway environment variables

## CDN & Assets Setup

### Cloudflare R2 (Production)

Hyperscape uses Cloudflare R2 for asset storage with global CDN distribution.

<Steps>
  <Step title="Create R2 bucket">
    1. Go to Cloudflare dashboard → R2
    2. Create bucket named `hyperscape-assets`
    3. Enable public access
  </Step>

  <Step title="Upload assets">
    Use the sync script to upload assets:
    
    ```bash
    # Set Cloudflare credentials
    export CLOUDFLARE_ACCOUNT_ID=your-account-id
    export CLOUDFLARE_API_TOKEN=your-api-token
    
    # Upload assets to R2
    bun run sync:r2
    ```
  </Step>

  <Step title="Configure custom domain">
    1. In R2 bucket settings, add custom domain: `assets.hyperscape.club`
    2. Cloudflare auto-configures DNS and SSL
    3. Set `PUBLIC_CDN_URL=https://assets.hyperscape.club` in both server and client
  </Step>
</Steps>

### Local CDN (Development)

For local development, use the Docker CDN:

```bash
bun run cdn:up    # Start nginx CDN container
bun run cdn:down  # Stop CDN container
```

The CDN serves assets from `packages/server/world/assets/` at `http://localhost:8080`.

## GitHub Actions CI/CD

The repository includes automated deployment workflows.

### Automatic Railway Deployment

Pushes to `main` automatically trigger Railway deployments:

```yaml
# .github/workflows/deploy-railway.yml
on:
  push:
    branches: [main]
    paths:
      - 'packages/shared/**'
      - 'packages/server/**'
      - 'packages/client/**'
```

**Required GitHub Secrets**:
- `RAILWAY_TOKEN` - Generate at railway.app/account/tokens

**Environment Variables** (in workflow):
- `RAILWAY_PROJECT_ID` - From Railway project settings
- `RAILWAY_SERVICE_ID` - From Railway service settings
- `RAILWAY_ENVIRONMENT_ID` - From Railway environment settings

### Cloudflare Pages Deployment

Cloudflare Pages automatically deploys on push to `main`:

- **Production**: Deploys from `main` branch
- **Preview**: Deploys from pull requests
- **URL**: `https://hyperscape.pages.dev` (and custom domain)
