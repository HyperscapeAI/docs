## Deployment Overview

Hyperscape uses a **split deployment architecture** for optimal performance and scalability:

```
┌─────────────────────────────────────────────────────────────┐
│                    Production Architecture                   │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  Frontend (Cloudflare Pages)                                │
│  ├─ hyperscape.club                                         │
│  ├─ www.hyperscape.club                                     │
│  └─ *.hyperscape.pages.dev (preview deployments)           │
│                                                              │
│  Server/API (Railway)                                       │
│  ├─ hyperscape-production.up.railway.app                   │
│  ├─ WebSocket: wss://hyperscape-production.up.railway.app/ws│
│  └─ REST API: /api/*                                        │
│                                                              │
│  Assets/CDN (Cloudflare R2)                                 │
│  ├─ assets.hyperscape.club                                  │
│  ├─ Models, textures, audio (3D assets)                    │
│  └─ Manifests (game data JSON files)                       │
│                                                              │
│  Database (Railway PostgreSQL)                              │
│  └─ Managed PostgreSQL instance                            │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### Deployment Model

| Component | Platform | Purpose |
|-----------|----------|---------|
| **Frontend** | Cloudflare Pages | Static React app with global CDN |
| **Server** | Railway | Game server (Fastify + WebSockets) |
| **Database** | Railway PostgreSQL | Player data, inventory, world state |
| **Assets** | Cloudflare R2 | 3D models, audio, textures, manifests |

### Why Split Deployment?

- **Performance**: Frontend served from Cloudflare's global CDN (low latency)
- **Scalability**: Server can scale independently from frontend
- **Cost**: Static hosting is cheaper than running servers for static files
- **Flexibility**: Update frontend without server redeployment and vice versa
- **Assets**: Large game assets (models, audio) served from CDN, not bundled with frontend


<Warning>
  `PUBLIC_PRIVY_APP_ID` must match between client and server.
</Warning>

## Railway Deployment

Hyperscape uses Railway for production server deployment with automated GitHub Actions integration.

### Architecture

**Production Deployment Model:**
- **Frontend**: Cloudflare Pages (hyperscape.club, www.hyperscape.club)
- **Server/API**: Railway (hyperscape-production.up.railway.app)
- **Assets/CDN**: Cloudflare R2
- **Database**: Railway PostgreSQL

### Automated Deployment

The repository includes a GitHub Actions workflow that automatically deploys to Railway on every push to `main`:

```yaml
# .github/workflows/deploy-railway.yml
name: Deploy to Railway
on:
  push:
    branches: [main]
    paths:
      - 'packages/shared/**'
      - 'packages/client/**'
      - 'packages/server/**'
      - 'packages/plugin-hyperscape/**'
      - 'package.json'
      - 'bun.lock'
      - 'nixpacks.toml'
      - 'railway.server.json'
      - 'Dockerfile.server'
```

**Deployment triggers only when relevant files change** to avoid unnecessary builds.

### Build Configuration

Railway uses **Nixpacks** for building the server. Configuration is in `nixpacks.toml`:

```toml
[phases.setup]
# Install system dependencies for native modules
aptPkgs = [
  "python3", "make", "g++", "pkg-config",
  "libcairo2-dev", "libpango1.0-dev", "libjpeg-dev",
  "libgif-dev", "librsvg2-dev", "ca-certificates"
]

[phases.install]
cmds = ["bun install"]

[phases.build]
cmds = [
  "bun run build:shared",
  "bun run build:server",
  "mkdir -p packages/server/world/assets/manifests"
]

[start]
cmd = "cd packages/server && bun dist/index.js"

[variables]
CI = "true"
SKIP_ASSETS = "true"  # Assets served from CDN
NODE_ENV = "production"
```

<Info>
The build skips asset download (`SKIP_ASSETS=true`) because assets are served from Cloudflare R2 CDN. Manifests are fetched from the CDN at server startup.
</Info>

### Manual Setup

<Steps>
  <Step title="Create Railway project">
    1. Connect your GitHub repository to Railway
    2. Select the `main` branch
    3. Railway will detect `railway.server.json` automatically
  </Step>
  
  <Step title="Configure build">
    Railway automatically uses the configuration from `railway.server.json`:
    - Builder: `NIXPACKS`
    - Config: `nixpacks.toml`
    - Start command: `cd packages/server && bun dist/index.js`
    - Health check: `/status` endpoint
  </Step>
  
  <Step title="Add PostgreSQL">
    Add PostgreSQL service from Railway marketplace. Railway will automatically set `DATABASE_URL` environment variable.
  </Step>
  
  <Step title="Set environment variables">
    Configure required environment variables in Railway dashboard:
    
    ```bash
    # Required
    PRIVY_APP_ID=your-privy-app-id
    PRIVY_APP_SECRET=your-privy-app-secret
    JWT_SECRET=your-jwt-secret
    PUBLIC_CDN_URL=https://assets.hyperscape.club
    
    # Optional
    ADMIN_CODE=your-admin-code
    LIVEKIT_API_KEY=your-livekit-key
    LIVEKIT_API_SECRET=your-livekit-secret
    ```
  </Step>
  
  <Step title="Configure GitHub Actions (optional)">
    For automated deployments, add Railway token to GitHub secrets:
    
    1. Generate Railway API token in Railway dashboard
    2. Add `RAILWAY_TOKEN` to GitHub repository secrets
    3. Update project/service/environment IDs in `.github/workflows/deploy-railway.yml`
  </Step>
</Steps>

### Deployment Verification

After deployment, verify the server is running:

```bash
# Check health endpoint
curl https://hyperscape-production.up.railway.app/status

# Check manifest availability
curl https://hyperscape-production.up.railway.app/manifests/items.json

# Test WebSocket connection
wscat -c wss://hyperscape-production.up.railway.app/ws
```

### Frontend Build Integration

The Railway build includes the frontend client:

1. Client is built during the build phase: `bun run build:client`
2. Client `dist/` is copied to `packages/server/public/`
3. Server serves the frontend at `/` with SPA routing
4. Frontend assets are served from `/assets/` (built client assets)
5. Game assets are served from CDN (models, audio, textures)

<Warning>
The server serves BOTH the frontend application AND the game API. The frontend is built into the server's `public/` directory during deployment.
</Warning>

### Manifest Fetching

On server startup, manifests are fetched from the CDN and cached locally:

```typescript
// From packages/server/src/startup/config.ts
const MANIFEST_FILES = [
  "items.json", "npcs.json", "resources.json", "tools.json",
  "biomes.json", "world-areas.json", "stores.json", "music.json",
  "vegetation.json", "buildings.json"
];

// Fetched from: PUBLIC_CDN_URL/manifests/*.json
// Cached to: packages/server/world/assets/manifests/
```

This ensures the server always has the latest game data without requiring redeployment.

## Cloudflare Pages Deployment (Recommended)

Hyperscape's production frontend is deployed to Cloudflare Pages for global CDN distribution.

### Automated Deployment

The repository includes a GitHub Actions workflow for Cloudflare Pages:

```yaml
# .github/workflows/deploy-cloudflare.yml
name: Deploy to Cloudflare Pages
on:
  push:
    branches: [main]
    paths:
      - 'packages/client/**'
      - 'packages/shared/**'
```

<Steps>
  <Step title="Connect GitHub repository">
    1. Go to Cloudflare Pages dashboard
    2. Create new project from GitHub
    3. Select `HyperscapeAI/hyperscape` repository
    4. Configure build settings (see next step)
  </Step>
  
  <Step title="Configure build settings">
    ```
    Build command: cd packages/client && bun run build
    Build output directory: packages/client/dist
    Root directory: (leave empty - monorepo)
    ```
  </Step>
  
  <Step title="Set environment variables">
    Add in Cloudflare Pages → Settings → Environment variables:
    
    ```bash
    PUBLIC_PRIVY_APP_ID=your-privy-app-id
    PUBLIC_API_URL=https://hyperscape-production.up.railway.app
    PUBLIC_WS_URL=wss://hyperscape-production.up.railway.app/ws
    PUBLIC_CDN_URL=https://assets.hyperscape.club
    PUBLIC_APP_URL=https://hyperscape.club
    ```
  </Step>
  
  <Step title="Configure custom domain">
    1. Add custom domain: `hyperscape.club`
    2. Add www subdomain: `www.hyperscape.club`
    3. Configure DNS records as instructed by Cloudflare
  </Step>
</Steps>

<Info>
Cloudflare Pages automatically creates preview deployments for pull requests at `*.hyperscape.pages.dev`. These are included in the server's CORS allowlist.
</Info>

## Database Setup

### Neon PostgreSQL

1. Create database at [neon.tech](https://neon.tech)
2. Copy connection string
3. Set as `DATABASE_URL` in server environment

### Migrations

```bash
cd packages/server
bunx drizzle-kit push      # Apply schema
bunx drizzle-kit migrate   # Run migrations
```

## CDN Setup

### Option 1: Self-Hosted

Use the included Docker CDN:

```bash
bun run cdn:up
```

Configure `PUBLIC_CDN_URL` to point to your CDN host.

### Option 2: Cloud Storage

Upload assets to S3, R2, or similar:

1. Build assets: `bun run assets:optimize`
2. Upload `packages/server/world/assets/`
3. Set `PUBLIC_CDN_URL` to bucket URL
