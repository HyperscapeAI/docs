## Overview

Hyperscape uses manifest-driven design where game content is defined in TypeScript data files rather than hardcoded in logic. This enables content creation without modifying game systems.

## Design Philosophy

### Separation of Concerns

| Layer | Responsibility |
|-------|----------------|
| **Manifests** | Content definitions (what exists) |
| **Systems** | Game logic (how things work) |
| **Entities** | Runtime instances |

### Benefits

- **Content creators** can add items, NPCs, areas without deep coding
- **Designers** iterate quickly on balance
- **Developers** focus on systems, not data
- **Modders** can extend content easily

## Manifest Files

All manifests are in `world/assets/manifests/`:

| File | Content |
|------|---------|
| `npcs.ts` | Mobs and NPCs |
| `items.ts` | Equipment, resources, consumables |
| `banks-stores.ts` | Shop inventories |
| `world-areas.ts` | Zones and regions |
| `world-structure.ts` | World layout |
| `avatars.ts` | Character models |
| `playerEmotes.ts` | Emote animations |
| `equipment-requirements.json` | Level requirements for gear |
| `equipment-stats.json` | Stat bonuses for equipment |
| `stations.json` | Crafting stations (anvils, furnaces, ranges, banks) |

## Manifest Structure

### NPCs (`npcs.json`)

NPC data is loaded from JSON manifests at runtime by DataManager:

```json
[
  {
    "id": "goblin",
    "name": "Goblin",
    "description": "A weak goblin creature",
    "category": "mob",
    "faction": "monster",
    "stats": {
      "level": 2,
      "health": 5,
      "attack": 1,
      "strength": 1,
      "defense": 1
    },
    "combat": {
      "attackable": true,
      "aggressive": true,
      "retaliates": true,
      "aggroRange": 4,
      "combatRange": 1,
      "attackSpeedTicks": 4,
      "respawnTicks": 35
    },
    "drops": {
      "defaultDrop": { "enabled": true, "itemId": "bones", "quantity": 1 },
      "common": [{ "itemId": "coins", "minQuantity": 5, "maxQuantity": 15, "chance": 1.0, "rarity": "common" }]
    },
    "appearance": { "modelPath": "asset://models/goblin/goblin.vrm", "scale": 0.75 }
  }
]
```

<Info>
  NPC definitions are in `world/assets/manifests/npcs.json`, not hardcoded in TypeScript.
</Info>

### Items (`items/`)

Items are now organized by type in separate files:

**items/weapons.json** - Combat weapons with tier-based requirements:
```json
[
  {
    "id": "bronze_sword",
    "name": "Bronze Sword",
    "type": "weapon",
    "tier": "bronze",
    "equipSlot": "weapon",
    "weaponType": "SWORD",
    "attackType": "MELEE",
    "attackSpeed": 4,
    "attackRange": 1,
    "bonuses": { "attack": 4, "strength": 3 }
  }
]
```

**items/tools.json** - Skilling tools with priority system:
```json
[
  {
    "id": "bronze_hatchet",
    "name": "Bronze Hatchet",
    "type": "tool",
    "tier": "bronze",
    "tool": {
      "skill": "woodcutting",
      "priority": 1
    }
  }
]
```

**items/resources.json** - Raw materials (ores, logs, bars, raw fish)

**items/food.json** - Cooked consumables with `healAmount`

**items/misc.json** - Currency, burnt food, junk items

### Tier Requirements (`tier-requirements.json`)

Centralized tier-based level requirements (OSRS-accurate):

```json
{
  "melee": {
    "bronze": { "attack": 1, "defence": 1 },
    "steel": { "attack": 5, "defence": 5 },
    "mithril": { "attack": 20, "defence": 20 },
    "rune": { "attack": 40, "defence": 40 }
  },
  "tools": {
    "bronze": { "attack": 1, "woodcutting": 1, "mining": 1 },
    "steel": { "attack": 5, "woodcutting": 6, "mining": 6 }
  }
}
```

### Gathering Resources (`gathering/`)

**gathering/woodcutting.json** - Trees and log yields:
```json
{
  "trees": [
    {
      "id": "tree_normal",
      "name": "Tree",
      "type": "tree",
      "harvestSkill": "woodcutting",
      "toolRequired": "bronze_hatchet",
      "levelRequired": 1,
      "baseCycleTicks": 4,
      "depleteChance": 0.125,
      "respawnTicks": 80,
      "harvestYield": [
        { "itemId": "logs", "quantity": 1, "chance": 1.0, "xpAmount": 25 }
      ]
    }
  ]
}
```

**gathering/mining.json** - Rocks and ore yields

**gathering/fishing.json** - Fishing spots with OSRS-accurate catch rates

### Recipes (`recipes/`)

**recipes/smelting.json** - Furnace recipes (ores → bars):
```json
{
  "recipes": [
    {
      "output": "bronze_bar",
      "inputs": [
        { "item": "copper_ore", "amount": 1 },
        { "item": "tin_ore", "amount": 1 }
      ],
      "level": 1,
      "xp": 6.2,
      "ticks": 4,
      "successRate": 1.0
    }
  ]
}
```

### Stations (`stations.json`)

Defines crafting stations and interactive objects in the world:

```json
{
  "stations": [
    {
      "type": "anvil",
      "name": "Anvil",
      "model": "asset://models/anvil/anvil.glb",
      "modelScale": 0.5,
      "modelYOffset": 0.2,
      "examine": "An anvil for smithing metal bars into weapons and tools."
    },
    {
      "type": "furnace",
      "name": "Furnace",
      "model": "asset://models/furnace/furnace.glb",
      "modelScale": 1.5,
      "modelYOffset": 1.0,
      "examine": "A furnace for smelting ores into metal bars."
    }
  ]
}
```

Station types include:
- **Anvil** — Smith bars into equipment
- **Furnace** — Smelt ores into bars
- **Range** — Cook food with reduced burn chance
- **Bank** — Store items

## Data Providers

### DataManager

The `DataManager` class in `packages/shared/src/data/DataManager.ts` loads all manifests from JSON files and populates runtime data structures:

```typescript
import { dataManager } from '@hyperscape/shared';

// Initialize (loads all manifests)
await dataManager.initialize();

// Access loaded data via global maps
import { ITEMS, ALL_NPCS } from '@hyperscape/shared';

const item = ITEMS.get("bronze_sword");
const npc = ALL_NPCS.get("goblin");
```

### Manifest Loading

DataManager supports two loading modes:

1. **Filesystem** (server-side): Loads from `packages/server/world/assets/manifests/`
2. **CDN** (client-side): Fetches from `http://localhost:8080/assets/manifests/`

The loading is **atomic** for directory-based manifests - all required files must exist or it falls back to legacy single-file format.

## Adding Content

### Step 1: Edit JSON Manifest

Add your content to the appropriate JSON file in `packages/server/world/assets/manifests/`.

Add your content to the appropriate manifest file in `world/assets/manifests/`:

- **NPCs**: `npcs.json`
- **Weapons**: `items/weapons.json`
- **Tools**: `items/tools.json`
- **Resources**: `items/resources.json`
- **Food**: `items/food.json`
- **Gathering**: `gathering/woodcutting.json`, `gathering/mining.json`, `gathering/fishing.json`
- **Recipes**: `recipes/smelting.json`, `recipes/smithing.json`, `recipes/cooking.json`

### Step 2: Restart Server

The DataManager loads manifests on startup:

```bash
bun run dev
```

### Step 3: Verify

Check the game to ensure content appears correctly. The smithing interface should show your new recipe.

## Validation

### JSON Manifest Validation

JSON manifests are validated at runtime by DataManager:

- **Schema validation**: Required fields checked on load
- **Duplicate detection**: Duplicate item IDs cause errors
- **Atomic loading**: All required files must exist (e.g., all 5 item category files)
- **Fallback support**: Falls back to legacy single-file format if directory loading fails

### TypeScript Data File Validation

TypeScript data files get compile-time validation:

- **Schema validation**: Invalid fields logged as warnings
- **Cross-references**: Missing itemId/npcId references caught
- **Required fields**: Missing required fields cause errors
- **Type safety**: TypeScript types ensure correct usage in code

<Warning>
  Invalid manifests will cause runtime errors with descriptive messages. Check server logs for validation warnings.
</Warning>

## Best Practices

1. **Use descriptive IDs**: `bronze_sword` not `sword1`
2. **Follow naming conventions**: snake_case for IDs
3. **Organize by category**: Use the directory structure (items/, recipes/, gathering/)
4. **Test after changes**: Verify in-game before committing
5. **Keep data flat**: Avoid deep nesting in manifest structures
6. **Use tier system**: Leverage TierDataProvider for equipment requirements instead of hardcoding
7. **Validate JSON**: Use a JSON validator before committing to catch syntax errors

## Manifest Loading Order

DataManager loads manifests in this order:

1. **Tier requirements** (`tier-requirements.json`) - Needed for item normalization
2. **Items** (`items/` directory or `items.json` fallback)
3. **NPCs** (`npcs.json`)
4. **Gathering resources** (`gathering/*.json`)
5. **Recipe manifests** (`recipes/*.json`)
6. **Skill unlocks** (`skill-unlocks.json`)
7. **Stations** (`stations.json`)
8. **World areas** (`world-areas.json`)
9. **Stores** (`stores.json`)

This order ensures dependencies are loaded before dependent data (e.g., tier requirements before items).
