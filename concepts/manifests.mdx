## Overview

Hyperscape uses manifest-driven design where game content is defined in TypeScript data files rather than hardcoded in logic. This enables content creation without modifying game systems.

## Design Philosophy

### Separation of Concerns

| Layer | Responsibility |
|-------|----------------|
| **Manifests** | Content definitions (what exists) |
| **Systems** | Game logic (how things work) |
| **Entities** | Runtime instances |

### Benefits

- **Content creators** can add items, NPCs, areas without deep coding
- **Designers** iterate quickly on balance
- **Developers** focus on systems, not data
- **Modders** can extend content easily

## Manifest Files

Manifests are stored in `packages/server/world/assets/manifests/` as JSON files and loaded at runtime by `DataManager`.

### Core Manifests

| File | Content |
|------|---------|
| `npcs.json` | Mobs and NPCs |
| `avatars.json` | Character models |
| `banks-stores.json` | Shop inventories |
| `world-areas.json` | Zones and regions |
| `tier-requirements.json` | Tier-based level requirements |
| `skill-unlocks.json` | Skill unlock descriptions |

### Item Manifests (Directory-Based)

Items are organized by category in `items/` directory:

| File | Content |
|------|---------|
| `items/weapons.json` | Swords, axes, bows, etc. |
| `items/tools.json` | Hatchets, pickaxes, fishing rods |
| `items/resources.json` | Ores, bars, logs, fish |
| `items/food.json` | Cooked food, raw food, burnt food |
| `items/misc.json` | Coins, junk items, quest items |

<Info>
  The directory-based structure is **atomic** - all category files must exist or the system falls back to legacy `items.json`.
</Info>

### Recipe Manifests (Directory-Based)

Processing skill recipes in `recipes/` directory:

| File | Content |
|------|---------|
| `recipes/cooking.json` | Raw → cooked food recipes |
| `recipes/firemaking.json` | Log burning data |
| `recipes/smelting.json` | Ore → bar recipes |
| `recipes/smithing.json` | Bar → equipment recipes |

### Gathering Manifests (Directory-Based)

Resource gathering data in `gathering/` directory:

| File | Content |
|------|---------|
| `gathering/woodcutting.json` | Tree types and locations |
| `gathering/mining.json` | Rock types and ore data |
| `gathering/fishing.json` | Fishing spot types |

### Legacy Manifests (Backwards Compatibility)

| File | Content | Status |
|------|---------|--------|
| `items.json` | All items (single file) | Fallback if `items/` missing |
| `resources.json` | All resources (single file) | Fallback if `gathering/` missing |
| `tools.json` | Tool definitions | Deprecated - tools now in `items/tools.json` |

## Manifest Structure

### NPCs (`npcs.ts`)

NPC data is loaded from JSON manifests at runtime by DataManager:

```typescript
// From packages/shared/src/data/npcs.ts (lines 1-21)
/**
 * NPC Database
 *
 * ALL NPC data is loaded from JSON manifests at runtime by DataManager.
 * This keeps NPC definitions data-driven and separate from code.
 *
 * Available 3D model types (in /assets/world/forge/):
 * - goblin/goblin_rigged.glb     → Used for goblins
 * - thug/thug_rigged.glb         → Used for bandits
 * - human/human_rigged.glb       → Used for guards, knights, warriors
 * - troll/troll_rigged.glb       → Used for hobgoblins
 * - imp/imp_rigged.glb           → Used for dark warriors
 *
 * To add new NPCs:
 * 1. Add entry to world/assets/manifests/npcs.json
 * 2. Use one of the existing modelPath types above
 * 3. OR generate new model in 3D Asset Forge
 * 4. Restart server to reload manifests
 */

// NPC Database - Populated at runtime from JSON manifests
export const ALL_NPCS: Map<string, NPCData> = new Map();
```

<Info>
  NPC definitions are in `world/assets/manifests/npcs.json`, not hardcoded in TypeScript.
</Info>

### Items (`items.ts`)

Items are loaded from JSON manifests similar to NPCs:

```typescript
// From packages/shared/src/data/items.ts (lines 1-25)
/**
 * Item Database
 *
 * Items are loaded from world/assets/manifests/items.json by DataManager.
 * This file provides the empty Map that gets populated at runtime.
 *
 * To add new items:
 * 1. Add entries to world/assets/manifests/items.json
 * 2. Generate 3D models in 3D Asset Forge (optional)
 * 3. Restart the server to reload manifests
 */

// Item Database - Populated by DataManager
export const ITEMS: Map<string, Item> = new Map();

// Helper functions
export function getItem(itemId: string): Item | null {
  return ITEMS.get(itemId) || null;
}

export function getItemsByType(type: ItemType): Item[] {
  return Array.from(ITEMS.values()).filter((item) => item.type === type);
}

// Shop items available for purchase
export const SHOP_ITEMS = ["bronze_hatchet", "fishing_rod", "tinderbox", "arrows"];
```

## DataManager

The `DataManager` class in `packages/shared/src/data/DataManager.ts` loads and provides access to all manifests:

```typescript
import { dataManager } from '@hyperscape/shared';

// Initialize (loads all manifests)
await dataManager.initialize();

// Access loaded data via global maps
import { ITEMS, ALL_NPCS } from '@hyperscape/shared';

const item = ITEMS.get("bronze_sword");
const npc = ALL_NPCS.get("goblin");
```

### Manifest Loading

DataManager supports two loading modes:

1. **Filesystem** (server-side): Loads from `packages/server/world/assets/manifests/`
2. **CDN** (client-side): Fetches from `http://localhost:8080/assets/manifests/`

The loading is **atomic** for directory-based manifests - all required files must exist or it falls back to legacy single-file format.

## Adding Content

### Step 1: Edit JSON Manifest

Add your content to the appropriate JSON file in `packages/server/world/assets/manifests/`.

For items, add to the correct category file in `items/` directory:
- Weapons → `items/weapons.json`
- Tools → `items/tools.json`
- Resources → `items/resources.json`
- Food → `items/food.json`
- Misc → `items/misc.json`

For recipes, add to the appropriate file in `recipes/` directory:
- Cooking → `recipes/cooking.json`
- Firemaking → `recipes/firemaking.json`
- Smelting → `recipes/smelting.json`
- Smithing → `recipes/smithing.json`

### Step 2: Restart Server

The server must restart to reload manifests:

```bash
# Stop server (Ctrl+C)
# Restart
bun run dev
```

<Info>
  Manifest changes require a server restart. Hot reload does not apply to JSON data files.
</Info>

### Step 3: Verify

Check the game to ensure content appears correctly.

## Validation

Manifests are TypeScript files, so you get:

- **Type checking**: Invalid fields caught at compile time
- **Autocomplete**: IDE suggestions for valid properties
- **Required fields**: Missing fields cause build errors
- **References**: TypeScript catches invalid itemId/npcId references

<Warning>
  Invalid manifests will cause TypeScript compilation to fail with descriptive errors.
</Warning>

## Best Practices

1. **Use descriptive IDs**: `bronze_sword` not `sword1`
2. **Follow naming conventions**: snake_case for IDs
3. **Document unusual values**: Add comments for non-obvious choices
4. **Test after changes**: Verify in-game before committing
5. **Keep data flat**: Avoid deep nesting in manifest structures
