## Overview

Hyperscape uses manifest-driven design where game content is defined in TypeScript data files rather than hardcoded in logic. This enables content creation without modifying game systems.

## Design Philosophy

### Separation of Concerns

| Layer | Responsibility |
|-------|----------------|
| **Manifests** | Content definitions (what exists) |
| **Systems** | Game logic (how things work) |
| **Entities** | Runtime instances |

### Benefits

- **Content creators** can add items, NPCs, areas without deep coding
- **Designers** iterate quickly on balance
- **Developers** focus on systems, not data
- **Modders** can extend content easily

## Manifest Files

All manifests are in `world/assets/manifests/`:

| File | Content |
|------|---------|
| `npcs.json` | Mobs and NPCs |
| `items/weapons.json` | Combat weapons |
| `items/tools.json` | Skilling tools (hatchets, pickaxes, fishing rods) |
| `items/resources.json` | Gathered materials (ores, logs, bars, raw fish) |
| `items/food.json` | Cooked consumables |
| `items/misc.json` | Currency, burnt food, junk items |
| `gathering/woodcutting.json` | Trees and log yields |
| `gathering/mining.json` | Rocks and ore yields |
| `gathering/fishing.json` | Fishing spots and catch rates |
| `recipes/smelting.json` | Furnace: ores → bars |
| `recipes/smithing.json` | Anvil: bars → equipment |
| `recipes/cooking.json` | Fire/range: raw → cooked food |
| `recipes/firemaking.json` | Logs → fires (XP data) |
| `tier-requirements.json` | Centralized tier-based level requirements |
| `skill-unlocks.json` | Skill progression milestones |
| `stores.json` | Shop inventories |
| `world-areas.json` | Zones and regions |
| `biomes.json` | Biome definitions with vegetation layers |
| `vegetation.json` | Procedural vegetation assets |
| `music.json` | Music tracks |

## Manifest Structure

### NPCs (`npcs.json`)

NPC data is loaded from JSON manifests at runtime by DataManager:

```json
[
  {
    "id": "goblin",
    "name": "Goblin",
    "description": "A weak goblin creature",
    "category": "mob",
    "faction": "monster",
    "stats": {
      "level": 2,
      "health": 5,
      "attack": 1,
      "strength": 1,
      "defense": 1
    },
    "combat": {
      "attackable": true,
      "aggressive": true,
      "retaliates": true,
      "aggroRange": 4,
      "combatRange": 1,
      "attackSpeedTicks": 4,
      "respawnTicks": 35
    },
    "drops": {
      "defaultDrop": { "enabled": true, "itemId": "bones", "quantity": 1 },
      "common": [{ "itemId": "coins", "minQuantity": 5, "maxQuantity": 15, "chance": 1.0, "rarity": "common" }]
    },
    "appearance": { "modelPath": "asset://models/goblin/goblin.vrm", "scale": 0.75 }
  }
]
```

<Info>
  NPC definitions are in `world/assets/manifests/npcs.json`, not hardcoded in TypeScript.
</Info>

### Items (`items/`)

Items are now organized by type in separate files:

**items/weapons.json** - Combat weapons with tier-based requirements:
```json
[
  {
    "id": "bronze_sword",
    "name": "Bronze Sword",
    "type": "weapon",
    "tier": "bronze",
    "equipSlot": "weapon",
    "weaponType": "SWORD",
    "attackType": "MELEE",
    "attackSpeed": 4,
    "attackRange": 1,
    "bonuses": { "attack": 4, "strength": 3 }
  }
]
```

**items/tools.json** - Skilling tools with priority system:
```json
[
  {
    "id": "bronze_hatchet",
    "name": "Bronze Hatchet",
    "type": "tool",
    "tier": "bronze",
    "tool": {
      "skill": "woodcutting",
      "priority": 1
    }
  }
]
```

**items/resources.json** - Raw materials (ores, logs, bars, raw fish)

**items/food.json** - Cooked consumables with `healAmount`

**items/misc.json** - Currency, burnt food, junk items

### Tier Requirements (`tier-requirements.json`)

Centralized tier-based level requirements (OSRS-accurate):

```json
{
  "melee": {
    "bronze": { "attack": 1, "defence": 1 },
    "steel": { "attack": 5, "defence": 5 },
    "mithril": { "attack": 20, "defence": 20 },
    "rune": { "attack": 40, "defence": 40 }
  },
  "tools": {
    "bronze": { "attack": 1, "woodcutting": 1, "mining": 1 },
    "steel": { "attack": 5, "woodcutting": 6, "mining": 6 }
  }
}
```

### Gathering Resources (`gathering/`)

**gathering/woodcutting.json** - Trees and log yields:
```json
{
  "trees": [
    {
      "id": "tree_normal",
      "name": "Tree",
      "type": "tree",
      "harvestSkill": "woodcutting",
      "toolRequired": "bronze_hatchet",
      "levelRequired": 1,
      "baseCycleTicks": 4,
      "depleteChance": 0.125,
      "respawnTicks": 80,
      "harvestYield": [
        { "itemId": "logs", "quantity": 1, "chance": 1.0, "xpAmount": 25 }
      ]
    }
  ]
}
```

**gathering/mining.json** - Rocks and ore yields

**gathering/fishing.json** - Fishing spots with OSRS-accurate catch rates

### Recipes (`recipes/`)

**recipes/smelting.json** - Furnace recipes (ores → bars):
```json
{
  "recipes": [
    {
      "output": "bronze_bar",
      "inputs": [
        { "item": "copper_ore", "amount": 1 },
        { "item": "tin_ore", "amount": 1 }
      ],
      "level": 1,
      "xp": 6.2,
      "ticks": 4,
      "successRate": 1.0
    }
  ]
}
```

**recipes/smithing.json** - Anvil recipes (bars → equipment)

**recipes/cooking.json** - Cooking recipes with burn mechanics

**recipes/firemaking.json** - Log burning data

## DataManager

The `DataManager` class in `packages/shared/src/data/DataManager.ts` loads and provides access to all manifests:

```typescript
import { DataManager } from '@hyperscape/shared';

const npc = DataManager.getNPC("goblin");
const item = DataManager.getItem("bronze_sword");
const area = DataManager.getArea("mistwood_valley");
```

## Adding Content

### Step 1: Edit Manifest

Add your content to the appropriate manifest file in `world/assets/manifests/`:

- **NPCs**: `npcs.json`
- **Weapons**: `items/weapons.json`
- **Tools**: `items/tools.json`
- **Resources**: `items/resources.json`
- **Food**: `items/food.json`
- **Gathering**: `gathering/woodcutting.json`, `gathering/mining.json`, `gathering/fishing.json`
- **Recipes**: `recipes/smelting.json`, `recipes/smithing.json`, `recipes/cooking.json`

### Step 2: Restart Server

The DataManager loads manifests on startup:

```bash
bun run dev
```

### Step 3: Verify

Check the game to ensure content appears correctly.

## Validation

Manifests are TypeScript files, so you get:

- **Type checking**: Invalid fields caught at compile time
- **Autocomplete**: IDE suggestions for valid properties
- **Required fields**: Missing fields cause build errors
- **References**: TypeScript catches invalid itemId/npcId references

<Warning>
  Invalid manifests will cause TypeScript compilation to fail with descriptive errors.
</Warning>

## Best Practices

1. **Use descriptive IDs**: `bronze_sword` not `sword1`
2. **Follow naming conventions**: snake_case for IDs
3. **Document unusual values**: Add comments for non-obvious choices
4. **Test after changes**: Verify in-game before committing
5. **Keep data flat**: Avoid deep nesting in manifest structures
