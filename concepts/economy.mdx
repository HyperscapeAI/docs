## Overview

Hyperscape features a player-driven economy with banking, shops, loot drops, and item trading.

## Currency

**Coins** are the universal currency:

- Dropped by all mobs
- Used to purchase from shops
- Stackable in inventory

## Inventory

### Configuration

```typescript
// From packages/shared/src/constants/GameConstants.ts
export const INVENTORY_CONSTANTS = {
  MAX_INVENTORY_SLOTS: 28,
  MAX_BANK_SLOTS: 100,
  MAX_STACK_SIZE: 1000,
```

### Capacity

- **28 slots** in active inventory (RuneScape-style)
- **100 slots** in bank storage
- **1000 max stack** for stackable items
- Items must be managed carefully
- Stackable items (coins, arrows) share a slot

### Item Properties

| Property | Description |
|----------|-------------|
| **Stackable** | Multiple units per slot (up to 1000) |
| **Tradeable** | Can be exchanged |
| **Weight** | Affects run energy |
| **Requirements** | Level gates for use |

## Banking

### Features

- Unlimited storage slots
- Accessible at bank locations in starter towns
- Each bank is independent (no shared storage)

### Operations

- **Deposit**: Move items from inventory to bank
- **Withdraw**: Move items from bank to inventory
- **Organize**: Drag to rearrange

<Info>
  Banks are safe storage—items cannot be lost from banks.
</Info>

## Loot Drops

### Mob Drops

All mobs drop loot on death:

| Mob Tier | Typical Drops |
|----------|---------------|
| Level 1 | Coins, bronze equipment (rare) |
| Level 2 | More coins, steel equipment (uncommon) |
| Level 3 | Substantial coins, mithril equipment (uncommon) |

### Drop Tables

Drop tables are defined in NPC manifests and calculated at runtime:

```typescript
// From packages/shared/src/data/npcs.ts (lines 107-149)
export function calculateNPCDrops(
  npcId: string,
): Array<{ itemId: string; quantity: number }> {
  const npc = getNPCById(npcId);
  if (!npc) return [];

  const drops: Array<{ itemId: string; quantity: number }> = [];

  // Add default drop if enabled
  if (npc.drops.defaultDrop.enabled) {
    drops.push({
      itemId: npc.drops.defaultDrop.itemId,
      quantity: npc.drops.defaultDrop.quantity,
    });
  }

  // Roll for drop tiers: always, common, uncommon, rare, veryRare
  npc.drops.always.forEach(processDrop);
  npc.drops.common.forEach(processDrop);
  npc.drops.uncommon.forEach(processDrop);
  npc.drops.rare.forEach(processDrop);
  npc.drops.veryRare.forEach(processDrop);

  return drops;
}
```

<Info>
  Drop tables are defined in `world/assets/manifests/npcs.json` and loaded by DataManager.
</Info>

## Player Trading

### Overview

Player-to-player trading uses an OSRS-accurate two-screen confirmation flow to prevent scams:

1. **Offer Screen**: Players add/remove items and accept
2. **Confirmation Screen**: Players review final trade and confirm
3. **Completion**: Items swapped atomically via database transaction

### Trading Flow

```mermaid
sequenceDiagram
    participant P1 as Player 1
    participant Server as TradingSystem
    participant P2 as Player 2
    
    P1->>Server: tradeRequest(targetPlayerId)
    Server->>P2: tradeIncoming (pink chat message)
    P2->>Server: tradeRequestRespond(accept: true)
    Server->>P1: tradeStarted
    Server->>P2: tradeStarted
    
    P1->>Server: tradeAddItem(slot, quantity)
    Server->>P1: tradeUpdated
    Server->>P2: tradeUpdated
    
    P1->>Server: tradeAccept
    P2->>Server: tradeAccept
    Server->>P1: tradeConfirmScreen
    Server->>P2: tradeConfirmScreen
    
    P1->>Server: tradeAccept (confirm)
    P2->>Server: tradeAccept (confirm)
    Server->>Server: Atomic item swap
    Server->>P1: tradeCompleted
    Server->>P2: tradeCompleted
```

### Trade UI Features

- **Click-Based Interaction**: Left-click to add 1, right-click for context menu
- **Context Menu Options**: Offer-1, Offer-5, Offer-10, Offer-X, Offer-All, Value, Examine
- **Anti-Scam Indicators**:
  - Red flashing exclamation when items removed
  - Wealth transfer indicator (green = gaining, red = losing)
  - Warning icon if value difference >50%
  - Partner's free inventory slots displayed
- **Proximity System**: Players automatically walk to target if out of range
- **Interface Blocking**: Can't trade while banking/shopping

### Security

- **Server-Authoritative**: All validation happens server-side
- **Atomic Swaps**: Database transactions prevent item duplication
- **Inventory Locks**: Prevent race conditions during swap
- **Tradeable Flag**: Items with `tradeable: false` cannot be traded
- **Proximity Validation**: Players must be adjacent (1 tile)
- **Interface Checks**: Blocks trading during bank/store/dialogue sessions

### Trade Session States

| State | Description |
|-------|-------------|
| `pending` | Trade request sent, awaiting response |
| `active` | Both players in offer screen |
| `confirming` | Both players in confirmation screen |
| `completed` | Trade successfully completed |
| `cancelled` | Trade cancelled by player or timeout |

### Timeouts

- **Request Timeout**: 5 minutes (auto-decline if not responded)
- **Active Trade Timeout**: 10 minutes (auto-cancel if inactive)
- **Cleanup Interval**: 60 seconds (removes expired sessions)

<Info>
Trading system code is in `packages/server/src/systems/TradingSystem/` and `packages/server/src/systems/ServerNetwork/handlers/trade/`.
</Info>
