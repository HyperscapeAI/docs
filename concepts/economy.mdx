## Overview

Hyperscape features a player-driven economy with banking, shops, loot drops, and item trading.

## Currency

**Coins** are the universal currency:

- Dropped by all mobs
- Used to purchase from shops
- Stackable in inventory

## Inventory

### Configuration


### Capacity

- **28 slots** in active inventory (RuneScape-style)
- **100 slots** in bank storage
- **1000 max stack** for stackable items
- Items must be managed carefully
- Stackable items (coins, arrows) share a slot

### Item Properties

| Property | Description |
|----------|-------------|
| **Stackable** | Multiple units per slot (up to 1000) |
| **Tradeable** | Can be exchanged |
| **Weight** | Affects run energy |
| **Requirements** | Level gates for use |

## Banking

### Features

- Unlimited storage slots
- Accessible at bank locations in starter towns
- Each bank is independent (no shared storage)

### Operations

- **Deposit**: Move items from inventory to bank
- **Withdraw**: Move items from bank to inventory
- **Organize**: Drag to rearrange

<Info>
  Banks are safe storage—items cannot be lost from banks.
</Info>

## Loot Drops

### Mob Drops

All mobs drop loot on death:

| Mob Tier | Typical Drops |
|----------|---------------|
| Level 1 | Coins, bronze equipment (rare) |
| Level 2 | More coins, steel equipment (uncommon) |
| Level 3 | Substantial coins, mithril equipment (uncommon) |

### Drop Tables

Drop tables are defined in NPC manifests and calculated at runtime:

```typescript
// From packages/shared/src/data/npcs.ts (lines 107-149)
export function calculateNPCDrops(
  npcId: string,
): Array<{ itemId: string; quantity: number }> {
  const npc = getNPCById(npcId);
  if (!npc) return [];

  const drops: Array<{ itemId: string; quantity: number }> = [];

  // Add default drop if enabled
  if (npc.drops.defaultDrop.enabled) {
    drops.push({
      itemId: npc.drops.defaultDrop.itemId,
      quantity: npc.drops.defaultDrop.quantity,
    });
  }

  // Roll for drop tiers: always, common, uncommon, rare, veryRare
  npc.drops.always.forEach(processDrop);
  npc.drops.common.forEach(processDrop);
  npc.drops.uncommon.forEach(processDrop);
  npc.drops.rare.forEach(processDrop);
  npc.drops.veryRare.forEach(processDrop);

  return drops;
}
```

<Info>
  Drop tables are defined in `world/assets/manifests/npcs.json` and loaded by DataManager.
</Info>

## Player Trading

### Trading System

Player-to-player trading with OSRS-accurate two-screen confirmation:

**Features:**
- **Two-Screen Confirmation**: Both players must accept on two separate screens
  - Screen 1: Offer items and review partner's offer
  - Screen 2: Final confirmation with wealth transfer indicator
  - Any change resets both players to screen 1
- **Wealth Transfer Indicator**: Visual warning for unbalanced trades
  - Shows net value difference with directional arrow
  - Color-coded: green (receiving), red (giving), gray (balanced)
- **Proximity Checks**: Players must be within 2 tiles to trade
  - Auto-walk to player when initiating trade from distance
  - Trade closes if players move too far apart
- **Interface Blocking**: Trading locks out other interfaces
  - Bank, store, dialogue automatically close when trade starts
  - Prevents item duplication exploits
- **Click-Based UI**: Improved interaction model
  - Click items to add/remove from trade offer
  - Click partner's items to examine
  - Quantity prompts for stackable items
  - Partner's free inventory slots displayed
- **Chat Integration**: Pink-colored trade request messages
  - \"[Player] wishes to trade with you.\" format
  - Clickable to accept trade request
- **Audit Logging**: All completed trades logged for security

**Implementation:**

```typescript
// From packages/server/src/systems/TradingSystem/
acceptance.ts     // Accept/decline logic
items.ts          // Add/remove items
request.ts        // Trade initiation with proximity checks
swap.ts           // Screen transitions
helpers.ts        // Shared utilities
types.ts          // Type definitions
```

**Security:**
- Transaction rollback on failure
- Inventory synchronization with proper event ordering
- Server-authoritative validation
- Distance checks on every action
