# February 2026 Changelog

This document summarizes all significant changes pushed to the main branch in February 2026, organized by category.

## Breaking Changes

### WebGPU-Only Rendering (Commit 47782ed, Feb 27 2026)

**BREAKING**: WebGPU is now REQUIRED. WebGL fallback has been completely removed.

**What Changed:**
- Removed all WebGL detection and fallback code from `RendererFactory.ts`
- Removed `isWebGLForced`, `isWebGLFallbackForced`, `isWebGLFallbackAllowed` functions
- Removed `isWebGLAvailable`, `isOffscreenCanvasAvailable`, `canTransferCanvas` functions
- Changed `UniversalRenderer` type to `WebGPURenderer` only
- `RendererBackend` type is now only `"webgpu"` (removed `"webgl"`)
- Removed `--disable-webgpu` and `forceWebGL` URL parameters from streaming
- Removed `DUEL_FORCE_WEBGL_FALLBACK` environment variable

**Why:**
- All materials use TSL (Three Shading Language) which ONLY works with WebGPU
- Post-processing effects use TSL-based node materials
- There is NO WebGL fallback path - the game simply won't render

**Browser Requirements:**
- Chrome 113+ (recommended)
- Edge 113+
- Safari 18+ (macOS 15+ only)
- Check compatibility: [webgpureport.org](https://webgpureport.org)

**Migration Guide:**
- Update browser to Chrome 113+ or Edge 113+
- Remove any `forceWebGL` or `--disable-webgpu` flags from configurations
- Server/streaming deployments must use Xorg or Xvfb with GPU access (no headless mode)

**Files Changed:**
- `packages/shared/src/utils/rendering/RendererFactory.ts`
- `packages/server/src/streaming/stream-to-rtmp.ts`
- `packages/server/ecosystem.config.cjs`
- `scripts/deploy-vast.sh`
- `CLAUDE.md`
- `AGENTS.md`

## Vast.ai Deployment & Streaming

### GPU Rendering Pipeline (Commits 263bfc5, 92ee48e, 47782ed, Feb 27 2026)

**Major architectural changes to GPU rendering for WebGPU support:**

**GPU Rendering Modes** (tried in order):
1. **Xorg with NVIDIA** (preferred):
   - Requires DRI/DRM device access (`/dev/dri/card0`)
   - Full hardware GPU acceleration
   - Best performance
   - Config: `/etc/X11/xorg-nvidia-headless.conf`
   - Options: `AllowEmptyInitialConfiguration`, `UseDisplayDevice=None`

2. **Xvfb with NVIDIA Vulkan** (fallback):
   - Virtual framebuffer for X11 protocol
   - Chrome uses NVIDIA GPU via ANGLE/Vulkan
   - CDP captures frames from Chrome's internal GPU rendering
   - Set `DUEL_CAPTURE_USE_XVFB=true` when active

3. **Failure Mode**:
   - If neither Xorg nor Xvfb can provide WebGPU, deployment FAILS
   - No soft fallback to headless mode (doesn't support WebGPU)
   - Explicit display accessibility verification required

**Environment Variables:**
```bash
DISPLAY=:99                                                    # X server display
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json      # Force NVIDIA Vulkan ICD
DUEL_CAPTURE_USE_XVFB=true/false                              # Dynamically set
GPU_RENDERING_MODE=xorg|xvfb-vulkan                           # Rendering mode indicator
STREAM_CAPTURE_HEADLESS=false                                 # Must be false for WebGPU
STREAM_CAPTURE_CHANNEL=chrome-dev                             # Use Chrome Dev
```

**Deployment Validation:**
- Script verifies NVIDIA GPU is accessible via `nvidia-smi`
- Checks Vulkan ICD availability via `vulkaninfo`
- Ensures display server (Xorg/Xvfb) is running via `xdpyinfo`
- Fails deployment if WebGPU cannot be initialized

**Files Changed:**
- `scripts/deploy-vast.sh` - Complete GPU setup logic
- `ecosystem.config.cjs` - Environment variable passthrough
- `AGENTS.md` - Deployment architecture documentation

### Audio Capture via PulseAudio (Commits 3b6f1ee, aab66b0, b9d2e41, Feb 26 2026)

**Feature**: Capture game music and sound effects in RTMP streams.

**Setup:**
- User-mode PulseAudio with `chrome_audio` virtual sink
- `XDG_RUNTIME_DIR=/tmp/pulse-runtime` for socket location
- FFmpeg captures from `chrome_audio.monitor` device
- Graceful fallback to silent audio if PulseAudio unavailable

**Audio Stability Improvements:**
- `thread_queue_size=1024` prevents buffer underruns
- `use_wallclock_as_timestamps=1` for real-time timing
- `aresample=async=1000:first_pts=0` recovers from audio drift (22ms threshold)
- Removed `-shortest` flag that caused audio dropouts during video buffering

**Configuration:**
```bash
STREAM_AUDIO_ENABLED=true
PULSE_AUDIO_DEVICE=chrome_audio.monitor
PULSE_SERVER=unix:/tmp/pulse-runtime/pulse/native
XDG_RUNTIME_DIR=/tmp/pulse-runtime
```

## Client & Build Fixes

### Vite Polyfills Fix (Commit e012ed2, Feb 26 2026)

**Problem:** Production builds failed with "Failed to resolve module specifier" errors for `vite-plugin-node-polyfills/shims/*` imports.

**Solution:** Add aliases to resolve shims to actual dist files:

```typescript
// vite.config.ts
resolve: {
  alias: {
    'vite-plugin-node-polyfills/shims/buffer': 'vite-plugin-node-polyfills/dist/shims/buffer',
    'vite-plugin-node-polyfills/shims/global': 'vite-plugin-node-polyfills/dist/shims/global',
    'vite-plugin-node-polyfills/shims/process': 'vite-plugin-node-polyfills/dist/shims/process',
  }
},
plugins: [
  nodePolyfills({
    protocolImports: false,  // Disable to avoid unresolved imports
  })
]
```

### Visual Testing Fix (Commit 205f964, Feb 27 2026)

**Problem:** WebGPU doesn't support `readPixels()` for pixel reading.

**Solution:** Use 2D canvas `drawImage()` for WebGPU pixel reading:

```typescript
// visualTesting.ts
// WebGPU: Use 2D canvas drawImage instead of readPixels
const canvas2d = document.createElement('canvas');
canvas2d.width = width;
canvas2d.height = height;
const ctx = canvas2d.getContext('2d');
ctx.drawImage(renderer.domElement, 0, 0);
const imageData = ctx.getImageData(0, 0, width, height);
```

## Migration Guide

### For Developers

1. **Update browser to Chrome 113+ or Edge 113+** (WebGPU required)
2. **Set JWT_SECRET in production** (now required)
3. **Set ADMIN_CODE in production** (recommended for security)
4. **Update MARKET_MINT** if using Solana markets (GOLD_MINT deprecated)
5. **Remove WebGL fallback code** from any custom implementations

### For Deployers

1. **Vast.ai instances must have NVIDIA GPU** with Vulkan support
2. **Configure stream keys** in GitHub secrets (Twitch, Kick, X)
3. **Set SOLANA_DEPLOYER_PRIVATE_KEY** for automated keypair setup
4. **Disable YouTube streaming** (set `YOUTUBE_STREAM_KEY=""`)
5. **Update KICK_RTMP_URL** to correct RTMPS endpoint

### For Users

1. **Update browser** to Chrome 113+, Edge 113+, or Safari 18+ (macOS 15+)
2. **Check WebGPU support** at [webgpureport.org](https://webgpureport.org)
3. **No action required** if already using supported browser
