## Overview

February 2026 brought major improvements to streaming infrastructure, AI agent stability, and deployment automation. This changelog covers 100+ commits with focus on production reliability.

## Streaming Infrastructure

### GPU Rendering Overhaul (Feb 27, 2026)

**Headless EGL Mode** (commit e51a332):
- Added headless EGL mode for containers without DRM/DRI access
- Auto-detect DRI devices and try Xorg if available
- Fall back to headless EGL if DRI unavailable
- Support `STREAM_CAPTURE_HEADLESS=new` for Chrome's new headless mode
- Support `STREAM_CAPTURE_USE_EGL=true` for EGL rendering

**Hardware GPU Required** (commit 30bdaf0):
- WebGPU requires hardware GPU rendering
- Xvfb software rendering too slow for streaming
- Fail fast if Xorg/GPU setup fails
- No software rendering fallback

**Robust Xorg/Xvfb Fallback** (commit 5fe4a18):
- Check if nvidia-smi works before attempting Xorg
- Verify X server responds with xdpyinfo before using it
- Add diagnostic logging for Xorg failures
- Properly set DUEL_CAPTURE_USE_XVFB based on outcome

**Xorg for NVIDIA GPU** (commit 263bfc5):
- Use Xorg instead of Xvfb for NVIDIA GPU rendering
- Xvfb is software framebuffer, cannot access physical GPU
- Force NVIDIA-only Vulkan ICD (VK_ICD_FILENAMES)
- Enable GPU rendering without physical display

**NVIDIA Hardware Vulkan** (commit 89b78e3):
- Force NVIDIA ICD via VK_ICD_FILENAMES
- Use vulkan ANGLE backend (hardware accelerated)
- Remove `--enable-unsafe-swiftshader` (not needed with hardware Vulkan)

### Audio Streaming (Feb 26, 2026)

**PulseAudio Integration** (commit 3b6f1ee):
- Install PulseAudio and create virtual sink (chrome_audio)
- Configure Chrome browser to use PulseAudio output
- Update FFmpeg to capture from PulseAudio monitor
- Add STREAM_AUDIO_ENABLED and PULSE_AUDIO_DEVICE config options
- Improve FFmpeg buffering with 'film' tune and 4x buffer multiplier
- Add input buffering with thread_queue_size for stability
- Fix Kick RTMP URL default to working endpoint

**PulseAudio Permissions** (commit aab66b0):
- Add root user to pulse-access group for system-wide access
- Create /run/pulse with proper permissions (777) for FFmpeg access
- Export PULSE_SERVER env var in both deploy script and PM2 config
- Add pactl check before using PulseAudio to gracefully fall back
- Verify chrome_audio sink exists before attempting capture

**Audio Stability** (commit b9d2e41):
- Add thread_queue_size=1024 for audio input to prevent buffer underruns
- Add use_wallclock_as_timestamps=1 for PulseAudio real-time timing
- Add aresample=async=1000:first_pts=0 filter to recover from audio drift
- Increase video thread_queue_size from 512 to 1024 for better a/v sync
- Remove -shortest flag that caused audio dropouts during video buffering

### Streaming Quality (Feb 26, 2026)

**RTMP Buffering Improvements** (commit 4c630f12):
- Changed default x264 tune from 'zerolatency' to 'film'
  - Allows B-frames for better compression
  - Better lookahead for smoother bitrate
  - Set STREAM_LOW_LATENCY=true to restore old behavior
- Increased buffer multiplier from 2x to 4x bitrate (18000k bufsize)
- Added FLV flags for RTMP stability (flvflags=no_duration_filesize)
- Improved input buffering with thread_queue_size and genpts+discardcorrupt

**Stream Timing Changes** (commit 7f1b1fd):
- Changed canonical platform from YouTube to Twitch (lower latency)
- Changed public delay from 12000ms to 0ms for live betting
- Configured Twitch, Kick, and X streaming destinations
- Removed YouTube (not needed)

**Stream Health Monitoring** (commit 14a1e1b):
- Increased CDP stall threshold from 2 to 4 intervals (120s)
- Added soft CDP recovery: restart screencast without browser/FFmpeg teardown
- Increased FFmpeg MAX_RESTART_ATTEMPTS from 5 to 8
- Added resetRestartAttempts() for recovery counter reset
- Increased CAPTURE_RECOVERY_MAX_FAILURES default from 2 to 4
