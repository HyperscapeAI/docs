## Overview

Hyperscape implements an OSRS-style quest system with multi-stage progression tracking, quest points, and comprehensive rewards. The system is **manifest-driven** (quests defined in JSON), **server-authoritative** (all logic runs server-side), and **security-hardened** (HMAC validation, rate limiting, audit logging).

Quest code lives in:
- `packages/shared/src/systems/shared/progression/QuestSystem.ts` - Core quest logic
- `packages/server/src/database/repositories/QuestRepository.ts` - Database persistence
- `packages/server/src/systems/ServerNetwork/handlers/quest.ts` - Network handlers
- `packages/client/src/game/panels/QuestJournal.tsx` - Quest UI

## Quest Stages

### Stage Types

| Type | Description | Required Fields |
|------|-------------|-----------------|
| `dialogue` | Talk to an NPC | `description` |
| `kill` | Kill specific mob type | `target`, `count` |
| `gather` | Gather items | `target` (itemId), `count` |
| `interact` | Interact with entities | `target` (entityType), `count` |

### Stage Progression

Stages progress automatically when objectives are met:
- **Kill stages**: Track kills via `NPC_DIED` events with HMAC validation
- **Gather stages**: Track via `INVENTORY_ITEM_ADDED` events
- **Interact stages**: Track via entity-specific events (FIRE_CREATED, COOKING_COMPLETED, etc.)
- **Dialogue stages**: Progress via dialogue system effects

## Quest Flow

### 1. Quest Request

Player talks to quest NPC → NPC dialogue includes `startQuest` effect:

```typescript
// In NPC dialogue node
{
  "id": "start_quest",
  "text": "Will you help me?",
  "responses": [
    {
      "text": "Yes, I'll help!",
      "next": "quest_accepted",
      "effect": "startQuest:goblin_slayer"
    }
  ]
}
```

Server emits `QUEST_START_CONFIRM` event → Client shows quest acceptance screen.

### 2. Quest Acceptance

Player clicks "Accept Quest" → Client sends `questAccept` packet:

```typescript
world.network.send("questAccept", { questId: "goblin_slayer" });
```

Server validates requirements and starts quest:
- Checks prerequisite quests completed
- Validates skill level requirements
- Verifies required items in inventory
- Creates `quest_progress` database row
- Grants starting items (if defined in `onStart`)
- Emits `QUEST_STARTED` event

### 3. Quest Progression

As player completes objectives, progress is tracked:

```typescript
// Kill tracking (server-side)
world.on(EventType.NPC_DIED, (data) => {
  // Validate kill token (HMAC)
  if (!validateKillToken(mobId, killedBy, timestamp, killToken)) {
    return; // Reject spoofed kills
  }
  
  // Update quest progress
  questSystem.handleNPCDied(data);
});
```

Progress updates saved to database and emitted to client:

```typescript
world.emit(EventType.QUEST_PROGRESSED, {
  playerId,
  questId,
  stage: currentStage,
  progress: { kills: 7 }, // Current progress
  description: "Kill 15 goblins (7/15)"
});
```

### 4. Quest Completion

When final stage objective is met, quest status becomes `ready_to_complete`. Player returns to quest NPC → Dialogue includes `completeQuest` effect:

```typescript
{
  "id": "quest_complete",
  "text": "You've done it! Here's your reward.",
  "effect": "completeQuest:goblin_slayer"
}
```

Server completes quest atomically:
- Marks quest as completed in database
- Awards quest points
- Grants reward items
- Grants reward XP
- Emits `QUEST_COMPLETED` event → Client shows completion screen

## Quest Status

| Status | Description |
|--------|-------------|
| `not_started` | Quest not yet started |
| `in_progress` | Quest active, objectives incomplete |
| `ready_to_complete` | All objectives met, return to NPC |
| `completed` | Quest finished, rewards claimed |

**Note**: `ready_to_complete` is a **derived status** computed at runtime when `status === "in_progress"` AND current stage objective is met. It's not stored in the database.

## Security Features

### HMAC Kill Token Validation

Prevents spoofed `NPC_DIED` events from compromised clients:

```typescript
// Server generates token when mob spawns
const killToken = generateKillToken(mobId, killedBy, timestamp);

// Client receives token with NPC_DIED event
world.emit(EventType.NPC_DIED, {
  mobId,
  killedBy,
  timestamp,
  killToken // HMAC-SHA256 signature
});

// Server validates before counting kill
if (!validateKillToken(mobId, killedBy, timestamp, killToken)) {
  logger.warn("Invalid kill token - possible spoof attempt");
  return;
}
```

Token includes:
- `mobId` - Prevents reusing tokens for different mobs
- `killedBy` - Prevents stealing other players' kills
- `timestamp` - 5-second validity window prevents replay attacks

### Rate Limiting

Prevents quest UI spam and DoS attacks:

| Handler | Limit | Purpose |
|---------|-------|---------|
| `getQuestList` | 5/sec | Prevent journal spam |
| `getQuestDetail` | 10/sec | Prevent detail spam |
| `questAccept` | 3/sec | Prevent accept spam |

Uses sliding window rate limiter with automatic cleanup.

### Quest Audit Logging

Immutable audit trail for all quest state changes:

```sql
CREATE TABLE quest_audit_log (
  id SERIAL PRIMARY KEY,
  playerId TEXT NOT NULL,
  questId TEXT NOT NULL,
  action TEXT NOT NULL, -- "started", "progressed", "completed"
  questPointsAwarded INTEGER DEFAULT 0,
  stageId TEXT,
  stageProgress JSONB,
  timestamp BIGINT NOT NULL,
  metadata JSONB
);
```

Enables:
- Fraud detection and investigation
- Debugging quest progression bugs
- Analytics for game design
- Customer support inquiries

### Input Validation

All quest IDs validated with security-conscious utilities:

```typescript
export const MAX_QUEST_ID_LENGTH = 64;
export const QUEST_ID_PATTERN = /^[a-z][a-z0-9_]{0,63}$/;

export function isValidQuestId(id: unknown): id is string {
  return (
    typeof id === "string" &&
    id.length > 0 &&
    id.length <= MAX_QUEST_ID_LENGTH &&
    QUEST_ID_PATTERN.test(id)
  );
}
```

Prevents:
- DoS via huge strings
- Log injection attacks
- Invalid character exploits

## Performance Optimizations

### O(1) Stage Lookup Caches

Replaced O(n) `find()` calls with O(1) Map lookups:

```typescript
// Pre-allocated stage lookup caches (per quest)
private _stageCaches: Map<string, Map<string, QuestStage>> = new Map();

// Build cache on first access
private getStageCache(questId: string): Map<string, QuestStage> {
  let cache = this._stageCaches.get(questId);
  if (!cache) {
    const definition = this.questDefinitions.get(questId);
    cache = new Map(definition.stages.map(s => [s.id, s]));
    this._stageCaches.set(questId, cache);
  }
  return cache;
}
```

Critical for hot paths (NPC_DIED events fire frequently).

### Object Spread Elimination

Replaced object spreads with direct mutation in hot paths:

```typescript
// Before: Allocates new object on every kill
progress.stageProgress = {
  ...progress.stageProgress,
  [stage.target]: currentKills
};

// After: Direct mutation (safe - we own this object)
progress.stageProgress[stage.target] = currentKills;
```

Reduces GC pressure in hot paths.

### Log Verbosity Reduction

Debug-level for frequent events, info-level only for milestones:

```typescript
// Every mob kill (frequent)
this.logger.debug(`NPC_DIED: killedBy=${killedBy}, mobType=${mobType}`);

// Quest milestones (infrequent)
this.logger.info(`Quest completed: ${questId} by ${playerId}`);
```

## Quest UI

### Quest Journal

OSRS-style quest tracking interface:

- **Quest List**: Color-coded status
  - Red: Not started
  - Yellow: In progress / ready to complete
  - Green: Completed
- **Quest Detail View**: Shows stages with strikethrough for completed
- **Progress Counters**: Dynamic counts (e.g., "Kill 15 goblins (7/15)")
- **Quest Points**: Total displayed prominently

### Quest Start Screen

Parchment-style confirmation screen:

- Quest name and difficulty
- Description
- Requirements (quests, skills, items)
- Rewards (quest points, items, XP)
- Accept / Decline buttons

### Quest Complete Screen

Celebration overlay:

- Congratulations message
- Quest name
- Rewards display
- Click anywhere to dismiss
- Fanfare sound effect (if audio system available)

## Database Schema

### quest_progress Table

```sql
CREATE TABLE quest_progress (
  id SERIAL PRIMARY KEY,
  playerId TEXT NOT NULL REFERENCES characters(id) ON DELETE CASCADE,
  questId TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'not_started',
  currentStage TEXT,
  stageProgress JSONB DEFAULT '{}',
  startedAt BIGINT,
  completedAt BIGINT,
  CONSTRAINT quest_progress_player_quest_unique UNIQUE(playerId, questId)
);

CREATE INDEX idx_quest_progress_player ON quest_progress(playerId);
CREATE INDEX idx_quest_progress_status ON quest_progress(playerId, status);
```

### quest_audit_log Table

```sql
CREATE TABLE quest_audit_log (
  id SERIAL PRIMARY KEY,
```

## Dialogue Integration

Quests integrate with the dialogue system via effects:

### startQuest Effect

```typescript
// In dialogue node
{
  "effect": "startQuest:goblin_slayer"
}
```

Triggers quest start confirmation screen. Player must click "Accept Quest" to actually start.

### completeQuest Effect

```typescript
// In dialogue node
{
  "effect": "completeQuest:goblin_slayer"
}
```

Completes the quest and shows completion screen with rewards.

### Quest-Aware Dialogue

NPCs can show different dialogue based on quest status:

```typescript
// In NPC definition
{
  "questOverrides": {
    "goblin_slayer": {
      "not_started": "start_quest_node",
      "in_progress": "quest_progress_node",
      "ready_to_complete": "quest_complete_node",
      "completed": "quest_done_node"
    }
  }
}
```

Priority: `ready_to_complete` > `in_progress` > `completed` > default

## XP Lamp System

Quest rewards can include XP lamps that let players choose which skill receives XP:

### Lamp Item Definition

```json
{
  "id": "xp_lamp_1000",
  "name": "XP Lamp (1000 XP)",
  "type": "misc",
  "useEffect": {
    "type": "xp_lamp",
    "xpAmount": 1000
  },
  "inventoryActions": ["Rub", "Drop", "Examine"]
}
```

### Usage Flow

1. Player right-clicks lamp → Selects "Rub"
2. Client emits `XP_LAMP_USE_REQUEST` event
3. Skill selection modal appears
4. Player selects skill
5. Client sends `xpLampUse` packet
6. Server validates and consumes lamp
7. Server grants XP to selected skill
8. Client shows success toast
