## Overview

Hyperscape features a comprehensive quest system inspired by Old School RuneScape, with multi-stage quests, skill requirements, and quest points tracking.

## Quest Features

- **Multi-stage quests** — Kill, gather, interact, and dialogue stages
- **Quest points** — Earned on completion, tracked per character
- **Prerequisites** — Quest, skill, and item requirements
- **Rewards** — Quest points, items, and skill XP
- **Progress tracking** — Real-time progress updates with counters
- **OSRS-style UI** — Color-coded quest journal with strikethrough for completed steps

## Quest Stages

### Stage Types

| Type | Description | Required Fields |
|------|-------------|-----------------|
| **dialogue** | Talk to an NPC | `description` |
| **kill** | Kill specific NPCs | `target`, `count` |
| **gather** | Collect items via gathering | `target`, `count` |
| **interact** | Interact with objects/stations | `target`, `count` |

### Kill Stages

Track NPC kills with HMAC validation to prevent spoofing:

```typescript
{
  "id": "kill_goblins",
  "type": "kill",
  "description": "Kill 15 goblins.",
  "target": "goblin",
  "count": 15
}
```

**Security:**
- HMAC-SHA256 kill tokens prevent event spoofing
- Tokens validated within 5-second window
- Server-only token generation (Node.js crypto module)

### Gather Stages

Track items collected through gathering skills:

```typescript
{
  "id": "gather_logs",
  "type": "gather",
  "description": "Chop 10 normal logs.",
  "target": "logs",
  "count": 10
}
```

**Features:**
- Flexible completion order (gather copper and tin in any order)
- Progress tracked by item ID
- Works with woodcutting, mining, and fishing

### Interact Stages

Track interactions with game objects:

```typescript
{
  "id": "light_fires",
  "type": "interact",
  "description": "Light 5 fires.",
  "target": "fire",
  "count": 5
}
```

**Supported interactions:**
- Firemaking (light fires)
- Cooking (cook food)
- Smithing (smith items)

## Quest Flow

### 1. Starting a Quest

**Via Dialogue:**
1. Talk to quest NPC
2. Dialogue system checks quest status
3. Shows quest start confirmation screen
4. Player clicks "Accept Quest"
5. Quest status changes to `in_progress`
6. Starting items granted (if defined in `onStart`)

**Dialogue Integration:**

```typescript
// From packages/shared/src/systems/shared/interaction/DialogueSystem.ts
{
  "dialogue": {
    "quest_overrides": {
      "goblin_slayer": {
        "not_started": "start_quest",
        "in_progress": "quest_progress",
        "ready_to_complete": "quest_complete",
        "completed": "quest_done"
      }
    }
  }
}
```

### 2. Tracking Progress

The quest system listens to game events:

```typescript
// From packages/shared/src/systems/shared/progression/QuestSystem.ts
this.subscribe(EventType.NPC_DIED, (data) => this.handleNPCDied(data));
this.subscribe(EventType.INVENTORY_ITEM_ADDED, (data) => this.handleGatherStage(data));
this.subscribe(EventType.FIRE_CREATED, (data) => this.handleInteractStage(data));
this.subscribe(EventType.COOKING_COMPLETED, (data) => this.handleInteractStage(data));
this.subscribe(EventType.SMITHING_COMPLETE, (data) => this.handleInteractStage(data));
```

**Progress Updates:**
- Real-time progress counters (e.g., "Kill 15 goblins (7/15)")
- Chat messages on milestone completion
- `QUEST_PROGRESSED` event emitted to clients

### 3. Completing a Quest

**Via Dialogue:**
1. Complete all quest stages
2. Quest status becomes `ready_to_complete`
3. Talk to quest NPC
4. Dialogue triggers `completeQuest` effect
5. Rewards granted atomically
6. Quest completion screen displayed

**Atomic Completion:**

```typescript
// From packages/server/src/database/repositories/QuestRepository.ts
await this.db.transaction(async (tx) => {
  // Mark quest as completed
  await tx.update(schema.questProgress).set({
    status: "completed",
    completedAt: Date.now(),
  });
  
  // Award quest points
  if (questPoints > 0) {
    await tx.update(schema.characters).set({
      questPoints: sql`${schema.characters.questPoints} + ${questPoints}`,
    });
  }
  
  // Audit log entry
  await tx.insert(schema.questAuditLog).values({
    playerId, questId, action: "completed",
    questPointsAwarded: questPoints, timestamp: Date.now(),
  });
});
```

## Quest Status

| Status | Description |
|--------|-------------|
| **not_started** | Quest not yet begun |
| **in_progress** | Quest active, objectives incomplete |
| **ready_to_complete** | All objectives met, return to NPC |
| **completed** | Quest finished, rewards claimed |

<Info>
  `ready_to_complete` is a **derived state** computed at runtime when status is `in_progress` AND the current stage objective is met. It's not stored in the database.
</Info>

## Database Schema

### quest_progress Table

```sql
CREATE TABLE quest_progress (
  id SERIAL PRIMARY KEY,
  playerId TEXT NOT NULL REFERENCES characters(id) ON DELETE CASCADE,
  questId TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'not_started',
  currentStage TEXT,
  stageProgress JSONB DEFAULT '{}',
  startedAt BIGINT,
  completedAt BIGINT,
  CONSTRAINT quest_progress_player_quest_unique UNIQUE(playerId, questId)
);

CREATE INDEX idx_quest_progress_player ON quest_progress(playerId);
CREATE INDEX idx_quest_progress_status ON quest_progress(playerId, status);
```

**Columns:**
- `playerId` — Character ID (CASCADE DELETE)
- `questId` — Quest identifier from manifest
- `status` — `not_started`, `in_progress`, or `completed`
- `currentStage` — Current stage ID
- `stageProgress` — JSON object tracking progress (e.g., `{"kills": 7}`)
- `startedAt` — Unix timestamp when quest started
- `completedAt` — Unix timestamp when quest completed

### quest_audit_log Table

Immutable audit trail for security and exploit detection:

```sql
CREATE TABLE quest_audit_log (
  id SERIAL PRIMARY KEY,
  playerId TEXT NOT NULL REFERENCES characters(id) ON DELETE CASCADE,
  questId TEXT NOT NULL,
  action TEXT NOT NULL,
  questPointsAwarded INTEGER DEFAULT 0,
  stageId TEXT,
  stageProgress JSONB DEFAULT '{}',
  timestamp BIGINT NOT NULL,
  metadata JSONB DEFAULT '{}'
);

CREATE INDEX idx_quest_audit_log_player ON quest_audit_log(playerId);
CREATE INDEX idx_quest_audit_log_quest ON quest_audit_log(questId);
CREATE INDEX idx_quest_audit_log_timestamp ON quest_audit_log(timestamp);
```

**Actions:**
- `started` — Quest accepted
- `progressed` — Stage progress updated
- `completed` — Quest finished

## Security Features

### HMAC Kill Token Validation

Prevents spoofed `NPC_DIED` events:

```typescript
// From packages/shared/src/utils/game/KillTokenUtils.ts
export function generateKillToken(
  mobId: string,
  killedBy: string,
  timestamp: number,
): string {
  const secret = process.env.KILL_TOKEN_SECRET || "default-secret";
  const data = `${mobId}:${killedBy}:${timestamp}`;
  return crypto.createHmac("sha256", secret).update(data).digest("hex");
}
```

**Validation:**
- Tokens include `mobId`, `killedBy`, and `timestamp`
- Timestamp must be within 5-second window
- Invalid tokens rejected with warning log

### Rate Limiting

Quest network handlers are rate-limited:


### Input Validation

Quest IDs validated with strict pattern matching:

```typescript
// From packages/shared/src/types/game/quest-types.ts
export const MAX_QUEST_ID_LENGTH = 64;
export const QUEST_ID_PATTERN = /^[a-z][a-z0-9_]{0,63}$/;

export function isValidQuestId(id: unknown): id is string {
  return (
    typeof id === "string" &&
    id.length > 0 &&
    id.length <= MAX_QUEST_ID_LENGTH &&
    QUEST_ID_PATTERN.test(id)
  );
}
```

## Performance Optimizations

### O(1) Stage Lookups

Pre-allocated stage lookup caches replace O(n) `find()` calls:

```typescript
// From packages/shared/src/systems/shared/progression/QuestSystem.ts
private _stageCaches: Map<string, Map<string, QuestStage>> = new Map();

private getStageCache(questId: string): Map<string, QuestStage> {
  let cache = this._stageCaches.get(questId);
  if (!cache) {
    const definition = this.questDefinitions.get(questId);
    cache = new Map(definition.stages.map(s => [s.id, s]));
    this._stageCaches.set(questId, cache);
  }
  return cache;
}
```

### Direct Mutation in Hot Paths

Object spreads eliminated in favor of direct mutation:

```typescript
// Before: Allocates new object on every kill
progress.stageProgress = {
  ...progress.stageProgress,
  [stage.target]: currentKills
};

// After: Reuses existing object (zero allocation)
progress.stageProgress[stage.target] = currentKills;
```

### Log Verbosity Reduction

Debug-level logging in hot paths (NPC kill events):

```typescript
// Frequent events: debug level
this.logger.debug(`NPC_DIED: killedBy=${killedBy}, mobType=${mobType}`);

// Milestones: info level
this.logger.info(`Quest completed: ${questId} by ${playerId}`);
```
