# Quest System

Hyperscape features a complete OSRS-style quest system with kill tracking, skill requirements, dialogue integration, and quest rewards including XP lamps and quest points.

<Info>
Quest system code: `packages/shared/src/systems/shared/progression/QuestSystem.ts` (1091 lines)
</Info>

---

## Overview

The quest system provides:

- **Quest Journal** — Track active and completed quests with progress indicators
- **Kill Tracking** — Automatic progress for kill objectives with HMAC validation
- **Skill Quests** — Gather, interact, and skill-based objectives (cooking, smithing, firemaking)
- **Dialogue Integration** — Quest start/complete through NPC conversations
- **Quest Rewards** — Quest points, items, and XP lamps
- **Security** — HMAC kill token validation, rate limiting, audit logging

## Quest Stages

Quests consist of sequential stages that players must complete in order:

### Stage Types

| Type | Description | Example |
|------|-------------|---------|
| `dialogue` | Talk to an NPC | "Talk to the Cook" |
| `kill` | Kill specific NPCs | "Kill 15 goblins" |
| `gather` | Gather resources | "Mine 10 copper ore" |
| `interact` | Interact with objects | "Light 5 fires" |

### Kill Stages

```json
{
  "id": "kill_goblins",
  "type": "kill",
  "description": "Kill 15 goblins.",
  "target": "goblin",
  "count": 15
}
```

**Features:**
- Automatic progress tracking via `NPC_DIED` events
- HMAC kill token validation prevents spoofing
- Progress persists to database on each kill
- Chat notifications at milestones (5, 10, 15 kills)

### Gather Stages

```json
{
  "id": "gather_copper",
  "type": "gather",
  "description": "Mine 10 copper ore.",
  "target": "copper_ore",
  "count": 10
}
```

**Features:**
- Tracks via `INVENTORY_ITEM_ADDED` events
- Flexible completion order (can gather multiple items in any order)
- Progress tracked by item ID, not stage index

### Interact Stages

```json
{
  "id": "light_fires",
  "type": "interact",
  "description": "Light 5 fires.",
  "target": "fire",
  "count": 5
}
```

**Supported Interactions:**
- `FIRE_CREATED` — Firemaking
- `COOKING_COMPLETED` — Cooking
- `SMITHING_COMPLETE` — Smithing

## Quest Flow

### 1. Quest Request

Player talks to quest NPC. Dialogue system checks quest status and shows appropriate dialogue:

```typescript
// DialogueSystem checks quest overrides
const questSystem = world.getSystem("quest") as QuestSystem;
const status = questSystem.getQuestStatus(playerId, questId);

if (status === "not_started") {
  // Show quest start dialogue
  questSystem.requestQuestStart(playerId, questId);
}
```

### 2. Quest Start Confirmation

Server emits `QUEST_START_CONFIRM` event with quest details:

```typescript
world.emit(EventType.QUEST_START_CONFIRM, {
  playerId,
  questId,
  questName,
  description,
  difficulty,
  requirements: {
    quests: [],
    skills: { attack: 10 },
    items: []
  },
  rewards: {
    questPoints: 1,
    items: [{ itemId: "xp_lamp_1000", quantity: 1 }],
    xp: { attack: 500 }
  }
});
```

Client displays **Quest Start Screen** with Accept/Decline buttons.

### 3. Quest Acceptance

Player clicks "Accept Quest". Client sends `questAccept` packet:

```typescript
world.network.send("questAccept", { questId });
```

Server validates requirements and starts quest:

```typescript
const success = await questSystem.startQuest(playerId, questId);
```

**On Success:**
- Quest status set to `in_progress`
- Starting items granted (if defined in `onStart`)
- `QUEST_STARTED` event emitted
- Progress saved to database

### 4. Quest Progress

As player completes objectives, progress is tracked automatically:

```typescript
// Kill tracking (via NPC_DIED event)
world.on(EventType.NPC_DIED, (data) => {
  if (data.mobType === stage.target) {
    progress.stageProgress.kills = (progress.stageProgress.kills || 0) + 1;
    
    // Emit progress event
    world.emit(EventType.QUEST_PROGRESSED, {
      playerId,
      questId,
      stage: currentStage,
      progress: progress.stageProgress
    });
  }
});
```

**Progress Tracking:**
- Kill stages: `{ kills: 7 }`
- Gather stages: `{ copper_ore: 5, tin_ore: 3 }`
- Interact stages: `{ fire: 2 }`

### 5. Quest Completion

When all objectives are met, quest status becomes `ready_to_complete`. Player returns to quest NPC and dialogue triggers completion:

```typescript
// Dialogue effect: completeQuest
await questSystem.completeQuest(playerId, questId);
```

**Completion Flow:**
1. Validate quest is `ready_to_complete`
2. Award quest points (atomic transaction)
3. Grant reward items
4. Grant XP rewards
5. Emit `QUEST_COMPLETED` event
6. Show completion screen

## Quest Status

Quests have 4 possible statuses:

| Status | Description |
|--------|-------------|
| `not_started` | Player hasn't started the quest |
| `in_progress` | Quest active, objectives incomplete |
| `ready_to_complete` | All objectives met, return to NPC |
| `completed` | Quest finished, rewards claimed |

<Info>
`ready_to_complete` is a **derived status** computed at runtime when `status === "in_progress"` AND the current stage objective is met. It's not stored in the database.
</Info>

**Usage Flow:**

3. Player selects skill
4. Lamp consumed, XP granted

## Database Schema

### quest_progress Table

Tracks player quest state:

```sql
CREATE TABLE quest_progress (
  id SERIAL PRIMARY KEY,
  playerId TEXT NOT NULL REFERENCES characters(id) ON DELETE CASCADE,
  questId TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'not_started',
  currentStage TEXT,
  stageProgress JSONB DEFAULT '{}',
  startedAt BIGINT,
  completedAt BIGINT,
  CONSTRAINT quest_progress_player_quest_unique UNIQUE(playerId, questId)
);

CREATE INDEX idx_quest_progress_player ON quest_progress(playerId);
CREATE INDEX idx_quest_progress_status ON quest_progress(playerId, status);
```

**Columns:**
- `playerId` — Character ID (foreign key)
- `questId` — Quest identifier from manifest
- `status` — `not_started`, `in_progress`, or `completed`
- `currentStage` — Current stage ID
- `stageProgress` — JSON object with progress data (e.g., `{"kills": 7}`)
- `startedAt` — Unix timestamp (ms)
- `completedAt` — Unix timestamp (ms)

### quest_audit_log Table

Immutable audit trail for security and debugging:

```sql
CREATE TABLE quest_audit_log (
  id SERIAL PRIMARY KEY,
  playerId TEXT NOT NULL REFERENCES characters(id) ON DELETE CASCADE,
  questId TEXT NOT NULL,
  action TEXT NOT NULL,
  questPointsAwarded INTEGER DEFAULT 0,
  stageId TEXT,
  stageProgress JSONB DEFAULT '{}',
  timestamp BIGINT NOT NULL,
  metadata JSONB DEFAULT '{}'
);

CREATE INDEX idx_quest_audit_log_player ON quest_audit_log(playerId);
CREATE INDEX idx_quest_audit_log_quest ON quest_audit_log(questId);
CREATE INDEX idx_quest_audit_log_timestamp ON quest_audit_log(timestamp);
```

**Actions:**
- `started` — Quest started
- `progressed` — Stage progress updated
- `completed` — Quest completed with rewards

## Security Features

### HMAC Kill Token Validation

Prevents spoofed `NPC_DIED` events:

```typescript
// Server generates kill token when mob dies
const killToken = generateKillToken(mobId, killedBy, timestamp);

// QuestSystem validates token before counting kill
if (!validateKillToken(mobId, killedBy, timestamp, killToken)) {
  logger.warn("Invalid kill token - possible spoof attempt");
  return;
}
```

**Implementation:**
- Uses HMAC-SHA256 with server-side secret
- Tokens include: `mobId`, `killedBy`, `timestamp`
- 5-second validity window
- Server-only (uses Node.js crypto module)

### Rate Limiting

Quest network handlers are rate-limited:

| Handler | Limit | Purpose |
|---------|-------|---------|
| `getQuestList` | 5/sec | Prevent UI spam |
| `getQuestDetail` | 10/sec | Prevent detail spam |
| `questAccept` | 3/sec | Prevent accept spam |

### Input Validation

All quest IDs are validated:

```typescript
export const MAX_QUEST_ID_LENGTH = 64;
export const QUEST_ID_PATTERN = /^[a-z][a-z0-9_]{0,63}$/;

export function isValidQuestId(id: unknown): id is string {
  return (
    typeof id === "string" &&
    id.length > 0 &&
    id.length <= MAX_QUEST_ID_LENGTH &&
    QUEST_ID_PATTERN.test(id)
  );
}
```

## Performance Optimizations

### O(1) Stage Lookups

Stage lookups use pre-computed Map caches instead of O(n) array searches:

```typescript
// Pre-allocated stage lookup caches (per quest)
private _stageCaches: Map<string, Map<string, QuestStage>> = new Map();

// Build cache on first access
private getStageCache(questId: string): Map<string, QuestStage> {
  let cache = this._stageCaches.get(questId);
  if (!cache) {
    const definition = this.questDefinitions.get(questId);
    cache = new Map(definition.stages.map(s => [s.id, s]));
    this._stageCaches.set(questId, cache);
  }
  return cache;
}
```

**Impact:** O(n) → O(1) for stage lookups in hot paths (NPC kill events)

### Direct Mutation

Object spreads eliminated in hot paths:

```typescript
// Before: Allocates new object on every kill
progress.stageProgress = {
  ...progress.stageProgress,
  kills: currentKills
};

// After: Direct mutation (zero allocation)
progress.stageProgress.kills = currentKills;
```

### Smart Logging

Log levels optimized for production:

```typescript
// Debug-level for frequent events (every mob kill)
this.logger.debug(`NPC_DIED: killedBy=${killedBy}, mobType=${mobType}`);

// Info-level only for milestones
this.logger.info(`Quest ${questId} completed by ${playerId}`);
```

## Dialogue Integration

Quests integrate with the dialogue system via **dialogue overrides**:

```json
{
  "cook": {
    "id": "cook",
    "name": "Cook",
    "dialogue": {
      "default": "cook_default",
      "questOverrides": {
        "goblin_slayer": {
          "not_started": "cook_quest_offer",
          "in_progress": "cook_quest_progress",
          "ready_to_complete": "cook_quest_complete",
          "completed": "cook_quest_done"
        }
      }
    }
  }
}
```

**Priority:** `ready_to_complete` > `in_progress` > `completed` > `default`

### Dialogue Effects

Dialogue nodes can trigger quest actions:

```json
{
  "id": "cook_quest_offer",
  "text": "Would you like to help me with the goblin problem?",
  "responses": [
    {
      "text": "Yes, I'll help!",
      "next": "cook_quest_accept",
      "effect": {
        "type": "startQuest",
        "params": ["goblin_slayer"]
      }
    },
    {
      "text": "Not right now.",
      "next": null
    }
  ]
}
```

**Available Effects:**
- `startQuest` — Show quest accept screen
- `completeQuest` — Complete quest and show rewards
