# Trading System

Hyperscape implements a secure, server-authoritative player-to-player trading system with OSRS-style mechanics including proximity checks, two-screen confirmation flow, wealth transfer indicators, and anti-scam protection.

<Info>
Trading code lives in `packages/server/src/systems/TradingSystem/` (server) and `packages/client/src/game/panels/TradePanel/` (client).
</Info>

## Core Features

- **OSRS-style two-screen confirmation** — Offer screen → Confirm screen prevents scams
- **Proximity checks** — Players must be adjacent (1 tile) to trade
- **Auto-walk to trade** — Click to trade walks player to target if out of range
- **Wealth transfer indicator** — Shows value difference between offers
- **Anti-scam protection** — Red flashing exclamation when items removed
- **Partner inventory slots** — Shows if partner can accept items
- **Chat integration** — Pink clickable trade request messages
- **Context menus** — Right-click for "Offer-X", "Offer-All", etc.
- **Interface blocking** — Can't trade while banking/shopping

## Trade Flow

### 1. Trade Request

Player A clicks Player B to initiate trade:

```typescript
// Client sends trade request
world.network.send("tradeRequest", { targetPlayerId: playerB.id });

// Server checks proximity
if (!arePlayersInTradeRange(world, playerA.id, playerB.id)) {
  // Queue pending trade - player walks to target first
  pendingTradeManager.queuePendingTrade(
    playerA.id,
    playerB.id,
    () => sendTradeRequestToTarget()
  );
  return;
}

// Send pink chat message to Player B (OSRS-style)
const chatMessage = {
  id: uuid(),
  from: "",
  body: `${playerA.name} wishes to trade with you.`,
  type: "trade_request",
  tradeId: tradeId,
};
```

### 2. Accept/Decline

Player B clicks the pink chat message or accepts via modal:

```typescript
// Player B accepts
world.network.send("tradeRequestRespond", {
  tradeId: tradeId,
  accept: true,
});

// Server opens trade window for both players
sendToSocket(playerA.socket, "tradeStarted", {
  tradeId,
  partnerId: playerB.id,
  partnerName: playerB.name,
  partnerLevel: playerB.combatLevel,
  partnerFreeSlots: 28,
});
```

### 3. Offer Screen

Players add/remove items from their offers:

```typescript
// Left-click inventory item: add 1 to trade
onItemLeftClick={(item) => {
  world.network.send("tradeAddItem", {
    tradeId,
    inventorySlot: item.slot,
    quantity: 1,
  });
}}

// Right-click inventory item: show context menu
// Options: Offer, Offer-5, Offer-10, Offer-X, Offer-All, Value, Examine

// Click item in trade offer: remove from trade
onRemoveItem={(tradeSlot) => {
  world.network.send("tradeRemoveItem", {
    tradeId,
    tradeSlot,
  });
}}
```

**Offer Screen Features:**
- Left panel: Your offer (4×7 grid, 28 slots)
- Center panel: Partner's offer (4×7 grid, 28 slots)
- Right panel: Your inventory (click to add items)
- Partner free slots indicator
- Wealth transfer indicator (shows value difference)
- Accept/Cancel buttons

### 4. Confirmation Screen

When both players accept on offer screen, trade moves to confirmation:

```typescript
// Server moves to confirmation screen
const moveResult = tradingSystem.moveToConfirmation(tradeId);

// Send confirmation screen packet to both players
sendToSocket(playerA.socket, "tradeConfirmScreen", {
  tradeId,
  myOffer: playerA.offeredItems,
  theirOffer: playerB.offeredItems,
  myOfferValue: 15000,      // Total value in gp
  theirOfferValue: 12000,   // Total value in gp
});
```

**Confirmation Screen:**
- Shows final offers (no inventory panel)
- Displays item values
- Wealth transfer warning if imbalanced
- Both players must accept again to complete

### 5. Trade Completion

When both players accept on confirmation screen:

```typescript
// Server executes atomic item swap
await executeTradeSwap(tradingSystem, tradeId, world, db);

// Atomic transaction:
// 1. Lock both inventories
// 2. Validate all items still exist
// 3. Check inventory space
// 4. Remove items from both players
// 5. Add items to both players
// 6. Unlock inventories
// 7. Send completion packets
```

## Security Measures

### Server-Authoritative Design

All trade operations are validated server-side:

- **Proximity validation** — Players must be within 1 tile
- **Item validation** — Items must exist in inventory with correct quantities
- **Tradeable flag** — Items with `tradeable: false` are rejected
- **Inventory space** — Checks both players have room for incoming items
- **Atomic transactions** — Database locks prevent item duplication
- **Rate limiting** — Prevents spam attacks

```typescript
    myOfferValue > 0) {
  // Display ⚠️ warning icon
```

**Two-Screen Confirmation:**

The OSRS-style two-screen flow prevents last-second item swaps:

1. **Offer screen** — Players build offers, both accept
2. **Confirmation screen** — Final review, both accept again
3. **Trade completes** — Atomic item swap

Acceptance resets if either offer changes, forcing re-review.

```typescript
// From TradePanel/utils.ts
export function parseQuantityInput(input: string): number {
  const normalized = input.toLowerCase().trim();
  const match = normalized.match(/^(\d+\.?\d*)(k|m)?$/);
  if (!match) return 0;
  
  let value = parseFloat(match[1]);
  if (match[2] === "k") value *= 1000;
  if (match[2] === "m") value *= 1000000;
  return Math.floor(value);
}

// Examples: "10k" → 10000, "1.5m" → 1500000, "500" → 500
```

## Proximity System

### PendingTradeManager

Handles "walk to player and trade" behavior:

```typescript
// From packages/server/src/systems/ServerNetwork/PendingTradeManager.ts
export class PendingTradeManager {
  /**
   * Queue a pending trade request.
   * Player walks to target, then trade request is sent.
   */
  queuePendingTrade(
    playerId: string,
    targetId: string,
    onInRange: () => void,
  ): void;
  
  /**
   * Process all pending trades - called every tick.
   * Re-paths if target moves.
   */
  processTick(): void;
  
  /**
   * Cancel pending trade for a player.
   */
  cancelPendingTrade(playerId: string): void;
}
```

**Behavior:**
1. Player clicks another player to trade
2. If not in range, server queues "pending trade" and moves player toward target
3. Every tick, server re-checks range and re-paths if target moved
4. When in range, server sends the trade request
5. New click or disconnect cancels pending trade

**Trade Interaction Range:**

```typescript
// From packages/server/src/systems/ServerNetwork/handlers/trade/helpers.ts
export const TRADE_PROXIMITY_TILES = 1;  // Players must be adjacent

// Chebyshev distance check (allows diagonals)
export function arePlayersInTradeRange(
  world: World,
  playerId1: string,
  playerId2: string,
): boolean {
  const distance = chebyshevDistance(pos1, pos2);
  return distance <= TRADE_PROXIMITY_TILES;
}
```

## Atomic Item Swap

The trade completion uses database transactions to prevent item duplication:

```typescript
// From packages/server/src/systems/ServerNetwork/handlers/trade/swap.ts
export async function executeTradeSwap(
  tradingSystem: TradingSystem,
  tradeId: string,
  world: World,
  db: DatabaseConnection,
): Promise<void> {
  // 1. Lock both inventories
  const initiatorLocked = inventorySystem.lockForTransaction(initiatorId);
  const recipientLocked = inventorySystem.lockForTransaction(recipientId);
  
  try {
    // 2. Flush both inventories to DB
    await inventorySystem.persistInventoryImmediate(initiatorId);
    await inventorySystem.persistInventoryImmediate(recipientId);
    
    // 3. Execute atomic swap in transaction
    await executeSecureTransaction({
      execute: async (tx) => {
        // Lock inventory rows with FOR UPDATE
        const initiatorInventory = await tx.execute(
          sql`SELECT * FROM inventory WHERE "playerId" = ${initiatorId} FOR UPDATE`
        );
        
        // Validate all items still exist with correct quantities
        for (const offer of session.initiator.offeredItems) {
          const item = initiatorInventory.find(i => i.slotIndex === offer.inventorySlot);
          if (!item || item.itemId !== offer.itemId || item.quantity < offer.quantity) {
            throw new Error("ITEM_CHANGED");
          }
          
          // Validate tradeable flag
          const itemDef = getItem(offer.itemId);
          if (!itemDef || itemDef.tradeable === false) {
            throw new Error("UNTRADEABLE_ITEM");
          }
        }
        
        // Check inventory space
        if (initiatorFreeSlots + initiatorOfferSlots.size < recipientOfferCount) {
          throw new Error("INVENTORY_FULL_INITIATOR");
        }
        
        // PHASE 1: Remove all offered items from both players
        for (const offer of session.initiator.offeredItems) {
          if (item.quantity === offer.quantity) {
            await tx.execute(sql`DELETE FROM inventory WHERE ...`);
          } else {
            await tx.execute(sql`UPDATE inventory SET quantity = ... WHERE ...`);
          }
        }
        
        // PHASE 2: Add traded items to both players
        for (const offer of session.initiator.offeredItems) {
          const recipientSlot = findFreeSlotFromSet(recipientTrackingSlots, recipientOfferSlots);
          await tx.execute(sql`INSERT INTO inventory VALUES (...)`);
        }
        
        return { initiatorReceived, recipientReceived };
      },
    });
    
    // 4. Reload inventories from DB
    await inventorySystem.reloadFromDatabase(initiatorId);
    await inventorySystem.reloadFromDatabase(recipientId);
    
    // 5. Complete trade
    tradingSystem.completeTrade(tradeId);
    
  } finally {
    // Always unlock inventories
    inventorySystem.unlockTransaction(initiatorId);
    inventorySystem.unlockTransaction(recipientId);
  }
}
```

### Wealth Transfer Indicator

```typescript
// From TradePanel/utils.ts
export function formatGoldValue(value: number): string {
  if (value < 1000) return value.toLocaleString();
  if (value < 1000000) {
    const k = Math.floor(value / 1000);
    const remainder = Math.floor((value % 1000) / 100);
    return remainder > 0 ? `${k}.${remainder}K` : `${k}K`;
  }
  if (value < 1000000000) {
    const m = Math.floor(value / 1000000);
    const remainder = Math.floor((value % 1000000) / 100000);
    return remainder > 0 ? `${m}.${remainder}M` : `${m}M`;
  }
  const b = Math.floor(value / 1000000000);
  return `${b}B`;
}

export function getWealthDifferenceColor(
  myValue: number,
  theirValue: number,
): string {
  const diff = theirValue - myValue;
  if (diff > 0) return "#22c55e";  // Green - gaining
  if (diff < 0) return "#ef4444";  // Red - losing
  return "#ffffff";  // White - equal
}
```

## Interface Blocking

Players cannot trade while using other interfaces:

```typescript
// From packages/server/src/systems/ServerNetwork/handlers/common/helpers.ts
export function hasActiveInterfaceSession(
  world: World,
  playerId: string,
): boolean {
  const sessionManager = getSessionManager(world);
  if (!sessionManager) return false;
  return sessionManager.getSession(playerId) !== undefined;
}

// Trade request validation
if (hasActiveInterfaceSession(world, playerId)) {
  sendTradeError(socket, "You can't trade while using another interface", "INTERFACE_OPEN");
  return;
}

if (hasActiveInterfaceSession(world, targetPlayerId)) {
  sendTradeError(socket, "That player is busy", "PLAYER_BUSY");
  return;
}
```

## Error Handling

### Trade Error Codes

| Code | Message | Cause |
|------|---------|-------|
| `NOT_AUTHENTICATED` | Not authenticated | Missing player ID |
| `SYSTEM_ERROR` | Trading system unavailable | TradingSystem not initialized |
| `RATE_LIMITED` | Too fast | Exceeded rate limit |
| `INVALID_PLAYER` | Invalid player | Target player ID invalid |
| `PLAYER_OFFLINE` | Player is not online | Target disconnected |
| `INTERFACE_OPEN` | Can't trade while using another interface | Player has active session |
| `PLAYER_BUSY` | That player is busy | Target has active session |
| `TOO_FAR` | You need to be closer | Players not adjacent |
| `NOT_IN_TRADE` | Not in an active trade | Trade session not found |
| `INVALID_SLOT` | Invalid inventory slot | Slot out of range |
| `INVALID_ITEM` | Invalid item | Item not found |
| `UNTRADEABLE_ITEM` | That item cannot be traded | Item has `tradeable: false` |
| `INVALID_QUANTITY` | Not enough items | Insufficient quantity |
| `ITEM_CHANGED` | Items changed during trade | Item validation failed |
| `INVENTORY_FULL_INITIATOR` | Your inventory is full | No space for incoming items |
| `INVENTORY_FULL_RECIPIENT` | Partner's inventory is full | Partner has no space |
