# Death & Respawn System

The death system handles player deaths with zone-aware mechanics, gravestone spawning, and secure item recovery. It uses database persistence to prevent item duplication exploits.

<Info>
Death code lives in `packages/shared/src/systems/shared/death/` with:
- `DeathStateManager.ts` - Death tracking and persistence
- `SafeAreaDeathHandler.ts` - Safe zone death logic
- `WildernessDeathHandler.ts` - PvP zone death logic
- `ZoneDetectionSystem.ts` - Zone type detection
</Info>

## Death Lock System

To prevent item duplication on server restart/crash, deaths are tracked with **database-first persistence** and crash recovery.

```typescript
interface DeathLockData {
  playerId: string;
  gravestoneId: string | null;     // If gravestone spawned
  groundItemIds: string[];         // If items on ground
  position: { x: number; y: number; z: number };
  timestamp: number;
  zoneType: string;                // "safe_area" | "wilderness" | "pvp_zone"
  itemCount: number;               // Total items dropped
  // Crash recovery fields
  items: DeathItemData[];          // Actual item data for recovery
  killedBy: string;                // What killed the player
  recovered: boolean;              // Whether death was processed during crash recovery
}

interface DeathItemData {
  itemId: string;
  quantity: number;
}
```

### Atomic Death Lock Acquisition

Death locks use **atomic database operations** to prevent race conditions:

```typescript
// From DeathRepository.ts
async acquireDeathLockAsync(
  data: DeathLockData,
  tx?: TransactionContext,
): Promise<boolean> {
  // Use INSERT ... ON CONFLICT DO NOTHING for atomic check-and-create
  const result = await db
    .insert(schema.playerDeaths)
    .values({
      playerId: data.playerId,
      gravestoneId: data.gravestoneId,
      items: data.items,              // Full item list for crash recovery
      killedBy: sanitizeKilledBy(data.killedBy),
      recovered: false,
      // ... other fields
    })
    .onConflictDoNothing({ target: schema.playerDeaths.playerId })
    .returning({ playerId: schema.playerDeaths.playerId });

  // If conflict occurred, nothing is returned = lock already exists
  return result.length > 0;
}
```

<Info>
**Atomic Operations**: Using PostgreSQL's `INSERT ... ON CONFLICT` ensures only ONE death lock can exist per player, preventing duplicate death processing even under high concurrency.
</Info>

### Creating a Death Lock

```typescript
async createDeathLock(
  playerId: string,
  options: {
    gravestoneId: string | null;
    groundItemIds: string[];
    position: { x: number; y: number; z: number };
    zoneType: string;
    itemCount: number;
    items: DeathItemData[];        // NEW: Full item data for recovery
    killedBy: string;              // NEW: What killed the player
  },
  tx?: TransactionContext,
): Promise<boolean> {
  // Server authority check
  if (!this.world.isServer) {
    console.error(`[DeathStateManager] Client attempted death lock creation - BLOCKED`);
    return false;
  }

  // Atomic acquisition - prevents duplicate deaths
  const acquired = await this.databaseSystem.acquireDeathLockAsync(
    {
      playerId,
      gravestoneId: options.gravestoneId,
      groundItemIds: options.groundItemIds,
      position: options.position,
      timestamp: Date.now(),
      zoneType: options.zoneType,
      itemCount: options.itemCount,
      items: options.items,
      killedBy: options.killedBy,
      recovered: false,
    },
    tx,
  );

  if (!acquired) {
    // Player already has active death lock
    return false;
  }

  // Store in memory cache
  this.activeDeaths.set(playerId, deathData);
  return true;
}
```

## Death Flow

### Safe Zone Death

1. Player HP reaches 0
2. Items kept in inventory (no drop)
3. Player respawns at nearest safe point
4. Short death animation plays

### Dangerous Zone Death

1. Player HP reaches 0
2. **Gravestone spawns** at death location
3. Player's items stored in gravestone (15 minute timer)
4. Player respawns at starter town
5. Player can return to reclaim items

### PvP Zone Death

1. Player killed by another player
2. **Items drop directly to ground**
3. Loot protection for killer (100 ticks)
4. After protection, anyone can loot
5. Items despawn after 200 ticks

### Gravestone Expiration

When gravestone expires:
1. Items transition to ground items
2. Ground items have additional despawn timer
3. `onGravestoneExpired()` updates death lock

```typescript
async onGravestoneExpired(playerId: string, groundItemIds: string[]): Promise<void> {
  const deathData = this.activeDeaths.get(playerId);
  if (!deathData) return;
  
  // Update tracking: gravestone → ground items
  deathData.gravestoneId = undefined;
  deathData.groundItemIds = groundItemIds;
  this.activeDeaths.set(playerId, deathData);
  
  // Update database
  await this.databaseSystem.updateGroundItemsAsync(playerId, groundItemIds);
}
```

## Item Recovery

### Looting from Gravestone

The loot system uses **shadow state with transaction tracking** for optimistic UI updates with automatic rollback:

```typescript
// From LootWindow.tsx (client)
const handleTakeItem = (item: InventoryItem, index: number) => {
  const transactionId = generateTransactionId();

  // 1. Track pending transaction for rollback
  setPendingTransactions(prev => new Map(prev).set(transactionId, {
    itemId: item.itemId,
    quantity: item.quantity,
    originalIndex: index,
    originalItem: { ...item },
  }));

  // 2. Optimistically remove from UI
  setItems(prev => prev.filter((_, i) => i !== index));

  // 3. Set timeout for automatic rollback (3 seconds)
  const timeout = setTimeout(() => {
    rollbackTransaction(transactionId);  // Put item back if no response
  }, 3000);

  // 4. Send request with transaction ID
  world.network.send("entityEvent", {
    event: EventType.CORPSE_LOOT_REQUEST,
    payload: { corpseId, itemId, quantity, transactionId },
  });
};

// Server confirms/rejects via LOOT_RESULT event
const handleLootResult = (result: LootResult) => {
  if (result.success) {
    // Confirmed - remove from pending
    setPendingTransactions(prev => {
      const newMap = new Map(prev);
      newMap.delete(result.transactionId);
      return newMap;
    });
  } else {
    // Failed - rollback (put item back)
    rollbackTransaction(result.transactionId);
  }
};
```

### Server-Side Loot Processing

```typescript
// From HeadstoneEntity.ts
private async processLootRequest(data: {
  playerId: string;
  itemId: string;
  quantity: number;
  transactionId: string;
}): Promise<void> {
  // 1. Check loot protection
  if (!this.canPlayerLoot(playerId)) {
    this.emitLootResult(playerId, transactionId, false, "PROTECTED");
    return;
  }

  // 2. Check if item exists
  const itemIndex = this.lootItems.findIndex(item => item.itemId === itemId);
  if (itemIndex === -1) {
    this.emitLootResult(playerId, transactionId, false, "ITEM_NOT_FOUND");
    return;
  }

  // 3. CRITICAL: Check inventory space BEFORE removing item
  const hasSpace = this.checkInventorySpace(playerId, itemId, quantity);
  if (!hasSpace) {
    this.emitLootResult(playerId, transactionId, false, "INVENTORY_FULL");
    return;
  }

  // 4. Block looting during death animation
  if (this.isPlayerInDeathState(playerId)) {
    this.emitLootResult(playerId, transactionId, false, "PLAYER_DYING");
    return;
  }

  // 5. Atomic remove from gravestone
  const removed = this.removeItem(itemId, quantity);
  if (!removed) {
    this.emitLootResult(playerId, transactionId, false, "ITEM_NOT_FOUND");
    return;
  }

  // 6. DEFENSIVE: Re-check inventory space (closes race window)
  const stillHasSpace = this.checkInventorySpace(playerId, itemId, quantity);
  if (!stillHasSpace) {
    // Rollback: put item back in gravestone
    this.lootItems.push({ id, itemId, quantity, slot, metadata });
    this.emitLootResult(playerId, transactionId, false, "INVENTORY_FULL");
    return;
  }

  // 7. Add to player inventory (safe now, space double-checked)
  this.world.emit(EventType.INVENTORY_ITEM_ADDED, {
    playerId,
    item: { id: `loot_${playerId}_${Date.now()}`, itemId, quantity, slot: -1 },
  });

  // 8. Confirm success to client
  this.emitLootResult(playerId, transactionId, true);
}
```

### Loot Result Events

```typescript
interface LootResult {
  transactionId: string;
  success: boolean;
  itemId?: string;
  quantity?: number;
  reason?: LootFailureReason;
  timestamp: number;
}

type LootFailureReason =
  | "ITEM_NOT_FOUND"      // Item already looted
  | "INVENTORY_FULL"      // No inventory space
  | "PROTECTED"           // Loot protection active
  | "GRAVESTONE_GONE"     // Gravestone despawned
  | "RATE_LIMITED"        // Too many requests
  | "INVALID_REQUEST"     // Malformed request
  | "PLAYER_DYING";       // Player is dying/dead
```

<Info>
**Shadow State Pattern**: The client optimistically updates the UI immediately, then rolls back if the server rejects the request. This provides instant feedback while maintaining server authority.
</Info>

### Loot All Feature

Players can loot all items at once with a single batch request:

```typescript
// Client sends batch request
world.network.send("entityEvent", {
  event: EventType.CORPSE_LOOT_ALL_REQUEST,
  payload: { corpseId, playerId, transactionId },
});

// Server processes all items atomically
private async processLootAllRequest(data: {
  playerId: string;
  transactionId: string;
}): Promise<void> {
  // Process each item, stopping if inventory becomes full
  for (const item of [...this.lootItems]) {
    const hasSpace = this.checkInventorySpace(playerId, item.itemId, item.quantity);
    if (!hasSpace) break;  // Stop looting, remaining items stay

    const removed = this.removeItem(item.itemId, item.quantity);
    if (removed) {
      this.world.emit(EventType.INVENTORY_ITEM_ADDED, { playerId, item });
      successfullyLooted.push(item);
    }
  }

  this.emitLootResult(playerId, transactionId, true, undefined, undefined, successfullyLooted.length);
}
```

### Rate Limiting

Loot requests are rate-limited to prevent spam:

```typescript
// From HeadstoneEntity.ts
private lootRateLimiter = new Map<string, number>();
private readonly LOOT_RATE_LIMIT_MS = 100;

private handleLootRequest(data: LootRequestData): void {
  const now = Date.now();
  const lastRequest = this.lootRateLimiter.get(data.playerId) || 0;

  if (now - lastRequest < this.LOOT_RATE_LIMIT_MS) {
    this.emitLootResult(data.playerId, data.transactionId, false, "RATE_LIMITED");
    return;
  }

  this.lootRateLimiter.set(data.playerId, now);
  // ... process loot
}
```

### Clearing Death Lock

Death locks persist until all items are looted or despawn:

```typescript
async clearDeathLock(playerId: string): Promise<void> {
  // Remove from memory
  this.activeDeaths.delete(playerId);

  // Remove from database
  if (this.databaseSystem) {
    await this.databaseSystem.deleteDeathLockAsync(playerId);
  }
}

// Death lock is cleared when:
// 1. All items are looted from gravestone (CORPSE_EMPTY event)
// 2. Ground items despawn (timeout)
// 3. Gravestone expires and ground items despawn
```

<Warning>
**Death Lock Persistence**: The death lock is NOT cleared on respawn. It persists until all items are recovered or despawn. This enables crash recovery.
</Warning>

## Reconnect Validation

When a player reconnects, the system checks for active deaths:

```typescript
async hasActiveDeathLock(playerId: string): Promise<boolean> {
  // Check memory cache first
  if (this.activeDeaths.has(playerId)) return true;

  // Fallback to database (critical for crash recovery)
  if (this.databaseSystem) {
    const dbData = await this.databaseSystem.getDeathLockAsync(playerId);
    if (dbData) {
      // Restore to memory cache
      this.activeDeaths.set(playerId, dbData);
      return true;
    }
  }

  return false;
}
```

This prevents:
- Item duplication if server crashes mid-death
- Double death processing on reconnect
- Gravestone re-creation exploits

## Respawn Validation

The respawn system validates that players are actually dead before allowing respawn:

```typescript
// From ServerNetwork/index.ts
this.handlers["onRequestRespawn"] = (socket, _data) => {
  const playerEntity = socket.player;
  if (!playerEntity) return;

  // Validate player is actually dead before allowing respawn
  const healthComponent = playerEntity.data?.properties?.healthComponent;
  const isDead = healthComponent?.isDead === true;

      `[ServerNetwork] Rejected respawn request from ${playerEntity.id} - player is not dead`,

    return;
  }

  // Process respawn
  world.emit(EventType.PLAYER_RESPAWN_REQUEST, { playerId: playerEntity.id });
};
```

## Combat State Cleanup

When a player dies or respawns, all combat-related states are cleaned up across multiple systems:

### Death Event Handlers

```typescript
// From AggroSystem.ts
world.on(EventType.PLAYER_SET_DEAD, (data) => {
  if (data.isDead) {
    // Stop all mobs from chasing this player
    for (const [mobId, mobState] of this.mobStates) {
      if (mobState.currentTarget === playerId) {
        mobState.isChasing = false;
        mobState.currentTarget = null;
        mobState.isInCombat = false;
      }
      mobState.aggroTargets.delete(playerId);
    }
  }
});

// From CombatSystem.ts
world.on(EventType.PLAYER_RESPAWNED, (data) => {
  // Clear all combat states targeting this player
  const clearedAttackers = combatStateService.clearStatesTargeting(playerId);

  // Clear player's own combat state
  combatStateService.clearState(playerId);
});
```

### Multi-Layer Cleanup

The system uses **defense-in-depth** with three layers of cleanup:

1. **Event-based cleanup**: Death/respawn events trigger immediate cleanup
2. **Runtime guards**: Health checks in aggro/combat loops
3. **Timeout cleanup**: Stale states cleaned up after timeout

```typescript
// Layer 3: Runtime guard in aggro loop
const player = this.world.getPlayer(mobState.currentTarget);

// Check if player is dead - stop chasing immediately
const playerHealth = player.health;
if (playerHealth?.current !== undefined && playerHealth.current <= 0) {
  this.stopChasing(mobState);
  mobState.currentTarget = null;
  mobState.aggroTargets.delete(player.id);
  return;
}
```

## Crash Recovery System

The death system includes **enterprise-grade crash recovery** to prevent item loss when the server restarts mid-death.

### Recovery on Server Startup

```typescript
// From DeathStateManager.ts
async recoverUnfinishedDeaths(): Promise<void> {
  // Query all unrecovered deaths from database
  const unrecoveredDeaths = await this.databaseSystem.getUnrecoveredDeathsAsync();

  for (const death of unrecoveredDeaths) {
    // Recreate gravestones/ground items from death.items
    if (death.zoneType === "safe_area") {
      await this.spawnGravestoneForRecovery(death);
    } else {
      await this.spawnGroundItemsForRecovery(death);
    }

    // Mark as recovered to prevent duplicate recovery
    await this.databaseSystem.markDeathRecoveredAsync(death.playerId);
  }
}
```

### Recovery Database Queries

```sql
-- Get all unrecovered deaths (called on server startup)
SELECT * FROM player_deaths WHERE recovered = false;

-- Mark death as recovered after processing
UPDATE player_deaths SET recovered = true WHERE playerId = ?;
```

<Info>
**Crash Safety**: The death lock is created with full item data BEFORE clearing inventory. If the server crashes after clearing inventory but before spawning the gravestone, the items can be recovered from the death lock on restart.
</Info>

## Input Sanitization

The death system sanitizes all player-provided input to prevent injection attacks:

```typescript
// From PlayerDeathSystem.ts
function sanitizeKilledBy(killedBy: unknown): string {
  if (typeof killedBy !== "string" || !killedBy) {
    return "unknown";
  }

  // Normalize Unicode to NFKC form to prevent homograph attacks
  let normalized = killedBy.normalize("NFKC");

  let sanitized = "";
  for (const char of normalized) {
    const code = char.charCodeAt(0);

    // Skip zero-width characters (U+200B-U+200D, U+FEFF)
    if (code >= 0x200b && code <= 0x200d) continue;
    if (code === 0xfeff) continue;

    // Skip BiDi override characters (U+202A-U+202E)
    if (code >= 0x202a && code <= 0x202e) continue;

    // Skip control characters (0x00-0x1F and 0x7F)
    if (code < 32 || code === 127) continue;

    // Skip dangerous HTML characters
    if ("<>'\"&".includes(char)) continue;

    sanitized += char;
  }

  return sanitized.trim().substring(0, 64) || "unknown";
}
```

<Warning>
**Security**: The `killedBy` field is sanitized to prevent Unicode attacks, BiDi override exploits, and HTML injection.
</Warning>
