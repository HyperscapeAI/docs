## Overview

Hyperscape uses a centralized GPU-instanced particle system for high-performance visual effects. The system reduces draw calls by 97% and eliminates CPU-side particle animation code.

**Performance Impact:**
- Draw calls: ~150 → 4 per fishing spot
- FPS improvement: 65-70 → 120 on reference hardware
- CPU savings: ~450 lines of per-entity animation code eliminated

## Architecture

The particle system uses a centralized routing architecture with specialized sub-managers:

```
packages/shared/src/entities/managers/particleManager/
├── ParticleManager.ts        # Central router with ownership tracking
├── WaterParticleManager.ts   # Fishing spot particles (splash, bubble, shimmer, ripple)
└── GlowParticleManager.ts    # Glow billboards (altar, fire, torch presets)
```

### ParticleManager

Central router that dispatches particle events to specialized sub-managers based on resource type or particle category.

**Key Features:**
- Single entry point for all particle systems
- Routes events to correct sub-manager based on type
- Ownership tracking eliminates need for type hints on unregister/move
- Extensible design for future particle types (dust, smoke, blood, magic)

**Usage:**
```typescript
import { ParticleManager } from '@hyperscape/shared';

// ResourceSystem creates ParticleManager on client
const particleManager = new ParticleManager(scene);

// Register water particles (fishing spot)
particleManager.registerSpot({
  entityId: 'entity-123',
  position: { x: 10, y: 0, z: 20 },
  resourceType: 'fishing_spot',
  resourceId: 'fishing_spot_net'
});

// Per-frame update
particleManager.update(deltaTime, camera);

// Cleanup
particleManager.unregisterSpot('entity-123', 'fishing_spot');
particleManager.dispose();
```

### WaterParticleManager

GPU-instanced fishing spot effects using 4 InstancedMeshes with TSL NodeMaterials.

**Particle Layers:**
- **Splash**: Water droplets with parabolic arc trajectories
- **Bubble**: Rising bubbles with lateral wobble
- **Shimmer**: Surface sparkles with twinkle animation
- **Ripple**: Expanding ring waves

**Technical Details:**
- 4 InstancedMeshes replace ~150 individual meshes per fishing spot
- TSL NodeMaterials with InstancedBufferAttributes for per-particle data
- GPU-computed animations (parabolic arcs, wobble, twinkle, ring expansion)
- Per-instance data: spotPos (vec3), ageLifetime (vec2), angleRadius (vec2), dynamics (vec4)
- Vertex buffer budget: 7 of 8 max attributes per particle layer

**Fishing Spot Variants:**
- **Net**: Calm, gentle ripples (shallow water fishing)
  - 4 splash, 3 bubble, 3 shimmer particles
  - Burst interval: 5-10 seconds
- **Bait**: Medium activity (default)
  - 5 splash, 4 bubble, 4 shimmer particles
  - Burst interval: 3-7 seconds
- **Fly**: More active (river/moving water)
  - 8 splash, 5 bubble, 5 shimmer particles
  - Burst interval: 2-5 seconds

**Burst System:**
- Fish activity bursts fire 2-4 splash particles simultaneously
- Random burst center with slight spread
- Configurable intervals per variant

### GlowParticleManager

Instanced glow billboards for altars, fires, and torches.

**Presets:**
- **altar**: Mesh-aware sparks sampling geometry vertices (12 particles)
- **fire**: Rising flame particles with spread (8 particles)
- **torch**: Concentrated flame effect with tight spread (6 particles)

**Features:**
- Color override support (single hex or three-tone palette)
- Billboard orientation via camera right/up vectors
- Mesh-aware spark placement (samples geometry vertices for altar preset)
- Preset-aware respawn spread (tight for torch, wider for fire/altar)

**Usage:**
```typescript
// Register glow particles (altar, fire, torch)
particleManager.register('entity-456', {
  type: 'glow',
  preset: 'altar',
  position: { x: 15, y: 1, z: 25 },
  color: 0x00ffff,
  meshRoot: altarMesh
});
```

## Integration

### ResourceSystem Integration

ResourceSystem creates ParticleManager on client startup and forwards resource events:

```typescript
// From packages/shared/src/systems/shared/entities/ResourceSystem.ts

// CLIENT: Create centralized particle hub
if (!this.world.isServer) {
  const scene = this.world.stage?.scene;
  if (scene) {
    this.particleManager = new ParticleManager(scene);
    
    // Retroactively register any fishing spot entities created before this system started
    const existingEntities = this.world.entities?.getByType?.('resource') || [];
    for (const entity of existingEntities) {
      if (entity instanceof ResourceEntity && entity.config?.resourceType === 'fishing_spot') {
        entity.tryRegisterWithParticleManager();
      }
    }
  }
  
  // Listen for resource events and route them through the particle hub
  this.subscribe(EventType.RESOURCE_SPAWNED, (data) => {
    this.particleManager?.handleResourceEvent(data);
  });
}

// Per-frame update: drives all particle managers
update(dt: number): void {
  if (this.particleManager) {
    const camera = this.world.camera;
    if (camera) {
      this.particleManager.update(dt, camera);
    }
  }
}
```

### ResourceEntity Integration

ResourceEntity delegates particle lifecycle to ParticleManager:

```typescript
// From packages/shared/src/entities/world/ResourceEntity.ts

// Lazy registration pattern (retries if manager not ready during entity init)
public tryRegisterWithParticleManager(): boolean {
  if (this._registeredWithParticleManager) return true;
  
  const pm = this.getParticleManager();
  if (!pm) return false;
  
  const pos = this.getPosition();
  pm.registerSpot({
    entityId: this.id,
    position: { x: pos.x, y: pos.y, z: pos.z },
    resourceType: this.config.resourceType || '',
    resourceId: this.config.resourceId || ''
  });
  this._registeredWithParticleManager = true;
  return true;
}

// Cleanup
destroy(): void {
  if (this._registeredWithParticleManager) {
    const pm = this.getParticleManager();
    if (pm) {
      pm.unregisterSpot(this.id, this.config.resourceType || '');
    }
    this._registeredWithParticleManager = false;
  }
  // ... rest of cleanup
}
```

## GPU Instancing Details

### InstancedBufferAttributes

Each particle layer uses named InstancedBufferAttributes for per-particle data:

```typescript
// Per-instance data (7 of 8 max vertex attributes)
const spotPosAttr = new THREE.InstancedBufferAttribute(spotPosArr, 3);      // vec3
const ageLifetimeAttr = new THREE.InstancedBufferAttribute(ageLifetimeArr, 2); // vec2
const angleRadiusAttr = new THREE.InstancedBufferAttribute(angleRadiusArr, 2); // vec2
const dynamicsAttr = new THREE.InstancedBufferAttribute(dynamicsArr, 4);    // vec4

spotPosAttr.setUsage(THREE.DynamicDrawUsage);
ageLifetimeAttr.setUsage(THREE.DynamicDrawUsage);
angleRadiusAttr.setUsage(THREE.DynamicDrawUsage);
dynamicsAttr.setUsage(THREE.DynamicDrawUsage);

geometry.setAttribute('spotPos', spotPosAttr);
geometry.setAttribute('ageLifetime', ageLifetimeAttr);
geometry.setAttribute('angleRadius', angleRadiusAttr);
geometry.setAttribute('dynamics', dynamicsAttr);
```

### TSL Shaders

Particle animations are computed entirely on the GPU using Three.js Shading Language (TSL):

```typescript
// Parabolic arc for splash particles
const arcY = mul(peakHeight, mul(float(4), mul(t, sub(float(1), t))));
const ox = mul(cos(angle), radius);
const oz = mul(sin(angle), radius);
particleCenter = add(spotPos, vec3(ox, add(float(0.08), arcY), oz));

// Billboard orientation
const billboardOffset = add(
  mul(mul(localXY.x, size), camRight),
  mul(mul(localXY.y, size), camUp)
);
material.positionNode = add(particleCenter, billboardOffset);
```

## Performance Benefits

### Before Refactor

Each fishing spot created 10-21 individual THREE.Mesh objects:
- ~150 draw calls per frame
- Heavy per-frame CPU animation (trig, quaternion copies, opacity writes)
- ~450 lines of per-entity animation code
- FPS: 65-70 on reference hardware

### After Refactor

Centralized GPU-instanced rendering:
- 4 draw calls per frame (one per particle layer)
- GPU-driven animations via TSL shaders
- Zero CPU animation code per entity
- FPS: 120 on reference hardware

## Extensibility

The ParticleManager architecture is designed for easy extension:

**To add a new particle type (e.g. fire, magic, dust):**

1. Create a new sub-manager class in `particleManager/` folder
2. Instantiate it in the ParticleManager constructor
3. Add routing logic in register/unregister/move/handleEvent methods
4. Call its update() from ParticleManager.update()
5. Call its dispose() from ParticleManager.dispose()

**Example:**
```typescript
// Future: FireParticleManager for campfires, torches, explosions
export class FireParticleManager {
  constructor(scene: THREE.Scene) {
    // Create InstancedMeshes for flame layers
  }
  
  registerSpot(config: FireParticleConfig): void {
    // Allocate particle slots
  }
  
  update(dt: number, camera: THREE.Camera): void {
    // Update particle ages and positions
  }
  
  dispose(): void {
    // Cleanup GPU resources
  }
}
```
