## Overview

Hyperscape captures game music and sound effects in RTMP streams using PulseAudio virtual sinks. This allows viewers to hear in-game audio alongside video.

<Info>
  Audio streaming was added in commits 3b6f1ee, aab66b0, b9d2e41 (Feb 26, 2026).
</Info>

## How It Works

```mermaid
graph LR
    A[Chrome Browser] -->|Audio Output| B[PulseAudio Virtual Sink]
    B -->|Monitor| C[FFmpeg]
    C -->|RTMP| D[Twitch/Kick/X]
```

1. **Chrome** outputs audio to PulseAudio virtual sink (`chrome_audio`)
2. **PulseAudio** creates a monitor device (`chrome_audio.monitor`)
3. **FFmpeg** captures from the monitor device
4. **RTMP** streams audio to platforms

## PulseAudio Setup

### User Mode (Recommended)

The deployment uses user-mode PulseAudio for reliability:

```bash
# Setup runtime directory
export XDG_RUNTIME_DIR=/tmp/pulse-runtime
mkdir -p "$XDG_RUNTIME_DIR"
chmod 700 "$XDG_RUNTIME_DIR"

# Create PulseAudio config
mkdir -p /root/.config/pulse
cat > /root/.config/pulse/default.pa << 'EOF'
.fail
load-module module-null-sink sink_name=chrome_audio sink_properties=device.description="ChromeAudio"
set-default-sink chrome_audio
load-module module-native-protocol-unix auth-anonymous=1
EOF

# Start PulseAudio
pulseaudio --start --exit-idle-time=-1 --daemonize=yes

# Verify sink exists
pactl list short sinks | grep chrome_audio
```

### System Mode (Alternative)

For system-wide PulseAudio:

```bash
# Add root to pulse-access group
usermod -aG pulse-access root

# Create runtime directory
mkdir -p /run/pulse
chmod 777 /run/pulse

# Start system PulseAudio
pulseaudio --system --exit-idle-time=-1 --daemonize=yes

# Create virtual sink
pactl load-module module-null-sink sink_name=chrome_audio
pactl set-default-sink chrome_audio
```

### Required

```bash
# Enable audio capture
STREAM_AUDIO_ENABLED=true

# PulseAudio monitor device
PULSE_AUDIO_DEVICE=chrome_audio.monitor

# PulseAudio server socket
PULSE_SERVER=unix:/tmp/pulse-runtime/pulse/native

# Runtime directory
XDG_RUNTIME_DIR=/tmp/pulse-runtime
```

Chrome must be configured to use PulseAudio:

```typescript

const browser = await chromium.launch({

    PULSE_SINK: 'chrome_audio',
  }

```

## FFmpeg Audio Capture

### Basic Configuration

```bash
# Audio input from PulseAudio monitor
-f pulse -i chrome_audio.monitor

# Audio codec
-c:a aac -b:a 128k -ar 44100
```

### Advanced Configuration (Stability)

The deployment uses advanced FFmpeg settings for audio stability (commit b9d2e41):

```bash
# Audio input with buffering and sync
-f pulse -i chrome_audio.monitor \
-thread_queue_size 1024 \
-use_wallclock_as_timestamps 1 \
-filter:a aresample=async=1000:first_pts=0

# Audio codec
-c:a aac -b:a 128k -ar 44100
```

**What Each Flag Does:**

| Flag | Purpose |
|------|---------|
| `-thread_queue_size 1024` | Prevent buffer underruns |
| `-use_wallclock_as_timestamps 1` | Real-time timing for PulseAudio |
| `-aresample=async=1000:first_pts=0` | Recover from audio drift >22ms |

### Video Buffering

Video buffering was also increased for better A/V sync:

```bash
# Video input with buffering
-thread_queue_size 1024  # Increased from 512
```

### Removed Flags

The `-shortest` flag was removed as it caused audio dropouts:

```bash
# ❌ Old: Caused audio dropouts during video buffering
-shortest

# ✅ New: No -shortest flag
# Let audio and video run independently
```

## Graceful Fallback

If PulseAudio is unavailable, FFmpeg falls back to silent audio:

```bash
# Check if PulseAudio is running
if pactl info &>/dev/null && pactl list sinks | grep -q chrome_audio; then
    AUDIO_INPUT="-f pulse -i chrome_audio.monitor"
else
    echo "WARNING: PulseAudio not available, using silent audio"
    AUDIO_INPUT="-f lavfi -i anullsrc"
fi

# Use in FFmpeg command
ffmpeg $AUDIO_INPUT -c:a aac ...
```

## Troubleshooting

### No Audio in Stream

**Symptom:** Stream has video but no audio

**Diagnosis:**
```bash
# 1. Check PulseAudio
pactl info
# Should show: Server String: unix:/tmp/pulse-runtime/pulse/native

# 2. Check virtual sink
pactl list short sinks | grep chrome_audio
# Should show: chrome_audio sink

# 3. Check monitor device
pactl list short sources | grep chrome_audio.monitor
# Should show: chrome_audio.monitor source

# 4. Test capture
ffmpeg -f pulse -i chrome_audio.monitor -t 5 test.wav
ffplay test.wav
```

**Solutions:**

**If PulseAudio not running:**
```bash
pulseaudio --start --exit-idle-time=-1 --daemonize=yes
```

**If virtual sink missing:**
```bash
pactl load-module module-null-sink sink_name=chrome_audio
pactl set-default-sink chrome_audio
```

**If permissions error:**
```bash
# Add root to pulse-access group
usermod -aG pulse-access root

# Create runtime directory
mkdir -p /run/pulse
chmod 777 /run/pulse
```

### Audio Dropouts

**Symptom:** Intermittent audio dropouts or silence

**Cause:** Buffer underruns

**Solution:** Update to latest code (commit b9d2e41 fixed this):

```bash
# Increased audio buffering
-thread_queue_size 1024  # Prevents buffer underruns

# Wall clock timestamps
-use_wallclock_as_timestamps 1  # Real-time timing

# Async resampling
-filter:a aresample=async=1000:first_pts=0  # Recover from drift
```

### Audio Desync

**Symptom:** Audio gradually drifts out of sync with video

**Cause:** Timing issues between audio and video streams

**Solution:** Update to latest code (commit b9d2e41 fixed this):

```bash
# Use wall clock timestamps for accurate timing
-use_wallclock_as_timestamps 1

# Async resampling to resync when drift exceeds 22ms
-filter:a aresample=async=1000:first_pts=0

# Increased video buffering for better A/V sync
-thread_queue_size 1024  # Video input
```

### PulseAudio Permission Denied

**Symptom:** FFmpeg fails with "Permission denied" when accessing PulseAudio

**Cause:** Insufficient permissions for PulseAudio socket

**Solution:**

```bash
# Add root to pulse-access group
usermod -aG pulse-access root

# Create /run/pulse with proper permissions
mkdir -p /run/pulse
chmod 777 /run/pulse

# Export PULSE_SERVER
export PULSE_SERVER=unix:/tmp/pulse-runtime/pulse/native

# Restart PulseAudio
pulseaudio --kill
pulseaudio --start --exit-idle-time=-1 --daemonize=yes
```

### Chrome Not Using PulseAudio

**Symptom:** No audio activity in PulseAudio when game is playing

**Diagnosis:**
```bash
# Monitor PulseAudio activity
pactl subscribe

# Play game audio
# Should see events like:
# Event 'new' on sink-input #1
# Event 'change' on sink #0
```

**Solution:** Verify Chrome environment variables:

```bash
# Check Chrome is using PulseAudio
echo $PULSE_SERVER
# Should be: unix:/tmp/pulse-runtime/pulse/native

echo $PULSE_SINK
# Should be: chrome_audio
```

**Restart Chrome with correct environment:**
```bash
export PULSE_SERVER=unix:/tmp/pulse-runtime/pulse/native
export PULSE_SINK=chrome_audio
# Restart streaming
```

### deploy-vast.sh

The deployment script automatically configures PulseAudio:

```bash
#!/bin/bash
# PulseAudio Setup

# 1. Kill existing PulseAudio
pulseaudio --kill 2>/dev/null || true
pkill -9 pulseaudio 2>/dev/null || true
sleep 2

# 2. Setup runtime directory
export XDG_RUNTIME_DIR=/tmp/pulse-runtime
mkdir -p "$XDG_RUNTIME_DIR"
chmod 700 "$XDG_RUNTIME_DIR"

# 3. Create config
mkdir -p /root/.config/pulse
cat > /root/.config/pulse/default.pa << 'EOF'
.fail
load-module module-null-sink sink_name=chrome_audio sink_properties=device.description="ChromeAudio"
set-default-sink chrome_audio
load-module module-native-protocol-unix auth-anonymous=1
EOF

# 4. Start PulseAudio
pulseaudio --start --exit-idle-time=-1 --daemonize=yes
sleep 3

# 5. Verify sink exists
if pactl list short sinks | grep -q chrome_audio; then
    echo "✓ chrome_audio sink is available"
else
    echo "Creating chrome_audio sink manually..."
    pactl load-module module-null-sink sink_name=chrome_audio
    pactl set-default-sink chrome_audio
fi

# 6. Export for PM2
export PULSE_SERVER=unix:$XDG_RUNTIME_DIR/pulse/native
```

## Performance Impact

### CPU Usage

Audio capture adds minimal CPU overhead:

- **PulseAudio:** ~1-2% CPU
- **FFmpeg AAC encoding:** ~5-10% CPU
- **Total overhead:** ~7-12% CPU

### Bandwidth

Audio adds to stream bandwidth:

- **AAC 128kbps:** ~16 KB/s
- **Total stream:** ~600 KB/s (video) + 16 KB/s (audio) = ~616 KB/s

### Latency

Audio capture adds minimal latency:

- **PulseAudio buffering:** ~20-50ms
- **FFmpeg encoding:** ~10-20ms
- **Total audio latency:** ~30-70ms
