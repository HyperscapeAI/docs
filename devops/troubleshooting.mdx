## Common Issues

### Characters Vanishing

**Symptom**: Characters disappear after page refresh

**Cause**: Missing Privy credentials—each refresh creates a new anonymous identity

**Solution**: Configure Privy authentication:

```bash
# packages/client/.env
PUBLIC_PRIVY_APP_ID=your-app-id

# packages/server/.env
PUBLIC_PRIVY_APP_ID=your-app-id
PRIVY_APP_SECRET=your-app-secret
```

### Assets Not Loading

**Symptom**: 404 errors for models/avatars

**Causes**:
1. CDN container not running (local development)
2. Manifests not fetched from CDN (production)
3. Wrong CDN URL configured

**Solutions**:

**Local development:**
```bash
bun run cdn:up
```

Or ensure you're using `bun run dev` which starts it automatically.

**Production:**
1. Verify `PUBLIC_CDN_URL` is set correctly in server environment
2. Check manifests are publicly accessible:
   ```bash
   curl https://assets.hyperscape.club/manifests/items.json
   ```
3. Check server logs for manifest fetch errors:
   ```
   [Config] 📥 Fetching manifests from CDN: https://assets.hyperscape.club
   [Config] ✅ items.json updated
   ```

**Manifest fetch failures:**
- Server logs "Failed to fetch manifests from CDN"
- Verify CDN URL is accessible
- Check CORS headers allow server origin
- In development, manifests can be local (skips CDN fetch)

### Database Schema Errors

**Symptom**: Errors about missing columns or tables

**Cause**: Schema changed but migrations not run

**Solution**:

```bash
cd packages/server
bunx drizzle-kit push
```

For a complete reset (destroys data):

```bash
docker stop hyperscape-postgres
docker rm hyperscape-postgres
docker volume rm hyperscape-postgres-data
docker volume rm server_postgres-data
bun run dev
```

### Port Conflicts

**Symptom**: "Port already in use" errors

**Solution**: Kill processes on conflicting ports:

```bash
lsof -ti:3333 | xargs kill -9   # Client
lsof -ti:5555 | xargs kill -9   # Server
lsof -ti:8080 | xargs kill -9   # CDN
lsof -ti:4001 | xargs kill -9   # ElizaOS
```

### Build Errors

**Symptom**: Compilation fails

**Solution**: Clean rebuild:

```bash
bun run clean
rm -rf node_modules packages/*/node_modules
bun install
bun run build
```

### PhysX Build Fails

**Symptom**: Errors during PhysX compilation

**Cause**: PhysX WASM build requires emscripten

**Solution**: PhysX is pre-built and committed. If you must rebuild:

```bash
cd packages/physx-js-webidl
./make.sh   # Requires emscripten toolchain
```

### Tests Failing

**Symptom**: Tests timeout or fail unexpectedly

**Causes**:
- Server running during tests
- Stale test data
- Port conflicts

**Solution**:

```bash
# Stop any running servers
lsof -ti:5555 | xargs kill -9

# Check logs
ls /logs/

# Run tests
npm test
```

### WebSocket Connection Failed

**Symptom**: Can't connect to game server

**Causes**:
- Server not running
- Wrong port configuration
- Firewall blocking
- CORS origin not allowed

**Solutions**:

1. **Verify server is running:**
   ```bash
   lsof -i:5555
   ```

2. **Check client configuration:**
   ```bash
   # packages/client/.env
   PUBLIC_WS_URL=ws://localhost:5555/ws  # Development
   PUBLIC_WS_URL=wss://hyperscape-production.up.railway.app/ws  # Production
   ```

3. **Check CORS configuration:**
   - Verify your origin is in the allowlist (see `packages/server/src/startup/http-server.ts`)
   - For custom domains, set `PUBLIC_APP_URL` in server environment

4. **Check browser console:**
   - Look for CORS errors
   - Verify WebSocket URL is correct
   - Check for SSL/TLS certificate issues (wss:// requires valid cert)

### CORS Errors

**Symptom**: Browser console shows "CORS policy" errors

**Cause**: Client origin not in server's CORS allowlist

**Solution**:

**For Cloudflare Pages preview deployments:**
- Automatically allowed via regex: `/^https?:\/\/.+\.hyperscape\.pages\.dev$/`

**For custom domains:**
```bash
# In packages/server/.env
PUBLIC_APP_URL=https://yourdomain.com
```

**For localhost with custom port:**
- Automatically allowed via regex: `/^https?:\/\/localhost:\d+$/`

**Verify allowed origins:**
Check server logs on startup:
```
[HTTP] ✅ CORS configured for: https://hyperscape.club, https://www.hyperscape.club, ...
```

### Hot Reload Not Working

**Symptom**: Changes don't appear in browser

**Causes**:
- Build cache stale
- Wrong directory

**Solution**:

```bash
bun run dev:reset
```

### Railway Deployment Issues

**Issue**: Build fails with "lockfile had changes, but lockfile is frozen"

**Solution**: Regenerate lockfile locally and commit:
```bash
bun install
git add bun.lock
git commit -m "chore: update bun.lock"
git push
```

**Issue**: Frontend not loading (503 "Frontend not available")

**Cause**: Client build not copied to server's public directory

**Solution**: Verify `nixpacks.toml` build phase includes client build:
```toml
[phases.build]
cmds = [
  "bun run build:shared",
  "bun run build:server",
  "cp -r packages/client/dist/* packages/server/public/"
]
```

**Issue**: Manifests not loading from CDN

**Symptoms**:
- Server logs: "Failed to fetch manifests from CDN"
- Game features not working (no items, NPCs, etc.)

**Solutions**:
1. Verify `PUBLIC_CDN_URL` environment variable is set
2. Check manifests are publicly accessible:
   ```bash
   curl https://assets.hyperscape.club/manifests/items.json
   ```
3. Verify CORS headers allow Railway origin
4. Check Railway logs for detailed error messages

### Cloudflare Pages Issues

**Issue**: Environment variables not updating

**Cause**: Cloudflare Pages caches environment variables

**Solution**:
1. Update variables in Pages dashboard
2. Trigger new deployment (push to branch or manual redeploy)
3. Clear browser cache

**Issue**: Preview deployment CORS errors

**Cause**: Preview URL not in CORS allowlist

**Solution**: Preview deployments are automatically allowed via regex:
```typescript
/^https?:\/\/.+\.hyperscape\.pages\.dev$/
```

If still failing, check server logs to verify the pattern matches your preview URL.
