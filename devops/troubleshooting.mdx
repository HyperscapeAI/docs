## Common Issues

### Characters Vanishing

**Symptom**: Characters disappear after page refresh

**Cause**: Missing Privy credentials—each refresh creates a new anonymous identity

**Solution**: Configure Privy authentication:

```bash
# packages/client/.env
PUBLIC_PRIVY_APP_ID=your-app-id

# packages/server/.env
PUBLIC_PRIVY_APP_ID=your-app-id
PRIVY_APP_SECRET=your-app-secret
```

### Assets Not Loading

**Symptom**: 404 errors for models/avatars

**Cause**: CDN container not running or manifests not fetched

**Solution**:

```bash
bun run cdn:up
```

Or ensure you're using `bun run dev` which starts it automatically.

**Debug endpoint**: Check what files are available:

```bash
curl http://localhost:5555/debug/public
```

This shows the contents of the `public/` directory and helps diagnose missing files.

### Frontend Not Available (503 Error)

**Symptom**: Accessing `http://localhost:5555/` returns "Frontend not available"

**Cause**: Client build not copied to server's `public/` directory

**Solution**:

```bash
# Build client and copy to server
bun run build:client
cp -r packages/client/dist/* packages/server/public/

# Or use production start which handles this
bun start
```

**Railway/Production**: The build process automatically copies client build to server public directory via `nixpacks.toml`.

### Database Schema Errors

**Symptom**: Errors about missing columns or tables

**Cause**: Schema changed but migrations not run

**Solution**:

```bash
cd packages/server
bunx drizzle-kit push
```

For a complete reset (destroys data):

```bash
docker stop hyperscape-postgres
docker rm hyperscape-postgres
docker volume rm hyperscape-postgres-data
docker volume rm server_postgres-data
bun run dev
```

### Port Conflicts

**Symptom**: "Port already in use" errors

**Solution**: Kill processes on conflicting ports:

```bash
lsof -ti:3333 | xargs kill -9   # Client
lsof -ti:5555 | xargs kill -9   # Server
lsof -ti:8080 | xargs kill -9   # CDN
lsof -ti:4001 | xargs kill -9   # ElizaOS
```

### Build Errors

**Symptom**: Compilation fails

**Solution**: Clean rebuild:

```bash
bun run clean
rm -rf node_modules packages/*/node_modules
bun install
bun run build
```

### PhysX Build Fails

**Symptom**: Errors during PhysX compilation

**Cause**: PhysX WASM build requires emscripten

**Solution**: PhysX is pre-built and committed. If you must rebuild:

```bash
cd packages/physx-js-webidl
./make.sh   # Requires emscripten toolchain
```

### Tests Failing

**Symptom**: Tests timeout or fail unexpectedly

**Causes**:
- Server running during tests
- Stale test data
- Port conflicts

**Solution**:

```bash
# Stop any running servers
lsof -ti:5555 | xargs kill -9

# Check logs
ls /logs/

# Run tests
npm test
```

### WebSocket Connection Failed

**Symptom**: Can't connect to game server

**Causes**:
- Server not running
- Wrong port configuration
- Firewall blocking
- CORS origin not allowed

**Solution**:

1. Verify server is running: `lsof -i:5555`
2. Check client config: `PUBLIC_WS_URL`
3. Ensure no firewall blocks
4. Check browser console for CORS errors

### CORS Errors in Production

**Symptom**: API requests fail with CORS errors in browser console

**Cause**: Your deployment domain is not in the CORS allowlist

**Solution**:

Add your domain to `packages/server/src/startup/http-server.ts`:

```typescript
const allowedOrigins = [
  // ... existing origins
  "https://your-custom-domain.com",
];
```

**Current Allowed Origins**:
- `https://hyperscape.club`
- `https://www.hyperscape.club`
- `https://hyperscape.pages.dev`
- `https://*.hyperscape.pages.dev` (preview deployments)
- `http://localhost:*` (any port)
- `https://*.up.railway.app`

### Railway Deployment Failures

**Symptom**: Railway build fails or crashes on startup

**Common Causes & Solutions**:

1. **Lockfile frozen error**:
   ```
   lockfile had changes, but lockfile is frozen
   ```
   **Solution**: Regenerate lockfile locally and commit:
   ```bash
   bun install
   git add bun.lock
   git commit -m "fix: update bun.lock"
   ```

2. **Frontend not building**:
   ```
   No index.html found in public directory
   ```
   **Solution**: Verify build commands in `nixpacks.toml`:
   ```toml
   [phases.build]
   cmds = [
     "bun run build:shared",
     "bun run build:server",
     "cd packages/client && bun run build",
     "cp -r packages/client/dist/* packages/server/public/"
   ]
   ```

3. **Manifest fetch failures**:
   ```
   Failed to fetch manifests from CDN
   ```
   **Solution**: Verify `PUBLIC_CDN_URL` is set and accessible:
   ```bash
   curl https://assets.hyperscape.club/manifests/items.json
   ```

4. **Database connection timeout**:
   ```
   Error: connect ETIMEDOUT
   ```
   **Solution**: Ensure Railway PostgreSQL service is running and `DATABASE_URL` is set correctly.

### Cloudflare Pages Build Failures

**Symptom**: Pages deployment fails

**Common Causes**:

1. **Wrong build directory**:
   - Build output must be in `packages/client/dist`
   - Set "Build output directory" to `packages/client/dist`

2. **Missing environment variables**:
   - Ensure all `PUBLIC_*` variables are set in Pages dashboard
   - Check Settings → Environment variables

3. **Build command fails**:
   ```bash
   # Correct build command:
   cd packages/client && bun install && bun run build
   ```

### Hot Reload Not Working

**Symptom**: Changes don't appear in browser

**Causes**:
- Build cache stale
- Wrong directory

**Solution**:

```bash
bun run dev:reset
```

## Deployment Issues

### Railway Build Failures

**Symptom**: Railway deployment fails during build phase

**Common Causes**:
- Lockfile out of sync with package.json
- Missing environment variables
- Build timeout (exceeds Railway limits)

**Solutions**:

```bash
# Regenerate lockfile locally
bun install
git add bun.lock
git commit -m "fix: update bun.lock"
git push

# Check Railway build logs for specific errors
# Verify nixpacks.toml configuration
# Ensure all required env vars are set in Railway dashboard
```

### Frontend Not Serving

**Symptom**: Railway server returns 503 "Frontend not available"

**Cause**: Client build not copied to server's `public/` directory

**Solution**: Verify build phase in `nixpacks.toml` includes:

```toml
[phases.build]
cmds = [
  "bun run build:shared",
  "bun run build:client",  # Must build client
  "bun run build:server",
  "mkdir -p packages/server/public",
  "cp -r packages/client/dist/* packages/server/public/"  # Copy client to server
]
```

### CORS Errors in Production

**Symptom**: Browser console shows CORS errors when connecting to API

**Cause**: Frontend domain not in server's CORS allowlist

**Solution**: The server automatically allows these domains:
- `https://hyperscape.club`
- `https://www.hyperscape.club`
- `https://hyperscape.pages.dev`
- `https://*.hyperscape.pages.dev` (preview deployments)
- `https://*.up.railway.app` (Railway deployments)

For custom domains, add to `allowedOrigins` in `packages/server/src/startup/http-server.ts` or set `PUBLIC_APP_URL` environment variable.

### Manifest Fetch Failures

**Symptom**: Server logs show "Failed to fetch manifests from CDN"

**Cause**: CDN URL incorrect or CDN not accessible

**Solution**:

1. Verify `PUBLIC_CDN_URL` environment variable is set correctly
2. Test CDN accessibility: `curl $PUBLIC_CDN_URL/manifests/items.json`
3. Check Railway logs for specific fetch errors
4. Ensure manifests are deployed to CDN

**Fallback**: Server will use local manifests if CDN fetch fails (in development).

### WebSocket Connection Refused (Production)

**Symptom**: Client can't connect to `wss://` WebSocket

**Causes**:
- Railway service not exposing WebSocket port
- Client using wrong WebSocket URL
- SSL/TLS certificate issues

**Solution**:

1. Verify Railway service is running: Check Railway dashboard
2. Test WebSocket: `wscat -c wss://hyperscape-production.up.railway.app/ws`
3. Ensure client's `PUBLIC_WS_URL` matches server domain
4. Railway automatically handles SSL for WebSocket upgrades
