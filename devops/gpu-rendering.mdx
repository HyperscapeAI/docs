## Overview

Hyperscape streaming requires **hardware GPU rendering** for WebGPU support. The game uses Three.js Shading Language (TSL) which compiles to WGSL and requires WebGPU - software rendering is not supported.

The deployment system automatically detects available GPU access and configures the optimal rendering mode.

## Rendering Modes

### Xorg Mode (Preferred)

**Best for:** Servers with DRM/DRI device access

**Requirements:**
- NVIDIA GPU with drivers installed
- `/dev/dri/card0` or similar DRM device
- Xorg server packages

**Configuration:**
```bash
# Auto-detected by deploy-vast.sh
GPU_RENDERING_MODE=xorg
DISPLAY=:99
DUEL_CAPTURE_USE_XVFB=false
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json
```

**How it works:**
1. Deploy script detects DRI devices
2. Installs `xserver-xorg-core` and NVIDIA Xorg drivers
3. Generates headless Xorg config with GPU BusID
4. Starts Xorg on display :99
5. Chrome uses NVIDIA GPU via Vulkan for WebGPU rendering

**Xorg Configuration:**
```bash
# Auto-generated by deploy-vast.sh
Section "ServerLayout"
    Identifier     "Layout0"
    Screen      0  "Screen0"
EndSection

Section "Device"
    Identifier     "Device0"
    Driver         "nvidia"
    BusID          "PCI:1:0:0"  # Auto-detected from nvidia-smi
    Option         "AllowEmptyInitialConfiguration" "True"
    Option         "UseDisplayDevice" "None"
EndSection

Section "Screen"
    Identifier     "Screen0"
    Device         "Device0"
    DefaultDepth    24
    SubSection     "Display"
        Depth       24
        Virtual    1920 1080
    EndSubSection
EndSection
```

**Verification:**
```bash
# Check Xorg is running
ps aux | grep Xorg

# Test display
DISPLAY=:99 xdpyinfo

# Check for software rendering fallback (bad)
grep -i "swrast" /var/log/Xorg.99.log
```

### Xvfb + Vulkan Mode (Fallback)

**Best for:** Containers without DRM but with NVIDIA GPU

**Requirements:**
- NVIDIA GPU with Vulkan support
- Xvfb (virtual framebuffer)
- NVIDIA Vulkan ICD

**Configuration:**
```bash
# Auto-detected by deploy-vast.sh
GPU_RENDERING_MODE=xvfb-vulkan
DISPLAY=:99
DUEL_CAPTURE_USE_XVFB=true
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json
STREAM_CAPTURE_ANGLE=vulkan
```

**How it works:**
1. Xvfb provides X11 protocol (virtual framebuffer)
2. Chrome uses NVIDIA GPU for rendering via ANGLE/Vulkan
3. CDP captures frames from Chrome's internal GPU rendering, not X framebuffer
4. Supports WebGPU without DRM/DRI access

**Start Xvfb:**
```bash
Xvfb :99 -screen 0 1920x1080x24 -ac +extension GLX +render -noreset &
export DISPLAY=:99
```

**Verification:**
```bash
# Check Xvfb is running
ps aux | grep Xvfb

# Test display
DISPLAY=:99 xdpyinfo

# Verify Vulkan works
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json vulkaninfo --summary
```

### Headless EGL Mode (Last Resort)

**Best for:** Containers without X server or DRM access

**Requirements:**
- NVIDIA GPU with EGL support
- Chrome's new headless mode
- NVIDIA EGL library

**Configuration:**
```bash
# Auto-detected by deploy-vast.sh
GPU_RENDERING_MODE=headless
DISPLAY=
STREAM_CAPTURE_HEADLESS=new
STREAM_CAPTURE_USE_EGL=true
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json
```

**How it works:**
1. Chrome runs in new headless mode (`--headless=new`)
2. Uses EGL for GPU access without X server (`--use-gl=egl`)
3. Ozone platform set to headless (`--ozone-platform=headless`)
4. NVIDIA GPU used for WebGPU via Vulkan

**Chrome Flags:**
```bash
--headless=new
--use-gl=egl
--ozone-platform=headless
--use-angle=vulkan
--enable-unsafe-webgpu
```

**Verification:**
```bash
# Check EGL library exists
ls -la /usr/lib/x86_64-linux-gnu/libEGL_nvidia.so.0

# Test Chrome headless
google-chrome-unstable --headless=new --use-gl=egl --print-to-pdf=test.pdf https://google.com
```

<Warning>
Headless EGL mode may not support WebGPU on all systems. Xorg or Xvfb modes are preferred.
</Warning>

## Unsupported Modes

### Software Rendering (Not Supported)

The following modes are **explicitly rejected** because they're too slow for streaming:

- **Xvfb alone** (software rendering, no GPU)
- **SwiftShader** (CPU-based Vulkan)
- **Lavapipe** (Mesa software Vulkan)
- **Chrome swrast** (software rasterizer)

**Why not supported:**
- WebGPU requires hardware GPU
- Software rendering is 10-100x slower
- Cannot maintain 30 FPS for streaming
- Causes frame drops and stuttering

## GPU Detection Flow

The `deploy-vast.sh` script automatically detects and configures GPU rendering:

```bash
# 1. Check for NVIDIA GPU
nvidia-smi || exit 1

# 2. Force NVIDIA-only Vulkan ICD
export VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json

# 3. Try Xorg if DRI devices exist
if [ -d "/dev/dri" ] && [ -e "/dev/dri/card0" ]; then
    # Install Xorg and NVIDIA drivers
    # Generate Xorg config with GPU BusID
    # Start Xorg on :99
    # Verify it's using NVIDIA (not swrast)
    if xorg_using_nvidia; then
        RENDERING_MODE=xorg
        DISPLAY=:99
    fi
fi

# 4. Fallback to Xvfb + Vulkan
if [ "$RENDERING_MODE" = "unknown" ]; then
    Xvfb :99 -screen 0 1920x1080x24 &
    if xvfb_started; then
        RENDERING_MODE=xvfb-vulkan
        DISPLAY=:99
        DUEL_CAPTURE_USE_XVFB=true
    fi
fi

# 5. Last resort: Headless EGL
if [ "$RENDERING_MODE" = "unknown" ]; then
    RENDERING_MODE=headless
    DISPLAY=
    STREAM_CAPTURE_HEADLESS=new
    STREAM_CAPTURE_USE_EGL=true
fi
```

## Chrome Configuration

### Chrome Dev Channel

**Why Chrome Dev:**
- WebGPU enabled by default
- Latest Vulkan/ANGLE support
- Better GPU compatibility

**Installation:**
```bash
wget -q -O - https://dl.google.com/linux/linux_signing_key.pub | apt-key add -
echo "deb [arch=amd64] http://dl.google.com/linux/chrome/deb/ stable main" > /etc/apt/sources.list.d/google-chrome.list
apt-get update
apt-get install -y google-chrome-unstable
```

**Playwright Configuration:**
```typescript
// From packages/server/src/streaming/browser-capture.ts
const browser = await chromium.launch({
  channel: 'chrome-dev',  // Uses google-chrome-unstable
  headless: false,        // Headful with Xvfb/Xorg
  args: [
    '--use-gl=angle',
    '--use-angle=vulkan',
    '--enable-unsafe-webgpu',
    '--disable-gpu-sandbox',
    '--no-sandbox'
  ]
});
```

### ANGLE Backend Selection

**Vulkan Backend (Default):**
```bash
STREAM_CAPTURE_ANGLE=vulkan
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json
```

**GL Backend (Fallback):**
```bash
STREAM_CAPTURE_ANGLE=gl
```

**When to use GL:**
- Vulkan ICD is broken or misconfigured
- NVIDIA driver issues
- Container without Vulkan support

### Headless Mode Configuration

**Important:** Playwright's `headless` option only accepts boolean, not string.

For Chrome's new headless mode:
```typescript
// ❌ Wrong - Playwright rejects string
const browser = await chromium.launch({
  headless: 'new'  // TypeError
});

// ✅ Correct - Pass headless=false and add --headless=new to args
const browser = await chromium.launch({
  headless: false,
  args: ['--headless=new']
});
```

**Environment Variables:**
```bash
# For Xorg/Xvfb mode
STREAM_CAPTURE_HEADLESS=false

# For Chrome new headless mode
STREAM_CAPTURE_HEADLESS=new
```

## Vulkan Configuration

### Force NVIDIA ICD

**Problem:** Mesa Vulkan ICDs conflict with NVIDIA ICD, causing initialization failures.

**Solution:** Force only NVIDIA ICD:

```bash
export VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json
```

**Why this works:**
- Isolates NVIDIA ICD from conflicting Mesa ICDs
- Prevents libGLX_nvidia.so.0 driver errors
- Ensures hardware Vulkan for WebGPU

**Verification:**
```bash
# Should show only NVIDIA GPU
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json vulkaninfo --summary
```

### Vulkan Troubleshooting

**Check Vulkan support:**
```bash
vulkaninfo --summary
```

**Check NVIDIA driver:**
```bash
nvidia-smi
```

**Check ICD files:**
```bash
ls -la /usr/share/vulkan/icd.d/
cat /usr/share/vulkan/icd.d/nvidia_icd.json
```

**Common Issues:**

| Issue | Cause | Fix |
|-------|-------|-----|
| `vkCreateInstance failed` | Conflicting Mesa ICDs | Set `VK_ICD_FILENAMES` |
| `libGLX_nvidia.so.0 not found` | Broken NVIDIA ICD config | Use GL ANGLE backend |
| `No Vulkan devices` | NVIDIA driver not loaded | Install nvidia-driver |

### GPU Rendering

```bash
# Rendering mode (auto-detected)
GPU_RENDERING_MODE=xorg              # xorg, xvfb-vulkan, or headless

# X Display
```

### Chrome Capture

```bash
# Capture mode
STREAM_CAPTURE_MODE=cdp              # cdp (default), mediarecorder, or webcodecs

# Headless mode
STREAM_CAPTURE_HEADLESS=false        # false (Xorg/Xvfb), new (headless EGL)

# EGL mode
STREAM_CAPTURE_USE_EGL=false         # true for headless EGL

# Chrome channel
STREAM_CAPTURE_CHANNEL=chrome-dev    # Use Chrome Dev for WebGPU

# ANGLE backend
STREAM_CAPTURE_ANGLE=vulkan          # vulkan (default) or gl
```

## Troubleshooting

### Xorg Fails to Start

**Check logs:**
```bash
cat /var/log/Xorg.99.log | grep -E "(EE)|(WW)"
```

**Common issues:**

**No screens found:**
```
(EE) No screens found(EE)
```
**Fix:** DRI devices not available, fallback to Xvfb or headless EGL

**NVIDIA driver failed:**
```
(EE) NVIDIA: Failed to initialize the NVIDIA GPU
```
**Fix:** Check `nvidia-smi`, reinstall drivers, or use GL ANGLE backend

**Software rendering (swrast):**
```
(II) IGLX: Loaded and initialized swrast
```
**Fix:** NVIDIA driver failed, deploy script will auto-fallback to headless EGL

### Vulkan Not Working

**Check Vulkan:**
```bash
vulkaninfo --summary
```

**No Vulkan devices:**
```bash
# Install Vulkan tools
apt-get install -y vulkan-tools

# Check ICD files
ls -la /usr/share/vulkan/icd.d/

# Force NVIDIA ICD
export VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json
vulkaninfo --summary
```

**Conflicting ICDs:**
```bash
# Remove Mesa ICDs (they conflict with NVIDIA)
rm /usr/share/vulkan/icd.d/lvp_icd.*.json
rm /usr/share/vulkan/icd.d/radeon_icd.*.json
```

### WebGPU Not Available

**Check Chrome flags:**
```bash
# Test WebGPU in Chrome
google-chrome-unstable \
  --headless=new \
  --use-gl=angle \
  --use-angle=vulkan \
  --enable-unsafe-webgpu \
  --print-to-pdf=test.pdf \
  https://webgpu.io
```

**Check browser console:**
```javascript
// In browser console
navigator.gpu  // Should be defined
```

**Common issues:**

| Issue | Cause | Fix |
|-------|-------|-----|
| `navigator.gpu` undefined | WebGPU disabled | Add `--enable-unsafe-webgpu` flag |
| `requestAdapter() returns null` | No GPU backend | Check Vulkan/GL ANGLE |
| `adapter.requestDevice() fails` | GPU initialization failed | Check Xorg/Xvfb logs |

### Performance Issues

**Low FPS (<20):**
- Check GPU usage: `nvidia-smi`
- Verify hardware rendering: `grep -i swrast /var/log/Xorg.99.log`
- Check Chrome is using GPU: `chrome://gpu` (if accessible)

**High memory usage:**
- Reduce capture resolution: `STREAM_CAPTURE_WIDTH=960 STREAM_CAPTURE_HEIGHT=540`
- Lower JPEG quality: `STREAM_CDP_QUALITY=60`
- Reduce FPS: `STREAM_FPS=24`

**Frame drops:**
- Check FFmpeg backpressure in logs
- Increase bitrate buffer: `STREAM_VIDEO_BITRATE_KBPS=6000`
- Use hardware encoder: `FFMPEG_HWACCEL=nvidia`

### Auto-Configuration

The deployment script automatically:
1. Detects GPU and driver version
2. Checks for DRI/DRM device access
3. Configures optimal rendering mode
4. Installs required dependencies
5. Verifies GPU rendering works

**No manual configuration needed** - just run the deploy script.
