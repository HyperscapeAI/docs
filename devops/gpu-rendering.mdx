## Overview

Hyperscape's streaming system requires **hardware GPU rendering** for WebGPU support. The game uses Three.js Shading Language (TSL) which compiles to WGSL and requires WebGPU—software rendering is not supported.

The deployment system automatically detects and configures the best GPU rendering mode for your environment.

## Rendering Modes

The system supports two GPU rendering modes, automatically selected based on available hardware:

### Xorg Mode (Preferred)

**Requirements:**
- NVIDIA GPU with working drivers
- DRI/DRM device access (`/dev/dri/card0` or similar)
- X server support

**Advantages:**
- Full hardware GPU acceleration
- Best performance
- Most stable for long-running streams

**Configuration:**
```bash
export DISPLAY=:99
export GPU_RENDERING_MODE=xorg
export DUEL_CAPTURE_USE_XVFB=false
export VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json
```

**Xorg Headless Configuration:**

The deployment creates a headless Xorg configuration for GPU rendering without a physical display:

```bash
# /etc/X11/xorg-nvidia-headless.conf
Section "ServerLayout"
    Identifier     "Layout0"
    Screen      0  "Screen0"
EndSection

Section "Device"
    Identifier     "Device0"
    Driver         "nvidia"
    BusID          "PCI:1:0:0"  # Auto-detected from nvidia-smi
    Option         "AllowEmptyInitialConfiguration" "True"
    Option         "UseDisplayDevice" "None"
EndSection

Section "Screen"
    Identifier     "Screen0"
    Device         "Device0"
    DefaultDepth    24
    SubSection     "Display"
        Depth       24
        Virtual    1920 1080
    EndSubSection
EndSection
```

**Start Xorg:**
```bash
Xorg :99 -config /etc/X11/xorg-nvidia-headless.conf -noreset &
```

### Headless EGL Mode (Fallback)

**Requirements:**
- NVIDIA GPU with EGL support
- NVIDIA EGL library (`libEGL_nvidia.so.0`)
- No DRI/DRM device access required

**Advantages:**
- Works in containers without DRM/DRI access
- No X server required
- Ideal for Vast.ai and similar GPU cloud providers

**Configuration:**
```bash
export DISPLAY=
export STREAM_CAPTURE_HEADLESS=new
export STREAM_CAPTURE_USE_EGL=true
export GPU_RENDERING_MODE=headless-egl
export VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json
```

**Chrome Flags:**
```bash
--headless=new                    # Chrome's new headless mode
--use-gl=egl                      # Use EGL instead of ANGLE
--ozone-platform=headless         # Headless Ozone platform
--enable-features=VaapiVideoDecoder,VaapiVideoEncoder  # GPU video encoding
```

## Automatic GPU Detection

The `scripts/deploy-vast.sh` script automatically detects and configures GPU rendering:

```bash
# 1. Verify NVIDIA GPU is available
nvidia-smi || exit 1

# 2. Check for DRI devices
if [ -d "/dev/dri" ] && [ -e "/dev/dri/card0" ]; then
    # Try Xorg mode
    Xorg :99 -config /etc/X11/xorg-nvidia-headless.conf &
    
    # Verify Xorg started successfully
    if xdpyinfo -display :99 >/dev/null 2>&1; then
        export DISPLAY=:99
        export GPU_RENDERING_MODE=xorg
    else
        # Fall back to headless EGL
        export DISPLAY=
        export STREAM_CAPTURE_HEADLESS=new
        export STREAM_CAPTURE_USE_EGL=true
        export GPU_RENDERING_MODE=headless-egl
    fi
else
    # No DRI devices - use headless EGL
    export DISPLAY=
    export STREAM_CAPTURE_HEADLESS=new
    export STREAM_CAPTURE_USE_EGL=true
    export GPU_RENDERING_MODE=headless-egl
fi
```

## Xorg Swrast Fallback Detection

When NVIDIA Xorg driver fails to initialize (common in containers without full DRM access), Xorg falls back to modesetting with swrast (software rendering). This is unusable for WebGPU.

The deployment script detects this and automatically switches to headless EGL mode:

```bash
# Check Xorg log for software rendering fallback
if grep -q "IGLX: Loaded and initialized swrast" /var/log/Xorg.99.log; then
    echo "Xorg using SOFTWARE RENDERING - switching to headless EGL"
    pkill -9 Xorg
    export DISPLAY=
    export STREAM_CAPTURE_HEADLESS=new
    export STREAM_CAPTURE_USE_EGL=true
    export GPU_RENDERING_MODE=headless-egl
fi
```

**Why This Matters:**
- Xorg can start successfully but use software rendering
- Software rendering is too slow for WebGPU streaming
- Automatic detection prevents silent performance degradation
- Headless EGL provides hardware acceleration without X server

## Software Rendering Not Supported

The following software rendering modes are **NOT supported** and will cause streaming failures:

- ❌ **Xvfb** - Software framebuffer, no GPU access
- ❌ **SwiftShader** - CPU-based Vulkan, too slow
- ❌ **Lavapipe** - Software Vulkan via llvmpipe, too slow

**Why:**
- WebGPU requires hardware GPU rendering
- Software rendering is 10-100x slower than hardware
- Streaming requires 30+ FPS for smooth playback
- Software rendering typically achieves <5 FPS

## Vulkan Configuration

### Force NVIDIA-Only Vulkan ICD

To avoid conflicts with Mesa ICDs (which may be broken or misconfigured), force only the NVIDIA ICD:

```bash
export VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json
```

**Why This Matters:**
- Vast.ai containers often have multiple Vulkan ICDs installed
- Mesa ICDs may be misconfigured or incompatible
- NVIDIA ICD is the only one that works reliably
- Forcing NVIDIA-only prevents fallback to broken ICDs

### Verify Vulkan Support

```bash
# Check Vulkan with NVIDIA-only ICD
export VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json
vulkaninfo --summary

# Should show NVIDIA GPU, not llvmpipe or swrast
```

## Chrome Configuration

### Chrome Dev Channel

Use Chrome Dev channel for latest WebGPU features:

```bash
# Install Chrome Dev
wget -q -O - https://dl.google.com/linux/linux_signing_key.pub | apt-key add -
echo "deb [arch=amd64] http://dl.google.com/linux/chrome/deb/ stable main" > /etc/apt/sources.list.d/google-chrome.list
apt-get update
apt-get install -y google-chrome-unstable

# Verify installation
google-chrome-unstable --version
```

### Headless Mode Flags

**Important:** Playwright's `headless` option only accepts boolean, not string.

For Chrome's new headless mode (`--headless=new`):
1. Pass `headless: false` to Playwright
2. Add `--headless=new` to args array manually

```typescript
// ❌ Wrong: Playwright rejects string
const browser = await chromium.launch({
  headless: 'new'  // TypeError
});

// ✅ Correct: Pass as arg, not option
const browser = await chromium.launch({
  headless: false,
  args: ['--headless=new']
});
```

## Environment Variables

### GPU Rendering Mode

```bash
# Auto-detected by deploy script
GPU_RENDERING_MODE=xorg              # or headless-egl

# Display configuration
DISPLAY=:99                          # Xorg mode
DISPLAY=                             # Headless EGL mode (empty)

# Xvfb disabled (hardware GPU required)
DUEL_CAPTURE_USE_XVFB=false

# Vulkan ICD (force NVIDIA-only)
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json
```

### Chrome Capture Configuration

```bash
# Headless mode
STREAM_CAPTURE_HEADLESS=false        # Xorg mode
STREAM_CAPTURE_HEADLESS=new          # Headless EGL mode

# EGL mode
STREAM_CAPTURE_USE_EGL=false         # Xorg mode
STREAM_CAPTURE_USE_EGL=true          # Headless EGL mode

# Browser channel
STREAM_CAPTURE_CHANNEL=chrome-dev    # Use Chrome Dev channel

# ANGLE backend
STREAM_CAPTURE_ANGLE=vulkan          # Vulkan backend (default)

# WebGPU
STREAM_CAPTURE_DISABLE_WEBGPU=false  # WebGPU enabled (required)
```

## Troubleshooting

### Verify GPU Access

```bash
# Check NVIDIA driver
nvidia-smi

# Check Vulkan (NVIDIA-only)
export VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json
vulkaninfo --summary

# Check DRI devices (needed for Xorg)
ls -la /dev/dri/

# Check EGL support (needed for headless)
ls -la /usr/lib/x86_64-linux-gnu/libEGL_nvidia.so.0
```

### Verify Xorg

```bash
# Check Xorg is running
ps aux | grep Xorg

# Test display
xdpyinfo -display :99

# Check Xorg log
cat /var/log/Xorg.99.log

# Look for errors
grep -E "(EE)" /var/log/Xorg.99.log

# Check for software rendering fallback
grep -i "swrast" /var/log/Xorg.99.log
```

### Test Chrome GPU Rendering

```bash
# Xorg mode
DISPLAY=:99 google-chrome-unstable \
  --use-gl=angle --use-angle=vulkan \
  --enable-unsafe-webgpu \
  --screenshot=test.png \
  https://get.webgl.org/webgpu/

# Headless EGL mode
google-chrome-unstable \
  --headless=new --use-gl=egl \
  --ozone-platform=headless \
  --enable-unsafe-webgpu \
  --screenshot=test.png \
  https://get.webgl.org/webgpu/
```

### Common Issues

**Black screen in stream:**
- Check GPU rendering mode: `echo $GPU_RENDERING_MODE`
- Verify Vulkan: `vulkaninfo --summary`
- Check Xorg log for errors: `grep -E "(EE)" /var/log/Xorg.99.log`
- Check for swrast fallback: `grep -i "swrast" /var/log/Xorg.99.log`

**Xorg fails to start:**
- Check DRI devices: `ls -la /dev/dri/`
- Verify NVIDIA driver: `nvidia-smi`
- Check Xorg log: `cat /var/log/Xorg.99.log`
- Fall back to headless EGL mode

**WebGPU not available:**
- Check Chrome flags: `ps aux | grep chrome`
- Verify Vulkan ICD: `echo $VK_ICD_FILENAMES`
- Test Chrome GPU: See "Test Chrome GPU Rendering" above

## System Requirements

### NVIDIA GPU

- **Driver**: NVIDIA proprietary driver (not nouveau)
- **Vulkan**: NVIDIA Vulkan ICD installed
- **Compute Capability**: 6.0+ (Pascal or newer)

### Xorg Mode Requirements

- DRI/DRM device access (`/dev/dri/card0`)
- Xorg server packages
- NVIDIA Xorg driver (`xserver-xorg-video-nvidia`)

### Headless EGL Mode Requirements

- NVIDIA EGL library (`libEGL_nvidia.so.0`)
- Chrome's new headless mode support
- No DRI/DRM access required

## Installation

### Xorg Mode Setup

```bash
# Install Xorg and NVIDIA driver
apt-get update
apt-get install -y \
    xserver-xorg-core \
    mesa-utils \
    libglvnd0 \
    libgl1 \
    libglx0 \
    libegl1 \
    libgles2 \
    x11-xserver-utils

# Auto-detect NVIDIA driver version
NVIDIA_VERSION=$(nvidia-smi --query-gpu=driver_version --format=csv,noheader | cut -d. -f1)

# Install matching Xorg driver
apt-get install -y xserver-xorg-video-nvidia-${NVIDIA_VERSION}

# Create Xorg config (see "Xorg Headless Configuration" above)
# Start Xorg
Xorg :99 -config /etc/X11/xorg-nvidia-headless.conf -noreset &

# Verify
xdpyinfo -display :99
```


## PM2 Configuration

The `ecosystem.config.cjs` file passes GPU environment variables to the duel stack:

```javascript
env: {
  // GPU rendering mode (auto-detected by deploy script)
  GPU_RENDERING_MODE: process.env.GPU_RENDERING_MODE || "xorg",
  
  // Display (empty for headless EGL)
  DISPLAY: process.env.DISPLAY || "",
  
  // Xvfb disabled (hardware GPU required)
  DUEL_CAPTURE_USE_XVFB: "false",
  
  // Vulkan ICD (force NVIDIA-only)
  VK_ICD_FILENAMES: "/usr/share/vulkan/icd.d/nvidia_icd.json",
  
  // Chrome capture configuration
  STREAM_CAPTURE_HEADLESS: process.env.STREAM_CAPTURE_HEADLESS || "false",
  STREAM_CAPTURE_USE_EGL: process.env.STREAM_CAPTURE_USE_EGL || "false",
  STREAM_CAPTURE_CHANNEL: "chrome-dev",
  STREAM_CAPTURE_ANGLE: "vulkan",
  STREAM_CAPTURE_DISABLE_WEBGPU: "false",
}
```

## Deployment Integration

The GPU rendering configuration is automatically handled by `scripts/deploy-vast.sh`:

1. **Verify NVIDIA GPU** - Check `nvidia-smi` works
2. **Check DRI devices** - Look for `/dev/dri/card0`
3. **Try Xorg** - If DRI available, configure and start Xorg
4. **Detect swrast fallback** - Check Xorg log for software rendering
5. **Fall back to EGL** - If Xorg fails or uses swrast, use headless EGL
6. **Export environment** - Set GPU_RENDERING_MODE, DISPLAY, etc.
7. **Start PM2** - Pass environment to duel stack
