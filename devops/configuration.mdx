## Environment Files

Each package has its own `.env` file:

| Package | File | Purpose |
|---------|------|---------|
| Server | `packages/server/.env` | Server configuration |
| Client | `packages/client/.env` | Client configuration |
| Plugin | `packages/plugin-hyperscape/.env` | AI agent config |
| AssetForge | `packages/asset-forge/.env` | Asset tools config |

Copy from examples:

```bash
cp packages/client/.env.example packages/client/.env
cp packages/server/.env.example packages/server/.env
```

**Keypair Setup:**

The `SOLANA_DEPLOYER_PRIVATE_KEY` is automatically decoded and written to:
- `~/.config/solana/id.json` (Solana CLI default location)
- `deployer-keypair.json` (legacy location)

This happens during deployment via `scripts/decode-key.ts`.

### Solana Market Token Migration (commit 34255ee, Feb 26 2026)

**Breaking Change:** Markets now use native token (WSOL) instead of GOLD token.

**What Changed:**

```bash
# ❌ Old: GOLD_MINT (custom token)
GOLD_MINT=DK9nBUMfdu4XprPRWeh8f6KnQiGWD8Z4xz3yzs9gpump

# ✅ New: MARKET_MINT (native token)
MARKET_MINT=So11111111111111111111111111111111111112  # WSOL
```

**Why:**
- Simplifies market operations (no custom token minting/distribution)
- Uses native token of each chain (WSOL on Solana, WETH on EVM)
- Reduces transaction complexity and fees
- Better liquidity (native tokens are more liquid than custom tokens)

**Migration Guide:**

If you have existing markets using GOLD_MINT:

1. **Update environment variables:**
   ```bash
   # Remove GOLD_MINT
   # GOLD_MINT=DK9nBUMfdu4XprPRWeh8f6KnQiGWD8Z4xz3yzs9gpump
   
   # Add MARKET_MINT (or leave unset to use WSOL default)
   MARKET_MINT=So11111111111111111111111111111111111112
   ```

2. **Redeploy contracts:**
   ```bash
   cd packages/gold-betting-demo/anchor
   anchor build
   anchor deploy
   ```

3. **Update keeper configuration:**
   ```bash
   # In packages/gold-betting-demo/keeper/.env
   MARKET_MINT=So11111111111111111111111111111111111112
   ```

**Perps Oracle Disabled (commit 34255ee):**

The perps oracle is now disabled by default on devnet because the perps program is not deployed:

```bash
# Disable perps oracle updates (program not deployed on devnet)
ENABLE_PERPS_ORACLE=false

# Re-enable when perps program is deployed
# ENABLE_PERPS_ORACLE=true
```

**Code Changes:**

```typescript
// From packages/gold-betting-demo/keeper/src/service.ts
const enablePerpsOracle = process.env.ENABLE_PERPS_ORACLE === 'true';

if (enablePerpsOracle) {
  // Update perps oracle
  await updatePerpsOracle();
} else {
  logger.info('Perps oracle disabled (ENABLE_PERPS_ORACLE=false)');
}
```

### Stream Key Management

Stream keys must be explicitly unset and re-exported before PM2 start to avoid stale environment variables:

```bash
# From scripts/deploy-vast.sh
unset TWITCH_STREAM_KEY X_STREAM_KEY X_RTMP_URL KICK_STREAM_KEY KICK_RTMP_URL
source /root/hyperscape/packages/server/.env
bunx pm2 start ecosystem.config.cjs
```

This ensures PM2 picks up the correct stream keys from the .env file, not stale values from the shell environment.

**Why This Matters:**
- Vast.ai servers can have stale stream keys in their environment from previous deployments
- These stale values override the .env file values
- Explicitly unsetting ensures clean environment before sourcing .env
- Prevents streams from going to wrong channels/accounts

## Maintenance Mode

The server provides a maintenance mode API for graceful deployments without data loss.

### Environment Variables

```bash
# Maintenance mode is controlled via API, not environment variables
# The scheduler checks this internal flag:
STREAMING_DUEL_MAINTENANCE_MODE=true  # Set by enterMaintenanceMode()
```

### API Endpoints

**Enter Maintenance Mode:**
```bash
POST /admin/maintenance/enter
Headers:
  x-admin-code: <ADMIN_CODE>
  Content-Type: application/json
Body:
  {
    "reason": "deployment",
    "timeoutMs": 300000
  }
```

**Exit Maintenance Mode:**
```bash
POST /admin/maintenance/exit
Headers:
  x-admin-code: <ADMIN_CODE>
```

**Check Status:**
```bash
GET /admin/maintenance/status
Headers:
  x-admin-code: <ADMIN_CODE>
```

### What Maintenance Mode Does

When maintenance mode is entered:
1. **Pauses new duel cycles** - Current cycle completes, no new cycles start
2. **Locks betting markets** - No new bets accepted
3. **Waits for resolution** - Current market resolves before reporting safe to deploy
4. **Reports status** - API returns `safeToDeploy: true` when ready

**Safe to Deploy Conditions:**
- Not in active duel phase (FIGHTING, COUNTDOWN, ANNOUNCEMENT)
- No pending betting markets (or all markets resolved)
- Maintenance mode active

### Helper Scripts

```bash
# Enter maintenance mode
bash scripts/pre-deploy-maintenance.sh

# Exit maintenance mode
bash scripts/post-deploy-resume.sh
```

### CI/CD Integration

The Vast.ai deployment workflow automatically uses maintenance mode:

```yaml
# .github/workflows/deploy-vast.yml
- name: Enter Maintenance Mode
  run: |
    curl -X POST "$VAST_SERVER_URL/admin/maintenance/enter" \
      -H "x-admin-code: $ADMIN_CODE" \
      -d '{"reason": "deployment", "timeoutMs": 300000}'

# ... deploy steps ...

- name: Exit Maintenance Mode
  run: |
    curl -X POST "$VAST_SERVER_URL/admin/maintenance/exit" \
      -H "x-admin-code: $ADMIN_CODE"
```

**Benefits:**
- Prevents data loss during deployments
- Avoids market inconsistency
- Ensures clean duel cycle boundaries
- No interrupted streams or broken markets

## Vast.ai Deployment Improvements (Feb 26 2026)

### First-Time Setup Support (commit 6302fa4)

**Problem:** Deployment failed on fresh Vast.ai instances without existing repository.

**Solution:** Auto-clone repository if it doesn't exist:

```bash
# From .github/workflows/deploy-vast.yml
if [ ! -d "/root/hyperscape" ]; then
  echo "[deploy] First-time setup: cloning repository..."
  cd /root
  git clone https://github.com/HyperscapeAI/hyperscape.git
fi
```

### Bun Installation Check (commit abfe0ce)

**Problem:** Deployment assumed bun was already installed.

**Solution:** Always check and install bun if missing:

```bash
# From .github/workflows/deploy-vast.yml
if ! command -v /root/.bun/bin/bun &> /dev/null; then
  echo "[deploy] Installing bun..."
  curl -fsSL https://bun.sh/install | bash
fi
export PATH="/root/.bun/bin:$PATH"
```

### Secrets Injection Overhaul (commits b466233, 6302fa4, abfe0ce)

**Problem:** Environment variables weren't persisting through git reset operations in deployment script.

**Solution:** Write secrets to `/tmp` before git reset, then restore:

```bash
# Write secrets to /tmp FIRST (survives git reset)
cat > /tmp/hyperscape-secrets.env << 'ENVEOF'
DATABASE_URL=${{ secrets.DATABASE_URL }}
TWITCH_STREAM_KEY=${{ secrets.TWITCH_STREAM_KEY }}
X_STREAM_KEY=${{ secrets.X_STREAM_KEY }}
KICK_STREAM_KEY=${{ secrets.KICK_STREAM_KEY }}
SOLANA_DEPLOYER_PRIVATE_KEY=${{ secrets.SOLANA_DEPLOYER_PRIVATE_KEY }}
YOUTUBE_STREAM_KEY=
ENVEOF

# Then run deploy script (which does git reset)
bash /root/hyperscape/scripts/deploy-vast.sh

# Deploy script restores from /tmp after git reset
source /tmp/hyperscape-secrets.env
```

**Why This Matters:**
- `git reset --hard` overwrites `.env` file
- Writing to `/tmp` before reset preserves secrets
- Deploy script sources from `/tmp` after reset
- Ensures DATABASE_URL and stream keys persist

### PM2 Environment Variable Handling (commit b466233)

**Problem:** PM2 wasn't picking up new environment variables on restart.

**Solution:** Use `pm2 kill` instead of `pm2 delete`:

```bash
# ❌ Old: pm2 delete doesn't restart daemon
pm2 delete ecosystem.config.cjs

# ✅ New: pm2 kill restarts daemon with fresh env
pm2 kill
pm2 start ecosystem.config.cjs
```

**Impact:** Environment variables (stream keys, DATABASE_URL) are properly loaded on every deployment.

### YouTube Streaming Disabled (commit b466233)

**Problem:** Stale YouTube stream key was being used despite being removed from configuration.

**Solution:** Explicitly set `YOUTUBE_STREAM_KEY=""` in secrets file and ecosystem.config.cjs:

```javascript
// From ecosystem.config.cjs
env: {
  YOUTUBE_STREAM_KEY: "",  // Explicitly disable
  YOUTUBE_RTMP_STREAM_KEY: "",
}
```

**Streaming Destinations (Current):**
- ✅ Twitch
- ✅ Kick
- ✅ X/Twitter
- ❌ YouTube (disabled)

### Database Warmup (commit d66d13a)

**Problem:** Cold starts caused database connection failures.

**Solution:** Add warmup step after schema push with retry logic:

```bash
# From scripts/deploy-vast.sh
echo "[deploy] Warming up database connection..."
for i in {1..3}; do
  if bun run -b packages/server/src/scripts/test-db-connection.ts; then
    echo "[deploy] Database connection verified"
    break
  fi
  echo "[deploy] Database warmup attempt $i failed, retrying..."
  sleep 2
done
```

**Benefits:**
- Verifies database connection before starting server
- Retries up to 3 times to handle cold starts
- Prevents server crash-loops from database connection failures

## Content Security Policy

### CSP Headers

The client includes Content Security Policy headers to mitigate XSS attacks:

```
# From packages/client/public/_headers
Content-Security-Policy: 
  default-src 'self'; 
  script-src 'self' 'unsafe-inline' 'unsafe-eval' https://auth.privy.io https://*.privy.io; 
  style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; 
  img-src 'self' data: https: blob:; 
  font-src 'self' data: https://fonts.gstatic.com; 
  connect-src 'self' wss: https: ws://localhost:* http://localhost:*; 
  frame-src 'self' https://auth.privy.io https://*.privy.io; 
  worker-src 'self' blob:; 
  media-src 'self' blob:; 
```

**Security Notes:**

- `'unsafe-inline'` is required for Privy SDK (injects inline styles for modals)
- `'unsafe-eval'` is required for Privy SDK (uses eval for authentication flows)
- `data:` URLs allowed for WASM loading (commit 8626299)
- Google Fonts allowed for typography (commit e012ed2)
- `report-uri` removed (was broken, commit 8626299)

**Recent CSP Updates (Feb 26 2026):**

**Why:** PhysX WASM loading requires `data:` URLs for inline WASM modules.

## Vite Polyfills Configuration

### Node Polyfills Fix (commit e012ed2)

**Problem:** Production builds failed with "Failed to resolve module specifier" errors for `vite-plugin-node-polyfills/shims/*` imports.

**Solution:** Add aliases to resolve shims to actual dist files:

```typescript
// From packages/client/vite.config.ts
export default defineConfig({
  resolve: {
    alias: {
      // Fix vite-plugin-node-polyfills shims resolution
      'vite-plugin-node-polyfills/shims/buffer': 'vite-plugin-node-polyfills/dist/shims/buffer',
      'vite-plugin-node-polyfills/shims/global': 'vite-plugin-node-polyfills/dist/shims/global',
      'vite-plugin-node-polyfills/shims/process': 'vite-plugin-node-polyfills/dist/shims/process',
    }
  },
  plugins: [
    nodePolyfills({
      protocolImports: false,  // Disable to avoid unresolved imports
    })
  ]
});
```

**Why:**
- `vite-plugin-node-polyfills` exports shims from `shims/*` but actual files are in `dist/shims/*`
- Production builds couldn't resolve the imports
- Aliases map virtual paths to actual dist files
- `protocolImports: false` prevents additional unresolved imports

<Info>
This fix is required for production builds on Cloudflare Pages. Without it, the client fails to load.
</Info>

### CSRF Protection

The server uses CSRF tokens to prevent cross-site request forgery attacks.

**CSRF Middleware (commit cd29a76, Feb 26 2026):**

**Problem:** CSRF validation failed for cross-origin requests from Cloudflare Pages (hyperscape.gg) to Railway backend because SameSite=Strict cookies cannot be sent cross-origin.

**Solution:** Skip CSRF validation for known cross-origin clients that are already protected by Origin header validation and JWT bearer tokens:

```typescript
// From packages/server/src/middleware/csrf.ts
const knownCrossOriginClients = [
  /^https?:\/\/([a-z0-9-]+\.)?hyperscape\.gg$/,
  /^https?:\/\/([a-z0-9-]+\.)?hyperbet\.win$/,
  /^https?:\/\/([a-z0-9-]+\.)?hyperscape\.bet$/,
];

// Skip CSRF validation when Origin matches known clients
if (origin && knownCrossOriginClients.some(pattern => pattern.test(origin))) {
  return; // Skip CSRF check
}
```

**Why This Works:**

Cross-origin requests are already protected by:
1. **Origin header validation** (http-server.ts preHandler hook)
2. **JWT bearer token authentication** (Authorization header)

CSRF cookie validation is redundant for cross-origin and doesn't work anyway due to SameSite=Strict.

**Apex Domain Support (commit cd29a76):**

Added apex domain support to allowed origins:

```typescript
// ✅ Now supported
https://hyperscape.gg        // Apex domain
https://www.hyperscape.gg    // Subdomain
https://play.hyperscape.gg   // Subdomain
```

Previously only subdomains were matched.

## RTMP Streaming Configuration

### Streaming Quality Improvements (Feb 26 2026)

Recent commits improved RTMP streaming stability and quality for smoother viewer experience:

#### Buffering Improvements (commit 4c630f12)

**Problem:** Viewers experienced frequent buffering and stalling during streams.

**Solution:** Three key changes to reduce viewer-side buffering:

1. **Changed x264 tune from 'zerolatency' to 'film'**
   - Allows B-frames for better compression
   - Better lookahead for smoother bitrate
   - Set `STREAM_LOW_LATENCY=true` to restore old behavior

2. **Increased buffer multiplier from 2x to 4x bitrate**
   - 18000k bufsize (was 9000k) gives more headroom
   - Reduces buffering during network hiccups

3. **Added FLV flags for RTMP stability**
   - `flvflags=no_duration_filesize` prevents FLV header issues

4. **Improved input buffering**
   - Added `thread_queue_size` for frame queueing
   - `genpts+discardcorrupt` for better stream recovery

**Configuration:**

```bash
# Low latency mode (zerolatency tune, 2x buffer, no B-frames)
STREAM_LOW_LATENCY=true

# Balanced mode (film tune, 4x buffer, B-frames enabled) - DEFAULT
STREAM_LOW_LATENCY=false
```

**FFmpeg Args Comparison:**

```bash
# Low Latency Mode (STREAM_LOW_LATENCY=true)
-c:v libx264 -preset ultrafast -tune zerolatency -bufsize 9000k

# Balanced Mode (STREAM_LOW_LATENCY=false) - DEFAULT
-c:v libx264 -preset ultrafast -tune film -bufsize 18000k -bf 2
```

**When to Use Low Latency:**
- Interactive streams where <1s delay is critical
- Betting/prediction markets with real-time odds
- Live commentary or viewer interaction

**When to Use Balanced (Default):**
- Passive viewing experiences
- Recorded content or VODs
- Viewers on unstable connections
- Longer streams (>1 hour)

### Audio Streaming via PulseAudio (commits 3b6f1ee, aab66b0, b9d2e41, Feb 26 2026)

**Feature:** Capture game music and sound effects in RTMP streams using PulseAudio virtual sink.

**Setup (Vast.ai deployment):**

The `deploy-vast.sh` script automatically configures PulseAudio:

1. **Install PulseAudio** and create virtual sink (`chrome_audio`)
2. **Configure Chrome** to use PulseAudio output
3. **Update FFmpeg** to capture from PulseAudio monitor instead of silent audio

**PulseAudio Configuration:**

```bash
# User mode (more reliable than system mode)
PULSE_SERVER=unix:/tmp/pulse-runtime/pulse/native
XDG_RUNTIME_DIR=/tmp/pulse-runtime

# Virtual sink for Chrome audio
pactl load-module module-null-sink sink_name=chrome_audio sink_properties=device.description=Chrome_Audio

# Chrome uses this sink for audio output
# FFmpeg captures from chrome_audio.monitor
```

**FFmpeg Audio Capture:**

```bash
# Input from PulseAudio monitor
-f pulse -i chrome_audio.monitor

# Audio buffering and sync (commit b9d2e41)
-thread_queue_size 1024                    # Prevent buffer underruns
-use_wallclock_as_timestamps 1             # Real-time timing
-filter:a aresample=async=1000:first_pts=0 # Recover from audio drift

# Video buffering (increased for a/v sync)
-thread_queue_size 1024  # Increased from 512
```

**Audio Stability Improvements (commit b9d2e41):**

Three key changes to prevent intermittent audio issues:

1. **Buffering both audio and video inputs adequately**
   - Audio: `thread_queue_size=1024` prevents buffer underruns
   - Video: `thread_queue_size=1024` (increased from 512) for better a/v sync

2. **Using wall clock timestamps for accurate audio timing**
   - `use_wallclock_as_timestamps=1` for PulseAudio maintains real-time timing

3. **Async resampling to resync audio when drift exceeds 22ms**
   - `aresample=async=1000:first_pts=0` filter recovers from audio drift

4. **Removed `-shortest` flag**
   - Was causing audio dropouts during video buffering

**Permissions Fix (commit aab66b0):**

```bash
# Add root user to pulse-access group
usermod -aG pulse-access root

# Create /run/pulse with proper permissions
mkdir -p /run/pulse
chmod 777 /run/pulse

# Export PULSE_SERVER in both deploy script and PM2 config
export PULSE_SERVER=unix:/tmp/pulse-runtime/pulse/native
```

**Graceful Fallback:**

If PulseAudio is not available, FFmpeg falls back to silent audio:

```bash
# Check if PulseAudio is running
if pactl info &>/dev/null && pactl list sinks | grep -q chrome_audio; then
  AUDIO_INPUT="-f pulse -i chrome_audio.monitor"
else
  AUDIO_INPUT="-f lavfi -i anullsrc"  # Silent audio fallback
fi
```

**Configuration:**

```bash
# Enable audio capture
STREAM_AUDIO_ENABLED=true

# PulseAudio device (monitor of virtual sink)
PULSE_AUDIO_DEVICE=chrome_audio.monitor

# PulseAudio server socket
PULSE_SERVER=unix:/tmp/pulse-runtime/pulse/native

# Runtime directory for PulseAudio
XDG_RUNTIME_DIR=/tmp/pulse-runtime
```

**Troubleshooting:**

```bash
# Check PulseAudio status
pactl info

# List available sinks
pactl list sinks

# Verify chrome_audio sink exists
pactl list sinks | grep chrome_audio

# Test audio capture
ffmpeg -f pulse -i chrome_audio.monitor -t 5 test.wav
```
