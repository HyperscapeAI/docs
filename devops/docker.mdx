## Overview

Hyperscape uses Docker for local development infrastructure:

- **Asset CDN**: nginx serving game assets (development only)
- **PostgreSQL**: Database for player data (development and production)
- **Development services**: Local infrastructure for testing

**Production Architecture:**
- Frontend: Cloudflare Pages (no Docker)
- Backend: Railway (uses Nixpacks, not Docker Compose)
- Assets: Cloudflare R2 CDN (no Docker)
- Database: Railway PostgreSQL or Neon (managed service)

## Prerequisites

- [Docker Desktop](https://docker.com/products/docker-desktop) (macOS/Windows)
- Or Docker Engine on Linux: `apt install docker.io`

## CDN Container (Development Only)

The local CDN is only used for development. In production, assets are served from Cloudflare R2.

### Start CDN

```bash
bun run cdn:up
```

This starts an nginx container serving assets from `packages/server/world/assets/` on port 8080.

**What it serves:**
- 3D models: `http://localhost:8080/models/`
- Audio: `http://localhost:8080/audio/`
- Textures: `http://localhost:8080/textures/`
- Manifests: `http://localhost:8080/manifests/`

### Stop CDN

```bash
bun run cdn:down
```

### Automatic Start

The CDN starts automatically with `bun run dev`. Only run manually if using services separately.

<Info>
The server fetches manifests from `PUBLIC_CDN_URL` at startup. In development, this defaults to `http://localhost:8080`, so the CDN container must be running.
</Info>

## PostgreSQL Container

PostgreSQL starts automatically when the server runs via Docker Compose.

### Configuration

Default connection:

```
Host: localhost
Port: 5432
Database: hyperscape
User: postgres
Password: postgres
```

### Manual Control

```bash
cd packages/server
docker-compose up postgres    # Start PostgreSQL
docker-compose down postgres  # Stop PostgreSQL
```

## Docker Compose

The server package includes `docker-compose.yml`:

```yaml
services:
  postgres:
    image: postgres:15
    ports:
      - "5432:5432"
    environment:
      POSTGRES_DB: hyperscape
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    volumes:
      - postgres-data:/var/lib/postgresql/data

  cdn:
    image: nginx:alpine
    ports:
      - "8080:80"
    volumes:
      - ./world/assets:/usr/share/nginx/html:ro
```

## Resetting Containers

### Reset Database

<Warning>
  This deletes all local data (characters, inventory, progress).
</Warning>

```bash
# Stop containers
docker stop hyperscape-postgres
docker rm hyperscape-postgres

# Remove volumes
docker volume rm hyperscape-postgres-data
docker volume rm server_postgres-data

# Verify
docker volume ls | grep hyperscape

# Restart
bun run dev
```

### Reset CDN

```bash
docker stop hyperscape-cdn
docker rm hyperscape-cdn
bun run cdn:up
```

## No Docker Alternative

If you can't run Docker locally:

### External PostgreSQL

Use a hosted database (e.g., [Neon](https://neon.tech)):

```bash
# packages/server/.env
DATABASE_URL=postgresql://user:pass@host.neon.tech:5432/db
```

### External CDN

Host assets on cloud storage:

```bash
# packages/server/.env and packages/client/.env
PUBLIC_CDN_URL=https://your-cdn.example.com
```

## Production Docker Build

Railway uses a multi-stage Dockerfile for production deployments:

### Dockerfile.server

```dockerfile
# Stage 1: Builder - Install dependencies and build
FROM oven/bun:1.1.38-debian AS builder

# Install build dependencies for native modules
RUN apt-get update && apt-get install -y \
    python3 make g++ pkg-config \
    libcairo2-dev libpango1.0-dev libjpeg-dev

# Install dependencies (skip asset download in CI)
ENV CI=true SKIP_ASSETS=true
RUN bun install

# Build packages in order
RUN bun run build:shared
RUN bun run build:client
RUN bun run build:server

# Copy client build to server public directory
RUN cp -r packages/client/dist/* packages/server/public/

# Stage 2: Runtime - Minimal production image
FROM oven/bun:1.1.38-debian AS runtime

# Install runtime dependencies
RUN apt-get update && apt-get install -y \
    libcairo2 libpango-1.0-0 curl ca-certificates

# Copy built artifacts
COPY --from=builder /app/packages/server/dist ./packages/server/dist
COPY --from=builder /app/packages/server/public ./packages/server/public

# Create manifests directory (fetched from CDN at startup)
RUN mkdir -p ./packages/server/world/assets/manifests

# Health check
HEALTHCHECK --interval=30s --timeout=3s --start-period=30s \
  CMD curl -f http://localhost:${PORT:-5555}/status || exit 1

# Run server
CMD ["bun", "run", "start"]
```

**Key Features:**
- Multi-stage build reduces final image size
- Native module support (canvas, better-sqlite3)
- Client build bundled with server
- Manifests fetched from CDN at runtime
- Health check for Railway monitoring

### Building Locally

Test the production Docker build locally:

```bash
# Build image
docker build -f Dockerfile.server -t hyperscape-server .

# Run container
docker run -p 5555:5555 \
  -e DATABASE_URL=postgresql://... \
  -e PUBLIC_CDN_URL=https://assets.hyperscape.club \
  -e PRIVY_APP_ID=... \
  -e PRIVY_APP_SECRET=... \
  hyperscape-server
```

<Warning>
The production Docker build is primarily for Railway. For local development, use `bun run dev` instead.
</Warning>

## Container Status

Check running containers:

```bash
docker ps
```

Expected output when running:

```
CONTAINER ID   IMAGE           PORTS
abc123         postgres:15     0.0.0.0:5432->5432/tcp
def456         nginx:alpine    0.0.0.0:8080->80/tcp
```

docker logs -f hyperscape-postgres
